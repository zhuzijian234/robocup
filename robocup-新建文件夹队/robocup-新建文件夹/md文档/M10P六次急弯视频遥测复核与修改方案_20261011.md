# M10P 六次急弯视频、遥测复核与修改方案

日期：2026-10-11。范围：19:58:50～20:19:36 六次新测试、赛道布局视频和急弯照片。

**本次只分析、制定方案，没有修改固件、上位机业务代码或烧录文件。** 已从原始 bin 重新解析，并在独立分析目录编译现有 `path_track.c`，复核保存点云的边界关联。

## 1. 确定结论

1. **存在需要先修的几何逻辑缺漏，不能把全部问题归于赛道太急或增益不足。** 两次右急弯中，目标位置突变使接近满右转的命令突然回正，随后几何失效，控制继续保持已经减小的转角。关键回摆发生时 D 项为零。
2. **左右边界会重复关联同一面墙。** 用当前生产 C 函数回放左弯点云，seq17779 的左、右边界分别提取10、11个分区样本，其中8个相同；几何结果复现为 `GEOM_CONFLICT`。这不是雷达没收到点。
3. **另一些失败发生在已经持续接近舵机命令极限的情况下。** 因而修复回摆之后，还要处理入弯位置、曲线跟踪及实际转弯能力；继续增大 Kp 无法突破既有输出限幅。
4. **外侧准备位置有优化价值，但不能全弯统一向外偏。** 新视频多次显示最终接近或碰到出口外墙。外移应主要用于急弯入口的轨迹准备，并受外墙余量限制，出弯及时撤销。
5. **当前数据足够启动第一轮几何修复。** 还不足以确定最佳外移毫米数、满舵实际半径，或保证17/15下所有急弯都能通过。

## 2. 配置与分析口径

六组回传配置的固件标识均为 `sha256-43f8733c1e08c963`；直道上限17、弯速15、`cx=10`、基础预瞄700 mm、配置宽度500 mm。第三组配置虽可解码，但来自 session=0，不能算完成协商。

- 坐标采用固件约定：x向右、y向前，原点为雷达。PWM中位1445，右限1170、左限1720。PWM仅代表命令，不能据此确定实际轮角。
- 速度17/15是编码器控制单位，尚不能解释为m/s。
- CONTROL、DETAIL、PATH_EXTRA、RACE按 `(session, control_seq, param_revision)` 关联；缺失字段保留缺失，未把上一帧补成当前事实。
- 正式采集窗口按 meta 中的 `pre_roll_s`、`formal_end_s` 和协商session划分。预热段、停止采集后的点云导出段单独看，不混入正式比例。
- 视频按文件名配对。视频秒数和板端时间**没有精确同步标记**，本文分别列出视频阶段与控制序号，不声称某视频帧就是某控制帧。
- 视频已按0.4 s生成时序图，赛道布局按2 s生成时序图。手持相机、透视和遮挡不支持精确测量轮角、最小侧隙或弯道半径。
- 点云是控制层前向工作点，不是完整360°原始圈。四组各导出8条完整快照，共32条；其中200137前后两组重复4帧，合计28个不同控制序号的现场快照。
- 快照坐标经过毫米整数化；独立回放按记录宽度初始化，未重建全部宽度学习/避让历史。因此用于定位边界关联和拒绝原因，不冒充完整动态车辆仿真。

## 4. 两条有直接证据的失败链

### 4.1 右201004：边界来源改变，目标跳变，随后丢路径

| 字段 | seq25854 | seq25855 |
| --- | ---: | ---: |
| 边界来源 | LEFT=1 | RIGHT=2 |
| 近段斜率 | 1.199 | 1.159 |
| 远段斜率 | 1.575 | 1.447 |
| 参考y / mm | 700 | 700 |
| 目标x / mm | 957.09 | 119.16 |
| P项 | −266.63 | −43.12 |
| D项 | 0 | 0 |
| 最终PWM | 1178 | 1401 |

两帧间隔约78 ms。边界仍呈同向的大斜率，但目标横向位置减少約838 mm，转向命令减少223个PWM计数。这里的 LEFT/RIGHT 表示所跟边界身份，**不表示左转/右转**。

随后 seq25855～25858 的目标逐步回到119、176、231、290 mm，PWM为1401、1364、1341、1329；seq25859开始近段不可用，继续保持1329。这条计算链已经足以解释软件为何出现大幅收舵后不再恢复必要舵量。

现有 `center_at()` 按左右身份决定法线半宽偏移的正负；斜率较大时偏移项还包含 `sqrt(1+a²)`。身份错认/不连续会被放大成数百毫米目标差。来源变化仅触发 D 历史重置，未验证新路径是否与旧路径在空间上相容。

**可确定：目标和P项突变直接造成该次回摆。尚不能仅凭这一帧数值，断言是同一物理墙被改名还是切到另一条不相容边界。** 后续快照支持对边界关联机制进行修复，但恰好跳变前后的点云未被保存。

### 4.2 右201147：source不变也会发生类似跳变

seq27089→27090，source均为RIGHT，目标556.13→64.46 mm、参考y425.45→700 mm、PWM1178→1423，D均为0。

更关键的是：近段参考位置 `near_x` 从522.80→−170.66 mm；右近段直线截距从398.36→−227.25 mm。故不能只加“source变化时防抖”，**同一个来源枚举下的边界关联和近远段接管也需要连续性检查**。

seq27094起几何失效，PWM保持1299。这次无点云，不能进一步确定物理墙面，但数值链与第一组故障具有一致特征。

### 4.3 左弯的小回摆也有近远切换证据

左195850的seq17765→17766→17767：目标约−400→−656→−421 mm、PWM1642→1711→1658，远段在不可用/可用之间切换，近段斜率却只在约−0.70～−0.74变化。D项接近零或为零。

右201147的seq27072→27073：远段失效后，目标539→331 mm，PWM1176→1305，D由约−1.84变为0。这些说明**近远目标硬切换本身会形成回摆**，不应首先用舵机低通滤波掩盖。

## 5. 点云回放定位的缺漏

### 5.1 同一面墙同时进入左右边界

`boundary()` 对左右各运行一次；单帧内从近到远预测，但两个提取过程互不排他，也没有跨帧的墙面身份约束。弯道的一条边界跨过车体中线后，另一侧种子可能重新接上同一条墙。

现有C函数回放结果：

| 点云 | 左/右样本数 | 位置相同的样本数 | 复现结果 |
| --- | ---: | ---: | --- |
| 左195850 seq17777 | 5 / 7 | 3 | 暂可单侧跟踪 |
| 左195850 seq17779 | 10 / 11 | 8 | GEOM_CONFLICT |
| 左195850 seq17788 | 6 / 7 | 4 | GEOM_CONFLICT |
| 右201936 seq319 | 4 / 3 | 2 | GEOM_NEAR_MISSING |

seq17779的两条拟合线落在同一条可见轮廓上。处理方向是“去除重复关联并恢复可信单侧”，不能把几何冲突检查直接删除，也不能强行规定所有x>0点属于右墙。

### 5.2 分区直线模型仍会丢掉横向急弯

近段要求至少4个100 mm前向分区、250 mm的y跨度、斜率绝对值不超过1.8。急弯转为接近横向时，即便一条弧上有大量回波，y跨度也可能缩小，无法满足直线拟合条件。

右201004失效时前向工作点仍有约221～225个；右201936的seq319/320快照有276/275点。问题不是“点不够密”，而是边界身份与模型的支持方式。

现有弧形恢复保留了连续性、局部残差、通路宽度等检查，方向正确；但主直线尚有效时，提前接管还要求单侧、无远段、RMS>45、|a|>0.6。**错误但低残差的直线、以及远段形式上有效的跳变路径，不会进入这条分支。** 不宜单纯降低全部阈值，应引入能识别这些场景的证据。

`curve_rejected` 目前只粗分无候选/冲突等结果，不足以说明失败是种子、连续性、入口余量、总长度还是目标支持不足，应细分诊断。

### 5.3 保持PWM会保留最后一次错误减舵

保持上一条命令可以防止瞬时坏帧乱打方向，但这两次右弯恰好先接受了错误小转角，再出现几何失效。下一轮应修复新候选的可信度，并区分“最近输出”与“最近经过几何验证的命令”。

不能据此改为无期限锁满舵；真实出弯、下一段S弯、持续无有效几何必须有明确的重新接管规则。本轮也不恢复用户已经取消的自动停车逻辑。

## 6. 修改计划与顺序

### 第一阶段：边界身份和目标连续性，优先实施

主要文件：`HARDWARE/CENTRE_LINE/path_track.c/.h`。

1. 为分区样本保留原始簇/点归属信息，对左右关联做排他检查；若两侧大量重合，保留有独立近场支持和连续轮廓证据的一侧，另一侧标为不可用，不把同墙当双墙。
2. 关联评分综合近场种子、连续切向、同段位置、真实覆盖范围和另一侧余量。允许边界跨x=0；不固定相信左侧/右侧，也不依据RMS略低就瞬时接管。
3. 增加短期几何身份与置信度。跨帧比较使用共同支持区域内的路径距离、切向和走廊位置，允许车辆运动带来的变化；历史只提供辅助证据，不覆盖当前明确的S弯反向证据。
4. 同时检查“source变化”和“source不变但直线截距/目标突变”。在相同参考截面或相同弧长上比较候选，避免不同参考y制造假跳变。
5. 近远段有足够连续支持时平滑交接；远段消失时转入有支持的局部曲线/近段目标，而非忽然把远段横移量归零。缺少支持的候选不能靠低通后当真路径。
6. 只对急弯同向、置信度下降导致的异常减舵施加有界过渡；真实出弯、可靠新弯向和锥桶迫近有独立接管条件。避免全局增加保持时间，避免拖慢S弯换向。

验收：重放上述异常序列时，不能再直接接受未经几何证据支持的838/492 mm目标突变；重复墙样本不能构成双侧走廊；若无法恢复，必须明确记录降级原因，不能仅通过增加无效帧数量“消除抖动”。

### 第二阶段：急弯采用连续轮廓，保障横墙前持续跟踪

主要文件仍为 `path_track.c/.h`，控制接口尽量保留。

1. 将“急弯证据”定义为连续边界切向的累计变化、弧长支持、两侧一致性及曲线可通行性。**单一大斜率只是车身相对道路的方向，不足以独立证明是急弯。**
2. 在同向急弯中，即使直线RMS较低，也允许经过验证的弧形候选参与选择；依据整体轮廓和目标可达性裁决，不仅靠RMS>45的单阈值。
3. 对接近横向的曲段使用沿轮廓弧长采样与局部切向，不再把y跨度当成唯一有效长度。保留局部噪声、断簇、跨墙连接和空间余量检查。
4. 已确认同向弧形之后，模型退出依据持续的直道/出弯几何，减少一帧直线恢复引起的来回切换。可靠S弯拐点不受“继续同向”的历史约束。
5. 区分“道路中心轮廓”和“当前可跟踪目标”：弯中沿有支持的曲线选点，验证连接段/局部行驶通路，避免以一条远处切线的横截面目标代替整条转弯路径。
6. 不直接扩大700 mm急弯目标距离，也不全局降低点数、跨度、斜率门槛。远处轮廓用于识别趋势，实际跟踪目标服从可见支持和弯曲程度。

验收：复现seq17779、25859、319等现场，输出能解释的边界/曲线支持或明确拒绝原因；对已经过近、只剩贴墙视野的快照，不以强行生成目标为成功标准。关键指标是在失效之前持续保留正确路径。

### 第三阶段：急弯入口有限外移与实车几何校核

在前两阶段消除错误回摆后实施，以便分清哪项改动带来收益。

1. `cx=10`继续只承担全局居中校准。新增独立急弯轨迹偏置：右急弯入口向左、左急弯入口向右；沿局部路径法线计算，不把全局x横移当作所有姿态下相同侧隙。
2. 只有连续同向急弯、足够轮廓支持、可信外侧边界和实际余量满足时启用。长缓弯、普通直道、近远反向S弯预告以及证据冲突时不启动新的外移。
3. **初始实验幅度建议20～30 mm，上限暂设40 mm作为回放/实车验证候选值，不是已标定最优值。** 有效偏移还必须受可见走廊余量限制，空间不足时可小于此值或为0。不能按500 mm名义宽度盲算固定额度。
4. 外移在入弯准备段建立；弯中依据实际内外侧余量调整，出口外墙变近或路径切向趋直时平滑撤销。右弯向左布位不等于弯中持续给左舵，更不能在已有撞外墙趋势时继续外推。
5. 外移与锥桶避让不能直接相加：统一计算允许通行的横向区间。锥桶位于外侧时应削减/取消急弯外移；模型切换不应悄悄丢掉仍然可见的障碍约束。
6. 几何参数更新为轴距305 mm、雷达到后轴205 mm、雷达到前轴100 mm、轮外沿宽约260 mm。385 mm是轮胎最前到最后外廓，不能直接等同完整车身前后悬；旧350 mm注释后续同步修正。
7. 首版用于有限几何校核和轨迹对比；待测得舵角/最小转弯半径与物理速度后，再决定是否引入局部后轴运动学候选路径。暂不整体替换成熟PD，也不宣称当前雷达点中心余量等于全车扫掠余量。

验收：既改善入口内侧间隙，也不能增大出口外侧接触。若只看“离内墙更远”而忽略前轮/车头碰外墙，应判为失败。

### 并行的小改进：让下一次遥测保住现场

涉及 `HARDWARE/hc-05/ble_diag.c`、会话/发送相关文件和 `上位机/robocup_telemetry.py`。

1. 现有点云首次自动冻结主要由几何无效/避让事件触发，可能晚于目标跳变。增加边界身份突变、异常同向减舵、模型异常切换的事件触发，优先保存前后现场；复用现有缓冲区，不先扩大RAM。
2. 补充候选身份、重复关联计数、目标差、几何置信度、弧形拒绝细分、急弯状态及实际外移。按事件或低频输出；同步版本/配置描述和解析器，不擅自拼接到旧固定帧尾部。
3. `201147`原始回包持续为 `CLOUD id=10 state=2 frames=8 sending=0`，没有点云帧。说明该次有冻结数据但未观察到导出启动；不能仅归为“蓝牙慢”。上位机应等待freeze确认再dump，按同一cloud/session检测未启动并有限重试，明确显示完整/未完整。
4. `200513`在seq22345恢复session=0，板端时间连续。需连同此前会话清零问题处理：握手阶段也核对session，遇到会话丢失明确终止/重协商，不让“用户停止、error=null”掩盖未正式开始。
5. 本批仍有诊断附加帧缺失、一个CONTROL序号缺口。优先保障控制摘要和关键事件；不为诊断在主循环中新增阻塞发送、全速点云流或等待串口完成。

这部分可以独立验证，不必与运动控制改动同时烧录调参。

## 7. 如何保留已有优势

| 场景 | 本轮约束与回归重点 |
| --- | --- |
| 直道居中 | 保留cx=10，急弯附加偏移为0；基线几何可信时PWM不应无故变化 |
| 轻微弯度的长道路、缓弯 | 不因绝对斜率大就启动急弯模式；验证整段累计方向变化和曲率证据 |
| S弯 | 不全局锁舵/延长确认；几何确实变向时及时撤销旧急弯偏置；比较第二弯接管时刻 |
| 小弯、局部遮挡 | 保留现有有支持的近段恢复；排他关联不能误删另一条真实边界 |
| 锥桶 | 继续保留现有尺寸包络；急弯偏置与避让共享余量；新增急弯边界被误判成锥桶的反例 |
| 速度与电机 | 第一轮保留17/15、编码器PI及当前速度规划，便于对比；不增加自动停车 |
| 实时性/RAM | 使用固定上限工作区；估算新增静态状态、栈峰值、每帧最坏耗时，检查最终map；不以桌面回放时间代替F407实测 |

保留已有成功样本以及上一轮良好S弯序列。旧基线使用过不同cx/速度，需区分“旧参数兼容回归”和“当前17/15、cx10的新基线”。镜像几何测试应同时变换坐标和校准偏置的符号，不能用不一致的镜像参数证明左右对称。

新六组均为急弯，**没有新的高速S弯通过样本**，因此当前不能宣称这次方案已经证明不会损害S弯；必须把上述场景纳入实施后的验收。

## 8. 数据质量、实时性与剩余不确定性

- 六个bin重新解析均未发现V2坏帧，已接收报文的tx序号未出现缺口；这只说明收到的诊断报文可用，不能证明固件从未丢弃待发诊断。
- 正式窗口DETAIL缺失分别3/3/—/1/0/2帧，PATH_EXTRA缺失3/3/—/2/0/2帧；右201147还缺CONTROL seq27062。模型RACE为稀疏输出，不能把缺失model当成0。
- 前五组HEALTH中的历史 `rx_overflow=34` 未继续增长，第六组为0；`input_drop`、`scan_overflow`均为0。另有少量UART错误和tx_drop增长，需单独跟踪，不能说链路完全无问题。
- 正式窗口控制周期中位约80～89 ms，个别周期约160～169 ms；记录的处理耗时最高约7.7 ms。这不支持“几何计算一直卡住”的说法，但也不能忽略偶发扫描/调度间隔变长。先按事件对齐UART/扫描有效性查原因，不盲目扩大DMA。
- 右201936持续约1178命令仍过不去：可能同时涉及入口位置、识别阶段、实际满舵转弯半径与轮胎侧滑。当前无实测轮角/运动轨迹，不能在软件与机械之间给出唯一比例。
- 当前摄像不能精确判定最先碰的是前轮、车头还是后轮；建议下一次固定机位拍摄入口至出口，保证前后轮都可见，并记录可辨认的同步起始标记。

## 9. 实施前后最有价值的补充数据

第一阶段现在即可做，不需要等待全部标定。后续外移与提速标定建议补充：

1. 左、右满舵低速行驶的实际最小转弯直径，或PWM与实际前轮角关系；并观察15速度时是否明显推头/侧滑。
2. 急弯入口、顶点、出口实际可通行宽度，以及内外边界的尺寸；照片中的波纹管不是严格恒宽圆弧，不能据透视估算精确半径。
3. 同一摆放、相同17/15、cx10下左右急弯各至少3次，记录首次触碰部位；改善样本200137的入口位置作为对照。
4. 一组现有表现良好的缓弯、一组当前速度下的S弯、左右单侧锥桶各一组，作为不退步验证。

执行顺序建议：**修边界身份/近远接管 → 修急弯轮廓连续跟踪 → 验证缓弯与S弯 → 逐步启用小幅入口外移 → 再决定速度上限和机械需求。** 不把改Kp、改预瞄、改速度、改外移量同时混在一次试车中。
