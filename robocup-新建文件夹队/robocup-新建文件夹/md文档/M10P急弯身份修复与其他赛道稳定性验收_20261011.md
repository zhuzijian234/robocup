# M10P急弯身份修复与其他赛道稳定性验收

日期：2026-10-11。依据：六次新急弯视频/遥测复核及用户批准的修改方案。

状态：生产代码、上位机兼容、针对性测试和最终固件编译已完成；尚未烧录实车验证。

## 1. 本轮实际改动

### 边界身份与重复关联

- 左右边界搜索后识别重合采样，保留有更早近场支持的一条链，截断另一条重复尾部。相同证据时不强行选边；仍允许真实边界跨过车体中线。
- 若去重前两条链均能拟合、去重后才恢复出单侧路径，额外验证可见连接通路。原来只有一侧有效的道路，不因冗余无效链而增加整帧拒绝。
- 保存上一有效帧的道路近段位置、方向和目标，不复制点云。在同向大角度弯中，若边界身份变化造成接近整条车道的错位，而反侧身份与旧道路一致，且当前可见占用没有挡住候选局部中心，恢复正确身份。
- 本帧独立双侧走廊优先于历史；S弯反向证据不执行同向身份修复。断流、坏扫描、配置版本变化会清除历史，不能将旧圈证据拼接到新扫描。

针对右201004中seq25854/25855的记录拟合字段，生产函数测试验证：修正后该墙保持LEFT身份，700 mm截面的候选目标回到900 mm以上，不再因错用RIGHT法向偏移而落到约119 mm。**这是记录拟合字段的重放；跳变前后的原始点云缺失，因此不能称为完整现场闭环复现。**

### 急弯路径与短时回摆处理

- 保留已有弧形恢复，对近远同向、方向变化明确的急弯入口增加候选比较；不再只依赖近段RMS>45这一条入口条件。
- 新入口候选若明显减弱当前有支持的转向需求，不立即替换旧目标；之前已经采用曲线的同向急弯允许继续比较曲线，减少模型偶发切换。
- 记录统一700 mm尺度的目标变化，分别识别来源改变、来源不变时的目标突变。
- 对同向大弯、近段方向稳定、没有S预告/避让/直道证据的异常减舵，控制误差每帧最多先减80 mm，连续限制最多两帧；约12 Hz下通常为两次扫描。之后按当前有效路径恢复正常控制。
- 明确的反向路径可当帧接管；长间隔、坏扫描和真实出弯不继承这个减舵限制。未加全局舵机低通、全局锁舵或自动停车。
- 弧形拒绝原因现在细分为长度、种子、切向、残差、方向突变、弯曲证据、入口占用、后续占用、支持范围、候选冲突等位图。

### 急弯入口外移

- 默认法向外移上限 **25 mm**，位置在 `path_track.c` 的 `ACUTE_OUTER_MM`，与全局 `cx=10` 分离。
- 需要连续两帧同方向急弯入口证据；近段方向小于0.6 rad、远段大于0.6 rad且增量大于0.35 rad，才准备外移。方向证据改变重新计数。
- 右急弯向左、左急弯向右，沿局部法线变换目标；按10 mm/帧建立和释放，再根据真实外墙余量缩小，可能减至0。
- 目标对应外墙必须在当前可见支持范围内，移动区域不得占用；轮外沿半宽130 mm另加20 mm侧隙。空间不足不执行外移。
- S预告、锥桶候选/避让/释放阶段让出这部分偏移，避免和避让量相加。退出急弯入口后逐步释放，不能全弯持续贴外墙。
- 更新几何说明为轴距305 mm、雷达到后轴205 mm、前轴在雷达前100 mm、轮胎前后外廓385 mm。未把这些尺寸包装成尚未标定的完整车辆扫掠模型。

保留 **直道上限17 / 弯速15 / cx10 / 电机PA5 / 编码器PI**。主程序速度设置和电机引脚没有改动。

## 2. 遥测和采集可靠性

- RACE从schema1的112字节扩展到schema2的148字节，仍每4个控制序号最多发送一次。按约12 Hz估算，新增约108字节/秒，不发送实时全点云。
- 新字段：`duplicate_samples`、`identity_corrected`、`target_transition`、`transition_limited`、`curve_checks`、`outer_offset`、`target_delta`、`bend_rad`、`outer_clearance`。
- `curve_checks`是尝试过的候选拒绝位图；其中有非零位不代表最终路径一定失败，应结合`model`和几何有效性解读。
- 点云schema3增加触发位64，表示身份/目标突变或减舵过渡；仍为两组共最多8帧，复用原缓冲区。
- INFO回传`race=2`；`cloud=2`继续表示两组快照能力，点云包自身schema为3。CONFIG几何描述增加`acute=entry25+identity`。
- 上位机同时支持旧RACE、旧点云及新格式；CSV新增列，旧帧对应新字段留空，不伪造为0。
- 停止采集后先等待freeze/status确认，再请求dump；未启动可限次重试，收到完整点数才结束，避免只有`sending=0`就误判成功。
- 握手期间收到当前会话后又发生会话清零/改变，会明确报错。用户在协商完成前停止也明确标注“非正式run”。
- 蓝牙STATE连续低100 ms才清零会话，一次短暂低采样不会立即破坏会话。等待通过时间戳实现，没有阻塞雷达/电机循环。真实断线仍会清理会话。

**烧录新固件后请重启当前工程的上位机，再采集。旧上位机进程尚未加载新解码器时，无法识别新增schema。**

## 5. 下一次实测建议

保持17/15、cx10，使用本轮HEX及重启后的新上位机：

1. 先验证直道居中、原有缓弯和S弯，观察是否新增摆动或第二弯换向变慢。
2. 同一摆放的左、右急弯各至少3次，视频看清入口到出口，记录首次接触部位。
3. 重点看急弯中的`identity_corrected`、`target_transition`、`transition_limited`及PWM；验证是否不再出现1178→1401/1423式突然收舵。
4. 看`outer_offset`是否仅在入口出现、出口能撤销；不能只看内侧余量增加，还要检查出口外侧是否更近。
5. 留存bin、meta、点云、race.csv，核对`process_us`、tx_drop及点云完整性。

本次完成的是代码与离线验证，未声称实车已经通过所有赛道。若持续接近满舵仍转不过来，下一步需要实际最小转弯直径、轮角或固定机位轨迹，不能继续无限增大软件增益。
