# M10P 第一轮修改交付

日期：2026-10-10。固件：`sha256-800f98727bd3cd9b`。尚未实车验证。

## 本轮改动

1. **双侧冲突时允许唯一可靠的单侧接管。** 候选必须有有效近远段、近段RMS≤35 mm，接缝距离≤80 mm、斜率差≤0.8、远段覆盖预瞄。在双方共同支持区域的三个位置检查对墙法向距离≥150 mm。双方都满足且仍互相矛盾时不凭历史方向强行选择；原有显著残差优势的单侧降级仍保留。本轮没有改变全局拟合RMS、分区数和跨度门槛。
2. **短参考的误差做有界尺度补偿。** 真实参考250～700 mm时，原始道路毫米误差乘`min(700/ref_y,1.5)`；700 mm及更远参考维持原比例。只调整控制误差，不外推点云；避让偏移不重复放大。`road_error`仍是原始误差，`pd_err`是限幅后用于控制的误差，CONFIG units已说明新语义。这能减轻参考变短时力度塌缩，不能消除不同边界或不同道路曲率造成的所有目标变化。
3. **等待确认期间允许可信减舵。** 当近段拟合可靠且朝向支持目标，或近远段已经直时，可以减小旧弯舵量。候选跨越中位则本次最多减到中位，确认后才反打；`gate_reason`保留原等待原因，`command_applied`说明是否实际执行。坏扫描、证据不足和旧避让残余仍不能获得这个权限。
4. **首次异常和停止时末段各保留最多4帧点云。** 首次异常冻结后，另一个缓存继续滚动；收到`cloud freeze`即冻结末段，不等待下一次雷达扫描。末段帧`trigger_flags`位5为1，最新一帧带手动冻结位3。仍只保存路径算法实际使用的前方点，不是全360°点云。
5. **上位机支持双快照。** CLOUD schema 2支持最多8帧/3200点，同时兼容旧schema 1。停止正式采集后自动导出、校验完整性和处理；新版导出上限24秒，旧版仍12秒。接收到发送完成提示后，仍等待全部点云实际到达才关闭串口。

本轮未改：速度10、10 ms编码器PI、电机PA5/TIM2_CH1、方向PB15、舵机PA6、M10P变长接收与DMA配置。没有恢复自动停车。
