# 蓝牙调参说明书

> 适用工程: `LXY传承-副本`（STM32F407VET6 @168MHz）
> 代码: [HARDWARE/hc-05/ble_tune.c](HARDWARE/hc-05/ble_tune.c) / [ble_tune.h](HARDWARE/hc-05/ble_tune.h)，设计原理见 [蓝牙实时调参方案.md](蓝牙实时调参方案.md)
> 前置：先按 [硬件测试说明书.md](硬件测试说明书.md) 测试③把蓝牙链路打通。
> **前提条件：main.c 里 `HW_TEST_SELECT` 必须是 0（正常循线模式）**，调参功能只在循线模式下工作。

---

## 1. 这是什么：两条数据流

```
【调参】手机/电脑 → HC-05 → USART6 → 每圈解析 → 直接改参数    (文本命令, 车跑动中实时生效)
【遥测】控制循环每帧 → USART6 → HC-05 → VOFA+ 波形组件        (二进制, 8通道实时曲线)
```

调参改的是**控制参数**（舵机 PD、电机 PI、几何补偿），不是代码——改完立刻生效、断电丢失（恢复出厂值=重烧固件或按 §8 表逐条发回去）。免烧录、免拖线，可以在车**跑动时**连续调。

---

## 2. 快速上手（5 分钟）

1. 手机/电脑连上 HC-05（配对码 `1234`，见硬件测试说明书 §5.2 的路径 A/B）。⚠️ **HC-05 同一时刻只接受一个连接**：电脑 VOFA+ 收不到任何字节时，先把手机蓝牙串口 APP 断开。
2. VOFA+ 新建连接：串口 → 选蓝牙 COM 号 → 波特率 9600 → 数据引擎先选 **RawData**。
3. 发送面板发 `get`（记得勾"发送新行"）→ 应收到 16 行参数回显，第一行 `kp=35`。链路通了。
4. 发 `kp 35` → 回 `OK kp=35`。参数已改（波形里 ch2 会变）。
5. 另建一个**数据引擎**看波形（类型必须选「数据引擎」，不能是「串口调试助手」，见 §4.1）→ 协议选 **justfloat** → 拖一个波形图组件 → 右键 → 设置 → Y轴 → 选 all → 出 8 条曲线（显示名 I0~I7，对应 §5 的 ch0~ch7）。文本回显留在 RawData 那个引擎看。全部打通。

> 回显规则：`OK 名字=值`（成功）/ `ERR fmt`（格式错）/ `ERR range`（超范围，**不写值**）/ `ERR name`（没有这个命令）。

## 4. VOFA+ 配置详解

### 4.1 连接与数据引擎

- 串口：9600, 8N1，选蓝牙对应的 COM 口。⚠️ Windows 蓝牙 SPP 会生成两个 COM（「传出」和「传入」），选**传出**那个；HC-05 同一时刻只接受一个连接，手机还连着时电脑收不到数据。
- ⚠️ **引擎类型必须建「数据引擎」，不是「串口调试助手」**：后者只显示 hex 日志、不解析通道，波形图绑不上它——"日志有字节但没波形"的头号原因就是它。
- **文本阶段用 RawData 协议**：能看到 `OK/ERR/get` 回显。
- **波形阶段用 justfloat 协议（实测）**：N 个 float32 小端 + 帧尾 `00 00 80 7F`，一选就自动识别出 8 通道。注意 VOFA+ 里的 **FireWater 是文本 CSV 协议**（逗号分隔 + 换行结尾），与本工程发的二进制无关；网上博客常把两者写反，认准"一选就自动出 8 通道波形"的那个。

### 4.2 波形组件

- 拖「波形图」组件入画布，绑定上面的 justfloat 数据引擎；右键 → 设置 → Y轴 → 选 all，显示出 8 条曲线。
- VOFA+ 里通道显示名固定为 **I0~I7**，一一对应 §5 的 ch0~ch7，改不了名字。
- **幅度太大看不清小参数**：台架上 ch0(err) 会打满 ±500、ch1(舵机PWM) 在 1170~1720 间跳，把其余曲线压平——点右侧图例里的 **I0、I1** 隐藏它们，剩下的 kp/kd/模式/速度会自动放大看清；滚轮缩放、按住拖动平移。
- 通道含义见 §5。

### 4.3 滑块控件（高级用法）

- VOFA+ 滑块默认发 `kp:45` 这种**冒号**格式——本解析器兼容，直接用。
- 滑块范围按**发送值**配（kp 建议 0~100，对应 0~0.100）。
- 发送面板手动输入时勾选"发送新行"（带 `\r\n`，解析器兼容）。

## 5. 遥测 8 通道表

每次雷达处理走到正常遥测出口时发一帧，8 通道 + 帧尾 = 36 字节（9600、8N1下串行时间约37.5ms）。114.8ms是按标称点率估算的DMA块填满时间，在每块都发一帧的假设下约占32.7%，不等于实测控制周期或链路稳定保证。有效点不足而提前continue时不发本帧。VOFA+ 波形图里显示为 **I0~I7**，依次对应下表 ch0~ch7。

| ch | 内容 | 看什么 |
|---|---|---|
| 0 | 误差 err | 震荡/收敛；理想是过弯快速归零 |
| 1 | 舵机 PWM | SERVO_PWM_MIN~MAX（谢露车 1170~1720，LXY 车 1360~1800）。**顶到上下限 = 饱和**，加大 kp 无意义 |
| 2 | 当前 kp | 确认参数真的改了 |
| 3 | 当前 kd | 同上 |
| 4 | 实际执行模式/动作 | 0～9为实际PD实参（含5垂线、7均值B）；10保持、11感知无效、12直接强制PWM。模式6当前无主循环调用。诊断值独立于控制决策pid_select |
| 5 | 当前速度 Speed_now | 速度环响应快慢 |
| 6 | 目标速度 Speed_mubiao | 与 ch5 对比看跟踪 |
| 7 | **雷达转速（度/秒）** | **6Hz=2160，8Hz=2880，÷360 就是 Hz**。雷达不转、掉速、或验 PWM 控速是否生效时看这一路（2026-09-19 新增，见《激光雷达参数汇总.md》§4.4）|

**口径提醒**：

- 已修正5/7记录，使用独立telemetry_mode，不更改控制历史pid_select。ch1取TIM3 CCR1指令值（不是舵机实测角度）；ch4为10/11/12时ch0发送quiet NaN，表示本帧未计算PD误差，不修改PD历史。帧长仍为36B。旧版自制上位机需兼容这三个状态及NaN。
- 直道中位 PWM 约 **1560**（代码里 `servo_midpwm = SERVO_PWM_MID / 10.0f` 是 float，传给 uint16_t 参数时被截断：1565→156.5→156，内部 ×10 = 1560；不是 1565。谢露车改宏后为 1445→1440）。
- 强制转弯帧（main.c 直接 `Servo_ChangePwm(SERVO_PWM_MIN/MAX)`）和首帧直道时，ch1 显示的是**上一帧的 PD 输出值**，不代表那一刻的物理 PWM——看波形时知道有这两种特殊情况即可。

## 6. 调参经验与操作顺序

0. **断电即恢复出厂——这是特意保留的安全设计**：参数只写在 RAM，调飞了直接断电重开 = 回到 §8 出厂值；调出好参数就 `get` 截图存档，下次上电按图重发。
1. **安全起步**：先 `spd 10` 低速跑，调稳了再提速。
2. **一次只改一个参数**，改完跑一圈看波形再决定下一步；用 `get` 随时记录当前整组参数（截图保存）。
3. **判读口诀**：
   - 直道左右画龙（蛇形）→ 调 `kp`（大）和 `kd`（大）
   - 大弯过冲/切内 → 调 `kp2`/`kd2`
   - 小弯贴边/刮线 → 调 `kp3`/`kd3`
   - 起步猛顿一下 → 降 `sp_ki`；提速上不去 → 加 `sp_ki`
   - ch1 常顶 SERVO_PWM_MIN/MAX（限幅值） → 舵机已饱和，加 kp 没用，先看机械/几何参数（`yr`/`yl`/`disr`/`disl`/`angle`）
4. **几何参数**只在确认模式走对（ch4）后再动：`yr/yl` 是转弯的目标 Y 坐标，`disr/disl` 是小转弯的边界补偿系数。
5. 曲线判读：ch0 err 快速回零+不震荡 = P/D 合适；ch5 跟 ch6 越紧 = 速度环越好。
6. 调好一组后**记录到文件**，防止断电丢失。

## 7. 常见问题 FAQ

| 问题 | 原因/处理 |
|---|---|
| 收不到任何波形 | ①没连接（HC-05 STATE 灯）②协议没选 justfloat ③波特率不是 9600 |
| 数据引擎日志有字节、波形图空白 | 引擎类型建成了「串口调试助手」（不解析通道）——重建「数据引擎」+ justfloat；或波形图没绑定引擎 |
| 电脑连上 COM 却一个字节都没有 | ①HC-05 还被手机占着（先断开手机）②选了「传入」COM（换「传出」）③波特率不是 9600 |
| 发命令没回显 | ①没勾"发送新行"（按行解析）②引擎在二进制模式（切回 RawData 看文本）③未连接（未连接时不回发） |
| `ERR fmt` | 格式错：没有数字、没加分隔符。例：`kp`（无值）、`kpabc` |
| `ERR range` | 值超范围（见 §3 表），参数没被写 |
| `ERR name` | 命令名不在表里（注意是 `sp_kp` 不是 `skp`） |
| 发命令后像"卡住"再也不回 | 尾巴缓冲里残留半行：多发一个**回车（空行）**即可自愈 |
| 断开重连后 | 自动恢复：STATE 脚检测到连接后遥测自动继续，无需复位 |
| 想恢复出厂参数 | 按 §8 表逐条发回去，或直接重烧固件 |
| 调参时车抽动一下 | 正常：改的是 PID 系数不是状态；若在弯里猛抖，可能你把 kp/kd 改太极端，改回来即可 |
| 波形卡顿/掉帧 | 当前36 B遥测在9600、8N1下约37.5ms/帧；旧7通道32 B约33.3ms的数字已不适用。先检查处理跳过、发送阻塞及链路错误，不能直接认定掉帧正常；需要有线诊断时使用USART3并限频，避免打印拖慢控制 |
| 车没连蓝牙能跑吗 | 能，未连接时调参模块零发送零阻塞，与没有此功能完全一样 |

## 雷达失效保护与诊断查询

> ⚠️ **本节已于 2026-10-08 全部改写。** 旧的"启动许可 / 500ms 锁停 / 需重启解锁"已由
> 《竞速模式清理_20261008.md》删除，不再存在。当前正常模式（`HW_TEST_SELECT=0`）**没有任何雷达停车逻辑**：
> 近墙、感知无效、数据过期、DMA 故障、雷达断流都不会清零目标速度或 PI 积分，
> 停车只能切断电机供电。固定目标 `Speed_mubiao=10`，雷达只影响转向。

诊断查询（都返回一行文本，未连接蓝牙时不回复）：

| 命令 | 返回 |
|---|---|
| `radar` | `packets=… discontinuities=… rejected=… overflow=… raw=… invalid=…`（接收与整圈统计） |
| `motor` | `race=1 pwm=… target_x100=… speed_x100=… frame_age_us=…` |
| `perception` | `seq=… ok=… src=… why=0x.. pd=… points=… front=… left=… right=… gap=… clear_mm=… age_us=… err=… cx=… cal=… mode=…` |

`perception` 的字段含义：
- `src` 本帧实际使用的转向来源：**0**=双侧中线、**1**=仅左侧跟线、**2**=仅右侧跟线、**3**=降级（有回波但判据不全）、**4**=保持（无回波，舵角不动）
- `why` 判据失败原因位图：bit0 正前方无有效点、bit1 前方桶数不足、bit2 前方连续盲区过大、
  bit3 左侧桶数不足、bit4 右侧桶数不足、bit5 接收代次不符、bit6 前方点年龄超限、bit7 点云超容量
- `pd=1` 才表示本帧真的执行了 PD；`mode` 为 0/5/7 时 `err` 才是"中线横向偏差"
- **`src` 长期等于 4 才是故障**（真的没有回波）；等于 1/2/3 是正常的锥桶赛道工作状态

## 9. 通道中线标定（换车/换赛道必做）

`CENTER_X_TARGET_MM`（`cx` 命令）是"车体坐标系里通道中线应该落在的横向位置"。它来自旧 LXY 车的标定值 **50mm**，
在车宽 26cm、通道 50cm 的场地上，单侧余量只有 120mm，**50mm 的常驻偏置会吃掉 40% 余量**，必须按本车重标。

原理：mode 0/5/7 的误差是 `err = cx − x_中线`，其中 `x_中线` 是雷达坐标系里通道中线的横向位置。
车摆正时 `x_中线` 就是真值 C，所以 **`cal = cx − err` 就是应该写进 `cx` 的数**。

步骤（**先 `tele 0` 关掉自动遥测**，否则文本回显和二进制混在一起）：

1. 找一段 ≥2m 的**直**通道，把车**摆正在通道正中、车身与通道平行**（左右间隙相等）。
2. 连蓝牙，反复发 `perception`，确认：
   - `pd=1`
   - `mode` 是 **0**（直道中线拟合）或 5/7；若一直是 1~4/8/9，说明没摆正或有杂物，读数作废
   - `front`/`left`/`right` 不是接近 0（否则没有中线可用）
3. 读多帧的 `cal=` 取平均（前几帧有瞬态，跳过）：
   ```
   perception … err=-3.2 cx=50.0 cal=53.2 mode=0
   ```
4. 发 `cx 53`（整数即可；分辨率 1mm）。
5. 再发 `perception` 复核，**`err` 应≈0**（|err| 建议 < 10mm）。
6. 顺手记录 `get` 的整组参数（`cx` 掉电丢失，`get` 截图存档）。

**注意**：
- `err` 只在 PD 成功执行时更新；`pd=0` 或 `mode` 为 1~4/8/9 时读到的是旧值/别的量，不能用来标定。
- mode 0 的 `err` 被 `eclamp` 限幅（默认 ±350mm）。若摆正后仍贴 ±350，说明机械偏置远超预期，先查雷达安装。
- 左右不对称（左间隙 ≠ 右间隙）时，`cal` 会把"车的摆放误差"一起标进去；**必须在真正摆正的状态下读**。
- 方向自检（**注意符号**）：把车向**右**平移 50mm 再读，`err` 应变化约 **+50**
  （车右移 → 通道中线相对雷达偏左 → `x_中线` 变小 → `err = cx − x_中线` 变大）；
  向**左**平移 50mm 应约 **−50**。方向对不上说明坐标系理解错了，别写 `cx`。
