# M10P 转向改造计划（2026-10-08）

依据：`tmp/ds_review_20261008/`（独立复核）+ 本文档 §11（我的错漏）。
基线：`build_m10p_verified/robocup_m10p.hex`，构建标识 `sha256-f90bfe8c202aa580`，
`python -B test/verify_m10p.py` 全绿（ARM 58 源文件 / 0 错误 / 33 警告 / RAM 85072B / ROM 41584B）。

**前提不变式**：不恢复自动停车；电机保持固定目标+编码器闭环；雷达只影响转向。

## 1. 问题分层

四份日志把"弯中主动收舵/回正、随后打回甚至反向打满"拆成四层，层与层独立：

| 层 | 问题 | 证据（复核探针/日志） | 影响面 |
|---|---|---|---|
| **L1 感知层** | 单侧可见 ⇒ 中线点 0 ⇒ PD 拒绝 ⇒ 舵机不更新 | `single-side: input=60 center=0 pd=0 writes=0 pwm=1645`；352 个无效帧中 **350 个 `ref_count=0`**，点数 303~718 | **最大**（无效帧 47%~89%） |
| **L2 判据层** | "出弯"只看 `\|err\|` 和一条线的局部 `\|k\|` | 24.249/24.338s（k=−4.53/−6.15）、24.507/24.585s（k=−5.34/−5.31）通过 `sk=2` 仍造成 1620→1431、1620→1418 | 弯中突然摆正 |
| **L3 仲裁层** | ①左右断点"谁近谁赢"无迟滞 ②`turn_direction(1/2)` 按模式编号判方向，与输出符号不符 ⇒ guard 压掉反向修正 | ①27.000→27.257s mode4→3→4→3、1170↔1720 ②`mode1-real: error=250 candidate=1543 final=1245 held=1` | 反向打满、甩舵 |
| **L4 期限层** | 350ms 到期**无条件**放行弱中线回正 | `guard-expiry: straight=0 held=0 pwm=1445` | 到期瞬间摆正 |

## 2. 修改大纲

### M1（L1，最高收益）单侧边界推算中线

**改哪里**：`HARDWARE/LEIDA_DATA/LEIDA_DATA.c` 的 `LEIDA_DATA_HANDLE4`（新增降级路径），必要时在 `LEIDA_DATA.h` 增接口。

**怎么改**：
1. 先在 `HANDLE4` 内统计两侧可用度：对 0~90° 与 90~180° 各数出"±0.5° 内有 100~2000mm 回波"的整数度数 → `avail_right` / `avail_left`。
2. 双侧都够（沿用现有阈值，建议各 ≥ 10°）→ **走现有双侧配对，代码路径与结果一字不改**（保证零回归）。
3. 只有一侧够 → 逐整数度生成"虚拟中线点"：
   - 该侧在角度 `i` 的回波横向坐标 `x_side`（左墙 x<0，右墙 x>0）
   - 对侧虚拟墙位置取 `± half`，`half` 优先用**最近一次可信的** `paodao_distance/2`，退化时用 `M10P_CAR_HALF_MM + 40mm` 兜底
   - 中点 `x = (x_side + x_virtual)/2`，`y` 用该侧回波的 y
   - 逐度写入 `data_center[]`，**保持"一条点列"的形态**，这样下游 mode 0 的拟合、mode 5 的垂线判据、mode 7 的均值都还能用
4. 两侧都不够 → 维持现状（`n=0` → PD 拒绝 → 这是真正的"没数据"，`src=4`）

**为什么这么做**：`HANDLE4` 是逐角度双侧配对，任一侧缺就 `continue`（`LEIDA_DATA.c:121-122`）。单侧可见在锥桶/铝箔管赛道是常态，但通道宽度是已知先验，可以用"单侧墙 + 半宽"把中线补出来。这正是复核第 6 条"真正实现单侧边界推算中线"。

**验收**：
- 新增 C 检查（在 `test/check_m10p_geometry.py`）：单侧输入 60 点（复核构造：`angle=i+1, distance=300/cos`）→ `CENTER_cnt > 0` 且中线 x 与真值误差 < 20mm
- 双侧输入结果与旧实现**逐点一致**（把旧实现保留为对照函数，随机 100 组比对）
- 复核探针输出从 `center=0 pd=0 writes=0` 变为 `center>0 pd=1 writes=1`
- 离线回放 175104/175407：`ref_count=0` 的帧数应显著下降

### M2（L2）出弯判据从"单线斜率"升级为"多点一致性"

**改哪里**：`USER/main.c` 的 `straight_evidence` 表达式；判据函数可放 `CENTRE_LINE.c`。

**怎么改**：把单一 `|Midline.k| >= STRAIGHT_MIN_K` 换/补成"前方路径真的直"的多点证据：
- **(a) 近远段横向一致性**（首选，简单且直观）：把中线窗口按 y 分成近段(0~40%)与远段(60~100%)，各求平均 `x`，要求 `|x_near − x_far| <= STRAIGHT_X_SPAN`（初值 40mm）
- **(b) 三点 Menger 曲率**（已有 `curvity_cal`）：要求 `|曲率| <= STRAIGHT_MAX_CURV`
- **(c) 保留 `|k| >= STRAIGHT_MIN_K` 作为必要条件之一**
- **(d) 出弯确认加严**：`TURN_EXIT_FRAMES` 2→3，且要求连续帧的 `err` **同号**（防止 ±抖动凑够两帧）

**为什么**：复核明确"斜率反映局部拟合朝向，不足以证明整条前方路径已经出弯"。`sk` 只拦一类误出弯。

**验收**：
- 离线回放 175104 的 24.249/24.338/24.507/24.585s 四帧 → `straight_evidence` 必须为 **0**
- 真直道帧（如 163634 的稳定段）仍为 **1**
- 现有 143 条转向回归保持通过（`tick(0,...)` 的直道确认用例需要同步：桩里的中线点要构造成"近远段一致"）

---

### M3（L3）方向仲裁：迟滞 + 用输出符号判方向

**改哪里**：`CENTRE_LINE.c` 的 `turn_direction` / `TurnGuard_Apply`；`USER/main.c` 的左右断点仲裁。

**M3-A 断点仲裁加迟滞**（改 `main.c`）：
- 现状：`LEFT_duandian > RIGHT_duandian` 就丢左边，逐帧可翻转
- 改：若 `turn_guard.active` 且其方向已知，则**反向切换需要额外条件**——`新侧断点 < 0.6 × 另一侧`（明显更近）**或**连续 2 帧都指向新侧；否则维持原方向

**M3-B `turn_direction` 改由输出符号决定**（改 `CENTRE_LINE.c`）：
- 现状：`turn_direction(1)=1`（右）、`turn_direction(2)=2`（左），但 mode 1/2 的实际输出符号随通道几何变化 → guard 把"实际要求左打"的候选当同向弱指令压掉（复核 `mode1-real`）
- 改：`turn_direction` 只对**真正定向的** mode 3/4/8/9 返回方向；mode 1/2 返回 **0**（它们是通道居中）；guard 内部的同向/反向判断改用**候选相对中位的偏移符号**（`cand = pwm − SERVO_PWM_MID`）
- 新增分支：guard 活跃且 `cand` 与锚点偏移**反号**且 `|cand| >= TURN_RELEASE_MIN`（初值 60 计数）→ **立即释放并采用新候选**

**为什么**：复核第 3 条"slew 只减小幅度，不能纠正错误目标"；且 `mode1-real` 证明 guard 会压掉正确的反向修正。

**验收**：
- 复核 `mode1-real` 探针从 `final=1245 held=1` 变为采用候选 1543
- `mode1 opposite correction desired=1600 actual=1245` 变为 actual=1600
- 离线回放 27.000~27.257s 不再出现 1720↔1170 逐帧交替
- 现有同向"保持强转向"用例（`tick(small,1,weak)` 期望 held）保持通过

### M4（L4）350ms 到期必须带证据

**改哪里**：`CENTRE_LINE.c` 的 `TurnGuard_Apply` 到期分支。

**怎么改**：
- 到期时只有满足其一才放行：`straight` 为真 / 候选反向 / `|cand| >= TURN_MIN_OFFSET`
- 都不满足（近中位且无直道证据）→ **重挂一个期限**（`observed_us = now`），并设**最多重挂 1 次**（总上限约 700ms），避免复核指出的"无限固定旧舵角"

**为什么**：复核第 6 条"350ms 到期用于重新评估来源，不应直接批准弱中线回正，也不应无限固定旧舵角"。

**验收**：
- 复核 `guard-expiry` 探针：`straight=0` 且候选近中位 → `held=1`；给 `straight=1` → 释放
- 反向/强候选到期 → 立即放行

---

### M5（支撑，先做）低频仲裁诊断

**改哪里**：`HARDWARE/hc-05/ble_diag.c`（复用 DETAIL 索引 12~20，这些是 LD14P 遗留、M10P 下恒 0）+ `ble_tune.c` 的 `perception` 文本。

**至少要有**：`steer_source`、`why`、`executed_mode`（当前只在局部变量里）、`ref_count`、`center_cnt`、`straight_evidence`、`anchor_pwm`、`guard_active`、`guard_held`、`cand_offset`。

**为什么**：复核第 7 条"增加明确仲裁原因、限幅前后目标、所用边界及拟合质量的低频诊断，**先复现这几个事件再提固定目标速度**"。没有它，M1~M4 的效果无法归因。

**验收**：上车后 `perception` 一行能看到 `straight`/`guard`/`cand` 三个新字段；离线 CSV 能对每个"回正"帧读出原因。

## 3. 实施顺序（每阶段独立可烧可验）

| 阶段 | 内容 | 依赖 | 独立验证手段 |
|---|---|---|---|
| **S1** | M5 诊断增强 | 无 | `verify_m10p.py` + 上车回读 `perception` |
| **S2** | M3-B（方向改由输出符号决定） | S1 | 复核 `mode1-real`/`mode1 opposite` 探针 + 143 转向回归 |
| **S3** | **M1 单侧推算中线** | S1 | 新增单侧 C 检查 + 175104/175407 离线 `ref_count` 统计 |
| **S4** | M2 出弯判据（近远段一致性 + 曲率） | S1、S3 | 175104 四帧必须判"非直道" + 真直道帧仍判"直" |
| **S5** | M3-A 断点仲裁迟滞 | S2 | 27.000~27.257s 离线回放 |
| **S6** | M4 到期需证据 | S4 | 复核 `guard-expiry` 探针 |

**顺序理由**：复核明确"**先消除错误方向，再按时间和转向任务设计限幅**"，所以 S2 早于任何限幅类改动；M1 收益最大但需要 S1 的诊断才能证明有效；S3 之后 `ref_count` 才有意义，S4 的"直道证据"才不容易被单侧补点污染。

## 4. 每阶段的硬门槛

1. `python -B test/verify_m10p.py` **全绿**（含 ARM 链接）
2. 新增检查必须**同时包含正反例**（能判"直"也要能判"不直"）
3. 四份日志（175104 / 175252 / 175407 / 175457）离线回放：对应现象的帧数必须下降，且**不得**引入新的 `action=5`
4. 每阶段保留可烧录 hex + 构建标识 + `source_manifest.json`
5. 参数默认值必须与 `test/check_control_fixes.py` 的桩**逐字一致**（本次踩过：桩写 150 而生产是 600，导致误判）

## 6. 风险与回退

| 风险 | 缓解 |
|---|---|
| M1 是新增功能，可能污染双侧拟合 | 双侧时**原路径一字不改**；随机 100 组对照旧实现逐点一致 |
| M2/M3/M4 都改判据，可能互相掩盖 | 严格顺序 S2→S3→S4→S5→S6，每阶段单独烧录验证，一次只动一层 |
| 单侧推算的半宽估值错误 → 中线偏 | `half` 用"最近一次可信 paodao/2"，并在 `perception` 里输出 `half` 与来源（实测/兜底） |
| 迟滞导致反向弯响应变慢 | 迟滞只对"同侧反复翻转"生效；`|反向断点| < 0.6×` 立即放行；用 175252 的跨中位序列验收 |
| 参数膨胀 | 键位按 121 起顺延，`CONFIG` 分片数同步；旧上位机忽略未知键 ✓ |

**回退**：每个阶段独立提交，任一回退只需恢复该阶段的固件；驱动侧只依赖"目标速度固定"，不受转向改造影响。
