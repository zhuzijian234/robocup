# M10P 转向修正与诊断交付（2026-10-10）

本次完成已有证据支持的局部修正与诊断闭环，不代表上一份计划中的所有新几何算法都已实施。工程为 `LXY传承-m10p`，目标速度仍为10，保留编码器速度闭环，不新增自动停车或弯道降速。未改雷达接收协议、DMA、转速、电机引脚和速度PI参数。

## 1. 已确认的尺寸与使用范围

| 项目 | 数值与处理 |
| --- | --- |
| 车长、车身宽 | 350 × 240 mm |
| 雷达距车头 | 140～150 mm；由车长推算距车尾200～210 mm |
| 雷达距左右轮外沿 | 此前约130 mm；横向避让仍按130 mm半宽加20 mm侧隙，不能用较小的车身半宽替代轮胎外沿 |
| 扫描高度 | 150 mm |
| 锥桶 | 200 × 200 mm方底座，总高300 mm；底圆直径150 mm、高23 mm；顶圆直径50 mm |
| 扫描截面 | 按圆台线性尺寸估计半径约52 mm；算法仍使用52 mm截面圆识别 |
| 底座包络 | 方底座任意朝向外接圆半径约142 mm；计算采用170 mm，包含中心估计余量 |
| 通行空间 | 约500 mm，锥桶不在两侧同时封堵 |

350 mm车长不能当作轴距。当前仍是局部道路法向横移模型，没有假称完成车头、车尾随转弯扫过区域的验证。整车转弯轨迹模型还需要轴距及PWM与实际轮角的对照。

## 2. 现有数据能够确定什么

1. **第三次遥测存在避让释放与保舵耦合。** seq7454的道路误差约15.9 mm、残余避让约15.2 mm，叠加后误差接近0。旧代码仅因偏移非零就覆盖等待，把PWM写到1445；随后几帧恢复WAIT_EXIT，实际保持的却已经是中位。此次增加对应生产控制函数回归，释放/保持残余不得再覆盖保舵。
2. **几何间断是真实问题。** 第二、三次都有连续6帧没有新几何，首末约414 ms；有效数据年龄和接收统计没有对应的大幅恶化。不能把这种间断直接归咎于DMA或主循环处理慢。
3. **参考距离变化明显。** 有419→700 mm的相邻变化，同时PWM发生明显跳变。此次改善固定400 mm参考的边缘失配，尚未把控制改为距离归一化或二维折线路径。
4. **弯道测得宽度会波动。** 第二次约458～486 mm，第三次约446～506 mm。旧代码每个可信双侧帧都写入历史宽度；此次将历史更新限制在高质量、近远段一致的直道。
5. **第二、三次实际速度平均约10.03、9.99。** 当前没有数据要求改变速度环。
6. 第一组日志主要记录静止状态，不能强行与运动视频末尾对齐。第二、三次视频与遥测也没有可靠的共同时间标记，不宣称逐帧已经精确同步。

避让偏移与回正的联系有数据支持，但旧日志没有点云，无法证明每个圆弧究竟是真锥桶还是围挡碎片。近直角弯道和靠墙锥桶召回问题仍需要新点云确认。

## 3. 本次控制修改

- 将道路误差、避让偏移、道路裁决、最终执行分别记录。只有本帧连续确认的锥桶目标可覆盖道路等待；候选、遮挡保持、释放残余没有此权限。
- 圆弧中心需连续两帧相容才介入：横向差不超过100 mm、纵向差不超过150 mm。新目标重新确认；这会增加约一帧确认时间，用来抑制单帧误识别，不承诺解决持续的波纹围挡误判。
- 无效几何、坏扫描或扫描间隔超过250 ms会清除旧锥桶确认与偏移状态。这里清的是避让历史，不是电机速度或停车状态。
- 近参考默认400 mm；在真实边界支持下，允许移到250～450 mm。跨度、点数、间隙和残差门槛没有统一放松。
- 弯道、避让阶段不更新历史宽度。本帧可靠双侧宽度仍可用于当前避让及连续的单侧远段，避免宽赛段误用旧500 mm宽度把中心移偏。
- 三组PD基础增益、大误差增强和1170～1720 PWM限位保持不变。

主要文件：`HARDWARE/CENTRE_LINE/path_track.c/.h`、`CENTRE_LINE.c`。

## 4. 新诊断输出

原type5 DETAIL schema2保持不变。新增独立的type8/schema1扩展帧，176字节，与CONTROL/DETAIL按 `(session, control_seq, param_revision)` 配对，另有input_seq核对输入。没有修改旧字段含义或扩大256字节发送缓冲。

上位机新增 `.path.csv`：

| 字段 | 含义 |
| --- | --- |
| geometry_reason | 0通过；1输入/参数问题；2近段均不可用；3双侧矛盾；4参考无实际支撑 |
| fit_rejected | 四个字节分别为左近、右近、左远、右远的拒绝位图 |
| 拒绝位图 | 1分区点数不足；2前向跨度不足；4间隙过大；8退化拟合；16残差过大；32斜率超出当前模型 |
| road_target / target_x / road_error | 未避让道路目标、叠加避让后的目标、未限幅道路误差 |
| avoid_state | 0无偏移；1候选；2当前确认；3短暂保持；4释放 |
| avoid_confirm / cone_candidates | 当前关联确认帧数、通过圆弧形状筛选的候选数 |
| cone_x / cone_y / cone_lateral | 选中冲突目标的坐标及相对道路法向位置 |
| avoid_required / avoid_allowed | 请求法向横移、对墙预算允许横移；请求大于允许表示只能部分避让，不代表已证明能通过 |
| avoid_offset / avoid_y | 实际目标横移、当前冲突目标前向位置 |
| near_ref_y / width_candidate / width_frozen | 实际近参考、本帧候选宽度、是否冻结历史学习 |
| gate_reason / avoid_override | 避让覆盖前的道路裁决、是否实际覆盖等待 |
| 四组a/b/min_y/max_y | 近远左右拟合及其真实支持范围；须结合拒绝位图判断，失败拟合的0不等于零误差 |

几何失败时当前版本不运行锥桶避让分析，因此此时候选数0不能解释为场景没有锥桶；必须结合点云检查。

## 5. 四帧点云快照与采集方法

固件在新V2 session时自动准备4帧环形缓存，每帧最多400个前方Cartesian点。通常在至少3个可用几何帧后，首次出现几何失效或确认锥桶时触发，保存触发前两帧、触发帧、后一帧，然后冻结。缓存是送入路径算法的前方点，**不是原始整圈雷达包**。x向右、y向前，单位mm；整数导出误差小于1 mm。

1. 烧录本次HEX，使用本工程更新后的上位机。
2. 点击“一键诊断”，发车前完成INFO/配置协商。固件INFO含 `extra=1 cloud=1`。
3. 进行一次固定速度10的测试并保留视频。点击停止采集或等待采集时长结束。
4. 上位机自动执行 `cloud freeze`、`cloud dump`，最多继续接收12秒，然后保存。停止采集不控制小车电机；不要在导出前切断雷达主控/蓝牙电源或关闭程序。
5. 报告旁会新增 `.path.csv`、`.cloud.csv`、`.cloud_frames.csv`。提交原始 `.bin`、`.meta.json`、`.rx.jsonl` 和这些文件即可，保留三次测试的对应关系。

手动命令：

```text
cloud status   # 查看id、state、frames、sending
cloud arm      # 清空旧快照，重新捕获；会丢弃尚未导出的旧缓存
cloud freeze   # 未自动触发时冻结当前最近几帧
cloud dump     # 导出已冻结快照，完成后可再次导出
```

state=1为采集中，2为冻结。若想专门捕获后面的S弯而首个事件已经冻结，可在目标路段前重新arm；每个会话默认只冻结一个事件，不代表覆盖全程。

type9/schema1每包最多40点，最多224字节，每200 ms一包。队列满仅推迟发送，不在控制函数中等待。4帧满载约8秒传完，拥堵时可能超过；上位机到12秒仍不完整会保留已收数据并记录超时，不能声称完整。

`.cloud_frames.csv` 的 `complete=1` 且 `conflict=0` 才能按完整帧使用。丢块不补零，冲突不静默覆盖为“成功”。发送完成ACK可能先于最后一个普通优先级数据包到达，上位机会检查实际点集齐全后再关闭串口。

正式行驶窗口结束时间写入 `formal_end_s`。导出期间CONTROL/MOTOR仍保存在原始记录中，但不混入正式行驶统计。旧固件没有cloud能力时不发送这些命令。

常态新增扩展约176×12=2112 B/s；点云仅导出时额外最多1120 B/s。需在下一次实车记录确认tx_drop/motor_drop没有增长，串口理论余量不能替代无线链路实测。
