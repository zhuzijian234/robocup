# M10P代码架构说明

本次整理保留已经验证的接收、选点和控制策略，集中配置、隔离历史实现，并明确模块边界。没有更改运行门限、波特率、坐标方向或控制增益。

## 阅读顺序与职责

| 文件 | 职责与约束 |
| --- | --- |
| `HARDWARE/LEIDA_DATA/m10p_config.h` | 协议常量、点云容量、安装角、有效距离与前向安全包络的唯一配置入口；不依赖STM32头文件 |
| `HARDWARE/DMA/DMA.h/.c` | USART2 DMA循环接收与字节队列；ISR只搬字节，主循环负责故障恢复；缓冲参数有编译期约束 |
| `HARDWARE/LEIDA_DATA/m10p.h/.c` | 可移植解析器：160字节组包、字段校验、角度转换、整圈完整性和双缓冲所有权；不驱动电机 |
| `HARDWARE/LEIDA_DATA/m10p_vehicle.h/.c` | 接收层与车辆算法之间的适配：每轮有界取块、生成工作点云、检查缺测/新鲜度/近障、输出限速系数 |
| `HARDWARE/LEIDA_DATA/LEIDA_DATA.h/.c` | 当前使用的几何算法：角索引、边界、中线、断点、前方墙面与宽度；不再承担运行时协议解析 |
| `USER/main.c` | 初始化、取得扫描、计算转向、提交有效观测、归还扫描；可切换硬件测试模式仍保留 |
| `HARDWARE/LEIDA_TIMER/timer.h/.c` | 10ms速度环和驱动许可最终仲裁；失效/过期即撤销推进，恢复需连续有效观测 |
| `HARDWARE/hc-05/` | 遥测、蓝牙调参和发送队列；兼容字段保留，M10P健康度由M10P专用统计报告 |

调用链：`DMA ISR → 字节队列 → M10P_Poll → M10P_Feed → M10P_Acquire → M10P_Build → 几何/PD → Radar_Observe → M10P_Release`。TIM5独立检查许可并执行速度PI。

## 停用代码

以下历史实现用 `#if 0` 注释式隔离，源码保留供比较，但不参与M10P固件编译：

- LD14P解析器 `LEIDA_ParserReset`、`LEIDA_DATA_HANDLE1` 及47字节暂存区、旧原始点云 `LEIDA_DATA[800]`。
- 旧筛选函数 `HANDLE3/HANDLE3_2`，已由M10P整圈适配替代。
- 旧自动角度校准、预留 `HANDLE12`、未调用的 `HANDLE13`。
- 三个未调用的整圈文本打印函数；正式诊断继续使用蓝牙遥测。
- `leida_pwm.c` 的外部雷达电机PWM实现、预留 `TIM14_Int_Init`。
- 主程序中无读写调用的旧调试/状态变量。

停用接口在头文件也做相同隔离，主程序不再包含旧雷达PWM头文件。不要为了消除编译报错直接打开某段历史代码；若要恢复旧型号，应使用独立LD14P工程并重新审查接口与引脚。

旧解析统计仍被遥测和调试命令引用，因此保留兼容字段；硬件测试模式、正在使用的 `reverse`、共享几何函数及厂商外设库也保留，不能仅凭主程序未直接调用就屏蔽它们。

## 关键中文注释

补充了中断/主循环所有权、DMB发布顺序、故障epoch、保守接收时间戳、整圈借用归还、驱动许可和恢复条件。修正原注释中的DMA块大小（512字节）、后方切圈（原生180°）、近于100mm的处理（仍参与近障保护），以及“返回0即可认定道路畅通”等歧义。

DMA队列索引不再散落常数15，统一使用 `LIDAR_RX_BLOCKS-1`；头文件要求队列容量为2的幂，DMA缓冲恰好含两个半块。改变参数时不满足结构要求会在编译阶段报错。

## 验证

运行 `python test/verify_m10p.py`。除了原有解析、几何、控制、DMA和遥测回归，还会核对最终ARM符号表，确保停用的旧入口和旧原始点云没有进入固件。

历史宿主回归会直接提取旧函数作为对照，这不代表旧函数仍在固件运行。最终有效范围以C预处理结果和ARM链接符号表为准。最新RAM/ROM、构建标识和HEX摘要见《M10P移植交付说明.md》及 `build_m10p_verified/summary.json`。
