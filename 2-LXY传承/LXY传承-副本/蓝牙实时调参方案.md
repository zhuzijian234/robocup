## 1. 系统概览

### 1.1 两条数据流

| 方向 | 称呼 | 内容 | 路径 |
|---|---|---|---|
| PC → 车 | 🎛️ **调参** | 文本命令改参数 | VOFA+ 发送面板 → HC-05 → USART6 → 主循环解析 → 写变量 |
| 车 → PC | 📤 **发送** | 二进制波形回传 | 控制循环组 float 帧 → USART6 → HC-05 → VOFA+ 波形 |

### 1.2 完整链路

```
┌─────────────┐   COM口    ┌──────────────────────┐   2.4G蓝牙    ┌─────────────────┐  USART6  ┌─────────┐
│   VOFA+     │ ─────────> │ 路径A: 笔记本自带蓝牙   │ ┄┄┄┄┄┄┄┄┄┄> │ 车上HC-05(从机)  │ ───────> │ STM32   │
│  (PC软件)   │            │ 路径B: CH340+HC-05转接器 │  SPP透传     │                 │  9600bps │ F407    │
└─────────────┘            └──────────────────────┘              └─────────────────┘          └─────────┘
```

**关键事实：VOFA+ 只认 COM 串口，不知道下面是蓝牙还是 USB。** 只要蓝牙在 Windows 上变成（或挂在）一个 COM 口，VOFA+ 就能像开普通串口一样打开它。

### 1.3 为什么值得做

1. **免烧录**：有线方案每改一次 kp 都要停车、断电、重烧固件；蓝牙改值几十 ms 生效，可连续迭代几十组参数
2. **真实测试条件**：车拖着串口线跑，线会拽车、绕轮子，调出的参数与比赛状态有偏差
3. **硬件已就位**：HC-05、USART6 中断接收、STATE 引脚全部已接好，只缺一层解析代码（外加头文件补一行声明，见 §4.4）

## 2. 硬件连接

### 2.1 车上：HC-05 ↔ STM32（已接好，无需改动）

USART6 引脚复用（与谢露版对照后确定）：

| HC-05 引脚 | 接 STM32 引脚 | 功能 | 备注 |
|---|---|---|---|
| VCC | 3.3V | 供电 | 裸模块严禁 5V |
| GND | GND | 共地 | 必须 |
| TXD | **PC7** (USART6_RX) | 模块发→单片机收 | 交叉 |
| RXD | **PC6** (USART6_TX) | 单片机发→模块收 | 交叉 |
| STATE | **PC2** | 连接状态（高=已连接） | 可选，已接 |

参数：USART6，9600bps，8N1，RXNE+IDLE 中断，抢占优先级 (1,1)。

### 2.2 PC 侧接入（二选一）

**路径 A：笔记本自带蓝牙（最简单）**

1. 笔记本蓝牙配对 HC-05（配对码默认 `1234` 或 `0000`）
2. Windows 自动创建虚拟 COM 口（"Standard Serial over Bluetooth link"）
3. VOFA+ 打开该 COM 即可（SPP 虚拟串口的波特率设置对实际链路无效，设 9600 对齐无坏处）

**路径 B：USB-TTL + HC-05 转接器（台式机无蓝牙时）**

两个 HC-05 需先用 AT 指令配成一对（转接器侧设为主机，上电自动连车上的从机）：

| USB-TTL (CH340) | HC-05 | 说明 |
|---|---|---|
| **3V3 引脚** | VCC | **从 3V3 引脚取电**（见下方跳线说明） |
| GND | GND | 共地 |
| TXD | RXD | 交叉 |
| RXD | TXD | 交叉 |

⚠️ **黄帽跳线问题**：跳线帽只决定 **VCC 这一个脚** 的输出电压，而且会**把 VCC 针盖死插不了杜邦线**。解决：供电改从独立的 **3V3 引脚** 取（该脚是板上稳压器直出 3.3V，与帽子无关），帽子随便套或摘掉。备选：从排针背面焊点焊线取 VCC；或直接从车上 STM32 的 3.3V 供电（共地即可）。

### 2.3 电压规格

| 形态 | 供电 | 说明 |
|---|---|---|
| HC-05 裸模块 | **3.3V**，绝对 ≤3.6V | 接 5V 会烧 |
| HC-05 带底板成品 | 3.3V ~ 5V（板载 LDO，禁超 7V） | 5V 供电是标准用法 |
| 逻辑电平（两种形态都是） | 3.3V TTL | STM32 直连无需分压 |

### 2.4 波特率全链路对齐

STM32 USART6 = **9600**（代码里 `Bluetooth_Init()` 已设）＝ HC-05 出厂默认 9600 ＝ PC 侧 9600。

## 3. 原理解释

### 3.1 HC-05 透传原理：为什么单片机"看不见"蓝牙

HC-05 是**透传桥**（transparent bridge）：内部自带小单片机 + 蓝牙射频，一头说 UART，一头说蓝牙 SPP 协议。STM32 从头到尾只知道自己接了一个 UART 外设，**对蓝牙无感知**。所以收发代码与普通串口完全同套路：配波特率 → 配引脚复用 → 开中断 → 读写 DR 寄存器。

### 3.2 USART6 接收机制（已有代码，零改动）

```
手机发"kp 45\n" → HC-05收到无线包 → 从TXD按9600bps吐字节到PC7
→ 每来1字节 RXNE中断: 存入 BLERX_BUFF[BLERX_LEN++]
→ 发完停顿 >1字节时间: USART6硬件检测到线路空闲 → IDLE中断 → BLERX_FLAG=1
→ 主循环看到标志 → 解析 → Clear_BLERX_BUFF()
```

相关代码：[bsp_bluetooth.c](HARDWARE/hc-05/bsp_bluetooth.c) 的 `BSP_BLUETOOTH_IRQHandler()`。

### 3.3 为什么蓝牙下"IDLE 分帧"不可靠，要用 `\n`

有线时"你发一串，对面一串"是可靠的，IDLE 可作为帧结束标志。但蓝牙空中链路抖动时，模块可能把一条消息**分几块**吐给 STM32，块间出现间隙；9600 波特率下 1ms 空闲就触发 IDLE → 一条命令被切成两帧。

**对策：按内容分帧**——协议约定每条命令以 `\n` 结尾，解析层只认 `\n`，与 IDLE 何时触发无关。IDLE 只当"有货了"的通知，不当"一帧"的定义。解析层维护一个静态尾巴缓冲，把没见到 `\n` 的半行保留到下一帧拼上（见 §4.2 的 `BLE_Tune_Process`）——否则被 IDLE 切成两块的命令会丢。

### 3.4 MicroLIB 的坑：为什么参数用整数传输

EIDE 配置开着 MicroLIB（eide.yml `use-microLIB: true`）。**MicroLIB 不支持 `sscanf %f`、`strtof`**——用它们解析浮点会静默失败（返回值不对，值解析不出来），这是经典坑。

**方案：整数缩放传输。** 参数在协议里以整数出现，用 `atoi`（MicroLIB 支持）解析，按 scale 除以 10 的幂还原：

| 命令 | 发送值 | scale | 实际写入 |
|---|---|---|---|
| `kp 45` | 45 | 3 | 0.045 |
| `sp_kp 850` | 850 | 2 | 8.5 |
| `disr 62` | 62 | 0 | 62.0 |

### 3.5 调参如何"实时"生效：直接写字段，绝不重新 Init

控制循环（舵机 PD 每雷达帧、电机 PI 每 10ms 中断）**每次都现读** `Servo_pd.kp`、`Speed_pid.kp` 等结构体字段。所以蓝牙解析后直接 `Servo_pd.kp = 0.045f;`，下一拍就用新值。

⚠️ **绝不能调用 `Midline_PD_Init` / `Speed_PID_Init` 来改参数**——它们会把 `err`/`err_l` 清零（`Midline_PD_Init` 前两行）。车在弯里时 D 项突然归零会猛抖一下。

### 3.6 VOFA+ 二进制波形协议原理

- 格式：`N 个 float32（IEEE754，小端） + 帧尾 0x00 0x00 0x80 0x7F`
- 帧尾即 float 正无穷 `0x7F800000` 的小端表示，VOFA+ 靠它**自动识别通道数**
- Cortex-M4 天然小端，用 union 把 float 拆成 4 字节逐字节发送即可，无需转换
- ⚠️ 命名坑：官方文档把此格式叫 **FireWater**；网上大量二手博客把 FireWater/JustFloat 写反。**以软件实测为准**：哪个二进制引擎能自动出波形就用哪个

### 3.7 时序与带宽账

```
主循环: ┌─等DMA_RX_DONE(~78ms/帧)─┬─雷达解析─┬─模式决策─┬─Midline_PD(算舵机)─┬─遥测发送(33ms)─┐
                                  └─────────── 期间穿插 ───────────┘
🎛️ BLE_Tune_Process() 在 while(1) 顶部每圈都跑 → 命令响应 <1ms
电机PI: TIM5 中断独立运行, 10ms 一拍, 与主循环并行
```

- 遥测帧：7 通道 × 4B + 帧尾 4B = **32B ≈ 33ms @9600**；雷达帧周期约 78ms → 带宽安全
- 遥测的 33ms 阻塞发生在**本帧控制算完之后**，不影响当帧舵机输出；雷达 DMA 是硬件行为，不丢数据
- 9600bps ≈ 960 字节/秒，调参命令（短文本）与 33ms/帧遥测合计远低于上限

### 4.2 新建 `HARDWARE/hc-05/ble_tune.c`

```c
/**
 * @file    ble_tune.c
 * @brief   蓝牙实时调参模块 (VOFA+/串口助手 → HC-05 → USART6)
 *
 * 【调参】PC→车: 文本命令 "名字 整数\n" (名字后跟空格或冒号, 如 "kp 45"/"kp:45")，
 *               整数按 scale 缩放为浮点 (避开 MicroLIB 不支持 sscanf %f 的坑，用 atoi 解析)
 * 【发送】车→PC: float32小端 × 7通道 + 帧尾 0x00 00 80 7F
 *               (VOFA+二进制引擎自动识别通道)
 */
#include "ble_tune.h"
#include "bsp_bluetooth.h"
#include "centre_line.h"     /* Servo_pd, BLUE_* */
#include "LEIDA_DATA.h"      /* BLUE_ANGLE_LEFT_RIGHT */
#include "moto.h"            /* Speed_now, Speed_mubiao */
#include "stdio.h"
#include "string.h"

/* ======================== 🎛️【调参】参数表 ======================== */
typedef struct {
    const char *name;   /* 命令名 */
    float      *ptr;    /* 变量指针 */
    int16_t     min_i;  /* 整数下限(按scale) */
    int16_t     max_i;  /* 整数上限(按scale) */
    uint8_t     scale;  /* 发送值/10^scale = 实际值; 3 表示发45 → 0.045 */
} Param_t;

static const Param_t param_tab[] = {
    /* 舵机PD: 千分位 */
    {"kp",    &Servo_pd.kp,           0, 1000, 3},   /* 直道PD */
    {"kp2",   &Servo_pd.kp_2,         0, 1000, 3},   /* 大转弯PD */
    {"kp3",   &Servo_pd.kp_3,         0, 1000, 3},   /* 小转弯PD */
    {"kd",    &Servo_pd.kd,           0, 1000, 3},
    {"kd2",   &Servo_pd.kd_2,         0, 1000, 3},
    {"kd3",   &Servo_pd.kd_3,         0, 1000, 3},
    /* 电机PI: kp×100, ki×1000 */
    {"sp_kp", &Speed_pid.kp,          0, 5000, 2},   /* 发850 → 8.5 */
    {"sp_ki", &Speed_pid.ki,          0, 5000, 3},   /* 发505 → 0.505 */
    {"spd",   &Speed_mubiao,          0,   50, 0},   /* 目标速度 */
    /* 几何补偿参数: 1:1 */
    {"disr",  &BLUE_DIS_RIGHT,        0,  200, 0},
    {"disl",  &BLUE_DIS_LEFT,         0,  200, 0},
    {"yr",    &BLUE_Y_RIGHT,          0, 2000, 0},
    {"yl",    &BLUE_Y_LEFT,           0, 2000, 0},
    {"ystra", &BLUE_Y_STRA,           0, 2000, 0},
    {"angle", &BLUE_ANGLE_LEFT_RIGHT, 0,  180, 0},
};
#define PARAM_NUM (sizeof(param_tab) / sizeof(param_tab[0]))

/* ======================== 📤【发送】遥测底层 ======================== */
typedef union {
    float   f;
    uint8_t b[4];
} FloatByte_t;

static void Tele_SendFloat(float v)
{
    FloatByte_t u;
    u.f = v;
    BLE_Send_Bit(u.b[0]);   /* 小端低字节在前 (Cortex-M4 天然小端) */
    BLE_Send_Bit(u.b[1]);
    BLE_Send_Bit(u.b[2]);
    BLE_Send_Bit(u.b[3]);
}

static void Tele_SendTail(void)
{
    BLE_Send_Bit(0x00);
    BLE_Send_Bit(0x00);
    BLE_Send_Bit(0x80);
    BLE_Send_Bit(0x7F);
}

/* 📤 每雷达帧调用一次: 7通道 = 误差/舵机PWM/kp/kd/pid模式/当前速度/目标速度
 * 帧长 7×4+4=32字节 ≈ 33ms @9600; 雷达帧周期约78ms, 带宽安全 */
void BLE_Tune_Telemetry(float err, float servo_pwm, uint16_t pid_mode)
{
    Bluetooth_Mode();
    if (Get_Bluetooth_ConnectFlag() == 0) return; /* 未连接不发(也省下阻塞时间)
                                                      注: 必须用头文件已声明的getter,
                                                      Bluetooth_ConnectFlag变量本身未导出 */

    Tele_SendFloat(err);
    Tele_SendFloat(servo_pwm);
    Tele_SendFloat(Servo_pd.kp);
    Tele_SendFloat(Servo_pd.kd);
    Tele_SendFloat((float)pid_mode);
    Tele_SendFloat(Speed_now);
    Tele_SendFloat(Speed_mubiao);
    Tele_SendTail();
}

/* ======================== 📤【发送】get命令回显 ======================== */
static void Tune_SendAll(void)
{
    static const int mul[4] = {1, 10, 100, 1000};
    char line[40];
    uint8_t i;

    for (i = 0; i < PARAM_NUM; i++) {
        int iv = (int)(*param_tab[i].ptr * mul[param_tab[i].scale] + 0.5f);
        sprintf(line, "%s=%d\r\n", param_tab[i].name, iv);
        Send_Bluetooth_Data(line);
    }
}

/* ======================== 🎛️【调参】单行命令解析 ======================== */
static void Tune_ApplyOne(char *line)
{
    static const int mul[4] = {1, 10, 100, 1000};
    char *sp;
    char *sc;
    char *val;
    char ack[40];
    int iv;
    uint8_t i;

    if (strcmp(line, "get") == 0) { Tune_SendAll(); return; }  /* 精确匹配, 防"getxx"误触发 */

    sp = strchr(line, ' ');            /* 分隔符: 空格或冒号都认, 如 "kp 45" / "kp:45" */
    sc = strchr(line, ':');
    if ((sp == NULL) || ((sc != NULL) && (sc < sp))) sp = sc;  /* 取更靠前的那个作切点 */
    if (sp == NULL) { Send_Bluetooth_Data("ERR fmt\r\n"); return; }
    *sp = '\0';                     /* 切断 → line="kp", sp+1="45" */
    val = sp + 1;                   /* 兼容VOFA+滑块发"kp :493"这类格式 */
    while (*val && !((*val >= '0' && *val <= '9') || *val == '-')) val++; /* 跳过":"等非数字前缀 */
    if (*val == '\0') { Send_Bluetooth_Data("ERR fmt\r\n"); return; } /* 全是非数字, 拒绝(防止误写0) */
    iv = atoi(val);                 /* iv = 45 (整数, 避开 MicroLIB 不支持 %f 的坑) */

    for (i = 0; i < PARAM_NUM; i++) {
        if (strcmp(line, param_tab[i].name) != 0) continue;

        if ((iv < param_tab[i].min_i) || (iv > param_tab[i].max_i)) {
            Send_Bluetooth_Data("ERR range\r\n");    /* 钳位拒绝 */
            return;
        }
        /* 直接赋值字段, 下一帧控制循环现读新值即生效。
         * 绝不调用 Midline_PD_Init/Speed_PID_Init 改参数 —— 它们会清零误差状态 */
        *param_tab[i].ptr = (float)iv / mul[param_tab[i].scale];
        sprintf(ack, "OK %s=%d\r\n", line, iv);
        Send_Bluetooth_Data(ack);
        return;
    }
    Send_Bluetooth_Data("ERR name\r\n");
}

/* ======================== 🎛️【调参】主入口 ======================== */
void BLE_Tune_Process(void)
{
    static char tail[BLERX_LEN_MAX];        /* 跨IDLE保留的半行尾巴:
                                               蓝牙空中分块交货, 一条命令可能被
                                               IDLE切成两帧, 没见到\n的半行不能丢 */
    static uint8_t tail_len = 0;
    char *start, *end;
    uint8_t len, copy_n;

    if (BLERX_FLAG == 0) return;

    /* 关中断整体拷出: 防止解析期间 RX 中断又往里写。
     * Clear 也放进临界区, 避免开中断后新到的字节被误清 */
    __disable_irq();
    len    = BLERX_LEN;
    copy_n = (len > BLERX_LEN_MAX - 1 - tail_len) ? (uint8_t)(BLERX_LEN_MAX - 1 - tail_len) : len;
    memcpy(tail + tail_len, BLERX_BUFF, copy_n);
    tail_len += copy_n;
    Clear_BLERX_BUFF();
    __enable_irq();

    tail[tail_len] = '\0';

    /* 按 \n 分行: 支持一次发多条命令 */
    start = tail;
    while ((end = strchr(start, '\n')) != NULL) {
        *end = '\0';
        if (end != start) Tune_ApplyOne(start);/*此时start是第一个命令数组的地址*/
        start = end + 1; /*指向下一个*/
    }
    /* 没见到\n的半行留到下一帧继续拼 (与IDLE何时切帧无关) */
    tail_len = (uint8_t)strlen(start);
    memmove(tail, start, tail_len + 1);
}
```

### 4.4 bsp_bluetooth.h 补一行声明（必须，否则编译不过）

`BLE_Send_Bit` 在 [bsp_bluetooth.c](HARDWARE/hc-05/bsp_bluetooth.c) 里有定义（轮询 TXE 发 USART6），但头文件漏了声明：Keil AC5(C90) 下是隐式声明警告，EIDE/armclang(C99+) 直接报错。`BLE_send_String` 以 `\0` 结束，不能替代它发二进制 float（float 字节里会出现 0x00）。

在 `bsp_bluetooth.h` 声明区补一行：

```c
void BLE_Send_Bit(unsigned char ch);
```

> 因此"bsp_bluetooth 完全零改动"不成立：需要上述**一行**声明。接收侧（RXNE/IDLE 中断）依然零改动。

## 5. VOFA+ 使用方法

### 5.1 接入

1. 配好对（或接好转接器）→ 设备管理器确认 COM 号
2. VOFA+ 新建连接：串口 → COM 号 → 9600 → 数据引擎先选 **RawData**
3. 发送面板发 `kp 35` → 应回显 `OK kp=35`，调参链路走通
4. 切**二进制引擎**（带帧尾能自动识别通道的那个；FireWater/JustFloat 名字以实测为准）→ 拖波形组件 → 7 通道波形出来，发送链路走通

### 5.2 🎛️ 调参命令表

| 命令 | 实际写入 | scale | 示例 |
|---|---|---|---|
| `kp` / `kp2` / `kp3` | Servo_pd.kp / kp_2 / kp_3 | ×1000 | `kp 35` → 0.035 |
| `kd` / `kd2` / `kd3` | Servo_pd.kd / kd_2 / kd_3 | ×1000 | `kd2 22` → 0.022 |
| `sp_kp` | Speed_pid.kp | ×100 | `sp_kp 850` → 8.5 |
| `sp_ki` | Speed_pid.ki | ×1000 | `sp_ki 505` → 0.505 |
| `spd` | Speed_mubiao | ×1 | `spd 17` |
| `disr` / `disl` | BLUE_DIS_RIGHT / LEFT | ×1 | `disr 62` |
| `yr` / `yl` / `ystra` | BLUE_Y_RIGHT / LEFT / STRA | ×1 | `yr 1200` |
| `angle` | BLUE_ANGLE_LEFT_RIGHT | ×1 | `angle 90` |
| `get` | 📤 回发全部参数表 | — | — |

回显：`OK 名字=值`（成功）/ `ERR fmt`（格式错）/ `ERR range`（超范围被钳位拒绝）/ `ERR name`（无此参数）。

**VOFA+ 滑块适配**：解析器同时认**空格和冒号**作分隔符（取更靠前的那个）——VOFA+ 滑块默认发的 `kp:45` 可以直接用，**无需改发送格式**；手敲 `kp 45` 也照常。滑块范围记得按"发送值"配（kp 建议 0~100，对应 0~0.100）。⚠️ 教训：早期版本 `atoi(":493")` 会返回 0，而 0 在允许范围内不报错，曾把参数静默清零——现已由"跳过非数字前缀 + 全非数字拒绝"双重防护。

## 7. 注意事项

1. 🎛️ **分帧按 `\n`**：蓝牙 IDLE 不可靠（空中分块交货），解析层只认换行
2. 🎛️ **钳位**：跑车时手滑发 `kp 5000` 会被 `ERR range` 拒绝；超范围一律不写
3. 📤 **遥测带宽**：32B/帧 ≈ 33ms，勿再加通道；想看高频数据走 USART1 有线（115200）
4. 🔧 调试前把 main.c 的 `HW_TEST_MOTOR_SERVO` 设 0（测试模式在抢舵机）
5. 🔧 既有隐患（与方案无关，仅提醒）：main.c 中 `valid_couter <= 20` 分支里的 `break` 会跳出 `while(1)` 整个停摆，蓝牙也失去响应；建议日后改成只跳过当帧
6. 🔧 既有隐患（同上）：main.c 首帧若走直道且中线斜率 `|k|<=0.1`，`servo_pwm` 未赋值就被 `Servo_ChangePwm` 使用；遥测也会带出一次未初始化值，无害但值得知道
7. 🔧 调参原则：**直道画龙调 kp/kd；大弯过冲调 kp_2/kd_2；小弯贴边调 kp_3/kd_3；起步顿挫降 sp_ki；速度上不去加 sp_ki**。若舵机 PWM 常顶到 1360/1800 说明已饱和，加大 kp 无意义
