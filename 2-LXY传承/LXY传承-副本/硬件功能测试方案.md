## 0. 目标一句话

写 **3 个互相独立、逻辑尽量简单**的硬件测试程序，放在新建的 `test/` 文件夹里，主程序用一个宏选择跑哪个：

| 测试 | 文件 | 验证什么 |
|---|---|---|
| ① 舵机测试 | `test/test_servo.c` | 舵机中位、左右行程、方向（数值大=左） |
| ② 电机测试 | `test/test_motor.c` | 电机正/反转、各档占空比、编码器测速、方向/相序 |
| ③ 蓝牙测试 | `test/test_bluetooth.c` | 蓝牙连接、实时遥测、手机发命令实时改舵机/电机（=调参链路打通） |

## 2. 关键设计点：为什么要关掉 TIM5 中断（重要）

### 2.1 冲突是怎么发生的

现有代码里，TIM5 定时器每 **10ms** 中断一次（[timer.c:84](HARDWARE/LEIDA_TIMER/timer.c#L84)），中断里干两件事：

```
TIM5 中断 (10ms 一次)  ──→  Get_Encoder() 读编码器算速度
                        └─→  PID_realize() 算新占空比
                        └─→  Moto_Speed(新占空比)   ← 直接写电机 PWM！
```

如果测试程序在主循环里调 `Moto_Speed(50)`（要 50% 占空比），**10ms 后 TIM5 中断就会把它覆盖掉**，电机根本不听测试代码的话。这就是旧测试 `HW_TEST_MOTOR_SERVO` 电机部分实际不生效的原因。

### 2.2 解决办法（实际实现：在 main.c 初始化时统一关）

不在测试函数里关，而是在 main.c 的 `TIM5_Int_Init()` 之后统一关（`HW_TEST_SELECT != 0` 时）：

```c
#if HW_TEST_SELECT != 0
    TIM_ITConfig(TIM5, TIM_IT_Update, DISABLE);   /* 测试模式统一关掉速度环, 电机PWM归测试代码独占 */
#endif
```

- **三个测试全部关**：舵机测试本来不需要关（TIM5 不碰舵机），但统一关掉后电机占空比恒为 0，舵机测试时车也能放地上，且三个测试行为一致、好排查。
- 关了之后 TIM5 不再读编码器、不再写 PWM → 测试代码想给多少占空比就是多少。
- **副作用**：没人算 `Speed_now` 了 → 测试代码自己读 TIM4 计数器算速度（见 §4.2）。

### 2.3 编码器反向计数的坑（补码）

反转时编码器 CNT 会**往下数**：`0, 65535, 65534, ...`（uint16_t 溢出回绕）。直接当无符号数用会算出一个巨大的"速度"。

处理办法：先转成有符号数再算：

```c
int16_t scnt = (int16_t)TIM_GetCounter(TIM4);   /* 补码还原: 65535→-1, 65534→-2 */
TIM_SetCounter(TIM4, 0);                        /* 清零, 下次重新数 */
float speed = scnt * 100.0f / (4.0f * 11.0f * 6.25f);   /* 与 moto.c 同一公式 */
```

## 3. 测试① 舵机测试（test_servo.c）

### 3.1 逻辑（最简）

```
上电 → 回中位停 2 秒（肉眼确认回正）
     → 循环: 从中位 1565 出发先往小走(往右), 每 500ms 步进 20
             到 1360/1800 端点掉头, 往复循环
            每走一步串口打印: Servo PWM: 1560 <- 右打满 / <- 左打满 / <- 中位
```

- 只用两个现有函数：`Servo_ChangePwm()` + `delay_ms()`，全部在 while(1) 里。
- 步进 20、间隔 500ms → 单程 (1800−1360)/20 × 0.5s ≈ 11 秒，肉眼看得清。
- **include 顺序**：文件里 `#include "stm32f4xx.h"` 必须写在 `#include "Servo.h"` 之前——Servo.h 用了 `uint16_t` 但自己不 include 任何头文件，顺序反了会编译报 `unknown type name 'uint16_t'`。

### 3.2 参数宏

三个限幅宏在 `test/test.h`（换谢露车只改这里）：

```c
#define TEST_SERVO_MIN  1360   /* LXY车: 右打满     谢露车改 1170 */
#define TEST_SERVO_MAX  1800   /* LXY车: 左打满     谢露车改 1720 */
#define TEST_SERVO_MID  1565   /* LXY车: 中位       谢露车改 1445 */
```

步进与间隔在 `test_servo.c` 文件顶部：`TEST_SERVO_STEP 20`、`TEST_SERVO_DELAY_MS 500`。

### 3.3 预期现象对照表（串口 + 肉眼）

| 观察点 | 预期 | 异常说明 |
|---|---|---|
| 上电后舵机 | 先到中位停 2s，再开始扫 | 先乱摆 = 中位不对 |
| PWM 变大（往 1800） | 轮子往**左**打 | 往右打 = 方向反（本车舵机装反） |
| 1360 时 | 右打满但**不憋劲**（没有嗡嗡声） | 憋劲 = 限幅超了机械行程，改小 MIN |
| 1800 时 | 左打满不憋劲 | 同上，改小 MAX |
| 1565 时 | 轮子基本**正前方** | 明显偏 = 中位要重测（谢露车先试 1445） |

## 4. 测试② 电机测试（test_motor.c）

### 4.1 逻辑（最简）

```
TIM5 已在 main.c 初始化时关闭（§2.2），直接开始
→ 【正转】PB10 输出高电平, 占空比 20%→40%→60%→80%, 每档 1.5 秒
    每档期间每 100ms 采样编码器算一次速度并打印
→ 【停】  占空比 0, 停 1 秒
→ 【反转】PB10 输出低电平, 同样 20%→40%→60%→80% 扫一遍
→ 【停】  占空比 0, 结束（或从头循环）
```

- 电机 PWM：`Moto_Speed(duty)`；方向：`GPIO_SetBits(GPIOB, GPIO_Pin_10)`（高=正转）/ `GPIO_ResetBits(...)`（低=反转）——因为 moto.c 里没有公开的换向函数，测试代码直接操作 PB10，两行 GPIO 调用 + 注释。
- 速度采样用 §2.3 的办法，100ms 一次（100ms 内计数器不会溢出：轮子 1 圈=44 个计数，100ms 内不可能转 1489 圈）。

### 4.2 速度打印（MicroLIB 不支持 %f！）

速度是小数（0~27），但 MicroLIB 的 printf 打不了 `%f` → 和蓝牙调参方案一样用**整数放大 10 倍**打印：

```c
int speed_x10 = (int)(speed * 10);       /* 12.5 → 125, 人看的时候自己除以10 */
printf("Moto PWM:%u%% dir:%c speed:%d.%d\r\n", duty, dir, speed_x10/10, abs(speed_x10%10));
```

### 4.3 预期现象对照表

| 观察点 | 预期 | 异常说明 |
|---|---|---|
| 正转阶段 | 轮子正转，speed 为**正**，占空比↑速度↑ | 轮子倒转 = 电机线接反（改 PB10 极性） |
| 反转阶段 | 轮子反转，speed 为**负** | speed 仍为正 = 编码器 A/B 相接反 |
| 20% 占空比 | 轮子能转 | 不转 = 占空比太小（记下最小能转的值） |
| 手拨轮子（占空比 0 时） | 往正转方向拨 speed>0 | 相反 = 相序反 |
| ⚠️ 安全 | **测试前把车架起来！** | 80% 占空比下轮子转速很高，落地上电会窜出去 |

## 5. 测试③ 蓝牙测试（test_bluetooth.c）

### 5.1 逻辑（最简）

```
TIM5 已在 main.c 初始化时关闭（§2.2），s/m 命令给的 PWM 不会被速度环覆盖
→ 串口 + 蓝牙各发一行提示"等待蓝牙连接"
→ 循环:
   (1) Bluetooth_Mode() 刷新连接状态; 状态变化时打印 connected/disconnected
   (2) 已连接: 每 500ms 发一条状态行(蓝牙+调试串口各一份):
       s:1565 m:30 v:125        ← 舵机PWM / 电机占空比 / 速度×10
       (速度: 主循环每 10ms tick 累加一次 TIM4 计数, 500ms 汇总算一次, 用 §2.3 的补码办法)
   (3) BLERX_FLAG==1(收到一帧命令):
       '?'        → 立即回发一条状态行
       's'+数字   → 范围检查[TEST_SERVO_MIN, MAX] → Servo_ChangePwm → 回 "servo=1565 OK"
       'm'+数字   → 范围检查[0,100] → Moto_Speed → 回 "moto=30% OK"
       其他       → 回 "ERR fmt, use: s1500 / m50 / ?"
       Clear_BLERX_BUFF() 清标志等下一帧
```

### 5.2 命令解析（呼应 atoi 的坑）

手机/VOFA+ 发来的可能带分隔符（`s1500`、`s:1500`、`s 1500`），也可能带 `\r\n`。解析规则只有一条：

> **跳过第一个数字前的所有非数字字符，再 atoi；一个数字都没有 → 回 ERR fmt。**

```c
/* 例: "s:1500" → p 先走到 '1', atoi("1500")=1500; ":???" → 走到'\0' → ERR */
char *p = (char *)BLERX_BUFF;
while (*p && (*p < '0' || *p > '9')) p++;   /* 跳过非数字前缀 */
if (*p == '\0') { 回 "ERR fmt"; }            /* 全非数字 → 防 atoi 返回 0 误设 */
else { int val = atoi(p); ... }
```

这样 `atoi(":493")=0` 的坑被"跳过前缀"顺带解决：`s:0` 依然能正确设 0（值 0 是合法输入，只看 val 是否在范围内）。

### 5.3 发送用 sprintf（整数格式）

```c
char buf[64];
sprintf(buf, "s:%u m:%u v:%d\r\n", servo_pwm, moto_pwm, speed_x10);
BLE_send_String((unsigned char *)buf);   /* 发蓝牙 */
printf("%s", buf);                        /* 同时打印到调试串口 */
```

- MicroLIB 的 sprintf **支持整数格式**（%u/%d/%s/%c），只是不支持 %f → 所有小数按 ×10 整数发。
- 未连接时不发（`Get_Bluetooth_ConnectFlag()==0` 直接跳过），和蓝牙调参方案一致。

### 5.4 预期现象对照表

| 步骤 | 预期 | 异常说明 |
|---|---|---|
| 手机连上 HC-05 | 串口打印 connected，蓝牙收到第一行 `s:... m:...` | 没反应 = 查 STATE 脚 PC2 / 波特率 9600 |
| 手机发 `?` | 立刻回一行状态 | 回不来 = 接收路径断（查 USART6 RX） |
| 手机发 `s1600` | 舵机立刻左转，回 "servo=1600 OK" | 没动 = 命令解析没进（看调试串口回显） |
| 手机发 `m40` | 轮子转起来，遥测里 v 变大 | v 不变 = 编码器采样没跑 |
| 手机发 `m0` | 轮子停，v 回落 | ⚠️ 测试时车架起来 |
| 发 `hello` | 回 "ERR fmt" | 没回 = 分帧有问题（看调试串口） |
| 断开蓝牙 | 打印 disconnected，发送停止 | — |

> 测试③跑通 = 蓝牙调参方案的「收发 + 改参数 + 看实时数据」链路全部验证完毕，之后正式调参代码（ble_tune.c）只是把参数表换成 PID 系数。
