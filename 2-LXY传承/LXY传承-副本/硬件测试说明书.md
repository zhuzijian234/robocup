# 硬件测试说明书

> 适用工程: `LXY传承-副本`（STM32F407VET6 @168MHz，标准外设库）
> 配套文档: [硬件功能测试方案.md](硬件功能测试方案.md)（测试逻辑与预期现象表）、[蓝牙调参说明书.md](蓝牙调参说明书.md)、[蓝牙实时调参方案.md](蓝牙实时调参方案.md)
> 本说明书的定位：**怎么操作**（改哪个宏、按什么顺序、看什么现象、坏了查哪里）。

---

## 1. 测试总览

三个硬件测试代码在 [test/](test/) 文件夹，由 [USER/main.c](USER/main.c) 里的一个宏选择运行：

```c
#define HW_TEST_SELECT 0   /* 0=正常循线, 1=舵机测试, 2=电机测试, 3=蓝牙调参测试 */
```

| 值 | 运行内容 | 文件 | 验证的硬件 |
|---|---|---|---|
| 0 | 正常循线（默认） | — | 全系统 |
| 1 | 测试① 舵机往复扫描 | test/test_servo.c | 舵机、TIM3 CH1 (PA6) |
| 2 | 测试② 电机正反转+测速 | test/test_motor.c | 电机驱动 TIM2 CH4 (PB11)、方向脚 PB10、编码器 TIM4 (PD12/PD13) |
| 3 | 测试③ 蓝牙调参链路 | test/test_bluetooth.c | HC-05、USART6 (PC6/PC7)、STATE 脚 PC2 |

**使用流程**：改宏 → 编译 → 烧录 → 打开调试串口 USART1 @115200 看打印 → 对照现象表核对。

> 测试模式下 main.c 会自动关闭 TIM5 速度环中断、电机上电占空比为 0，所以**舵机测试（①）车可以放地上**；电机测试（②）和蓝牙测试（③，含 `m` 命令）**必须把车架起来**。

---

## 2. 测试前准备

1. **供电**：锂电池满电（电压不足舵机会抖、电机会顿）。
2. **架车**（测试②③必须）：拿两本书/盒子把车架到轮子悬空。**80% 占空比下轮子转速很高，落地会窜出去**。
3. **调试串口**：USB-TTL 接 USART1（PA9=TX, PA10=RX）@115200，串口助手打开。所有测试都有实时打印。
4. **蓝牙**（测试③）：手机装好蓝牙串口 APP（或用 VOFA+），先不连接。
5. 核对车上接线无松动：舵机 3 线（信号 PA6）、电机 2 线（PB11 PWM + PB10 方向）、编码器 4 线（PD12/PD13 + 电源地）、HC-05 5 线（VCC/GND/PC6/PC7/PC2）。

---

## 3. 测试① 舵机往复扫描（HW_TEST_SELECT = 1）

### 3.1 步骤

1. 改宏为 1，编译烧录，车放地上。
2. 打开 USART1 串口助手。
3. 观察：上电后舵机先**回中位停 2 秒**，然后从 1565 开始**往右（PWM 变小）**扫，每 500ms 走一步（步进 20），到 1360 掉头扫到 1800，再掉头……往复不停。

### 3.2 预期现象

| 观察点 | 预期 | 异常说明 |
|---|---|---|
| 上电后舵机 | 先回中位停 2s，再开始扫 | 先乱摆 = 中位不对 |
| PWM 变大（往 1800） | 轮子往**左**打（本车约定: 数值大=左） | 往右打 = 舵机装反了 |
| PWM=1360 | 右打满但**不憋劲**（没有持续嗡嗡声） | 憋劲 = 超机械行程，把 test.h 的 TEST_SERVO_MIN 改大 |
| PWM=1800 | 左打满不憋劲 | 同上，把 TEST_SERVO_MAX 改小 |
| PWM=1565 | 轮子基本正前方 | 明显偏 = 中位要重测（test.h 的 TEST_SERVO_MID） |
| 串口打印 | 每步一行 `Servo PWM: xxx`，到端点/中位带 `<- 右打满` 等标记 | 无打印 = USART1 没接好 |

### 3.3 常见故障排查

| 现象 | 排查 |
|---|---|
| 舵机完全不动 | ①舵机供电（5V 那根线） ②信号线是否 PA6 ③测试宏是否改对并重新编译烧录 |
| 舵机狂抖/抽风 | 供电不足（换个满电电池）或信号线接触不良 |
| 只扫半边 | test.h 里 MIN/MAX 写错（换谢露车时注意: MIN=1170, MAX=1720, MID=1445） |

> 测试①跑通了，说明舵机链路（TIM3 50Hz PWM → PA6 → 舵机）完好，可进入调参阶段。

---

## 4. 测试② 电机正反转 + 测速（HW_TEST_SELECT = 2）

### 4.1 步骤

1. **先把车架起来！**
2. 改宏为 2，编译烧录。
3. 观察：**正转**（PB10 高）占空比 20%→40%→60%→80%，每档 1.5 秒、每 100ms 打一行速度 → **停 1 秒** → **反转**（PB10 低）同样四档 → 停 1 秒 → 循环。

### 4.2 串口读数方法

速度是小数（0~27），MicroLIB 打不了 `%f`，所以**放大 10 倍**打印成 `int.小数` 格式：

```
Moto PWM:20% dir:+ speed:3.2     ← 实际速度 3.2, 每100ms采样一次
Moto PWM:80% dir:+ speed:13.5
Moto PWM:20% dir:- speed:-3.1    ← 反转时速度带负号
```

### 4.3 预期现象

| 观察点 | 预期 | 异常说明 |
|---|---|---|
| 正转阶段 | 轮子正转，speed 为**正**，占空比↑速度↑ | 轮子倒转 = 电机线接反（把 PB10 极性逻辑反过来） |
| 反转阶段 | 轮子反转，speed 为**负** | speed 仍为正 = 编码器 A/B 相接反 |
| 20% 占空比 | 轮子能转 | 不转 = 启动占空比不够（记下最小能转的值，速度环最低输出参考它） |
| 占空比 0（停的阶段） | 用手往正转方向拨轮子，speed>0 | 相反 = 编码器相序反 |
| 速度数值 | 随占空比单调上升、正反转绝对值接近 | 明显不对称 = 电机/驱动单边问题 |

### 4.4 常见故障排查

| 现象 | 排查 |
|---|---|
| 轮子不转但打印正常 | 电机驱动板供电（电机电源那路，不是芯片 3.3V） |
| 速度恒 0 | 编码器供电/信号线（PD12/PD13），或 TIM4 未初始化（检查 Encoder_Init） |
| 速度忽大忽小 | 编码器接触不良；100ms 窗口内溢出不可能（1 圈=44 计数），先排除接线 |

> 测试②跑通 = 电机驱动、方向脚、编码器计数三条链路全部完好。正反转方向记下来，和 §4.3 的表对不上就先修硬件再调参。

## 5. 测试③ 蓝牙调参链路（HW_TEST_SELECT = 3）

### 5.1 步骤

1. **架车**（`m` 命令会转轮子）。
2. 改宏为 3，编译烧录。
3. 打开 USART1 串口助手，看到 `===== 测试③ 蓝牙测试 =====` 和"等待蓝牙连接"提示。
4. 手机配对 HC-05：蓝牙名一般 `HC-05`，配对码 `1234`（不行试 `0000`）。
5. 配对上后：车上 HC-05 的 **STATE 灯**（快闪→慢闪/常亮变化）确认连接；USART1 打印 `蓝牙已连接!`；手机收到第一行状态 `s:1565 m:0 v:0`。
6. 手机蓝牙串口 APP 发送命令（每条命令**以换行结尾**，APP 里一般勾"发送新行"）：

| 命令 | 预期 |
|---|---|
| `?` | 立刻回一行 `s:1565 m:0 v:0`（当前舵机PWM/电机占空比/速度×10） |
| `s1600` | 舵机立刻往左打，回 `servo=1600 OK` |
| `s1360` | 舵机往右打满，回 `servo=1360 OK` |
| `m50` | 轮子转起来（已架车），遥测里 v 变大，回 `moto=50% OK` |
| `m0` | 轮子停，回 `moto=0% OK` |
| `hello` | 回 `ERR fmt, use: s1500 / m50 / ?` |

7. **双路核对**：所有收发在手机 APP 和 USART1 串口助手（printf 回显）上各出现一份——两边一致说明蓝牙↔USART6 双向链路都通。
8. 断开蓝牙：USART1 打印 disconnected，遥测停止。

### 5.2 PC 接入路径（二选一）

- **路径 A 笔记本**：系统蓝牙配对 HC-05 → Windows 自动出虚拟 COM 口 → VOFA+/APP 打开该 COM。
- **路径 B 台式机无蓝牙**：USB-TTL(CH340)+另一个 HC-05 转接器，两模块先 AT 指令配成一对（转接器侧为主机）。⚠️ **转接器 HC-05 的 VCC 从 CH340 的 3V3 引脚取电**——黄色跳线帽会盖死 VCC 针插不了杜邦线，帽子摘掉不影响 3V3 引脚输出。

### 5.3 常见故障排查

| 现象 | 排查 |
|---|---|
| 搜不到 HC-05 | 模块供电（3.3V）；HC-05 上电灯快闪才是未连接状态 |
| 连上但无打印 connected | STATE 脚 PC2 没接或接触不良（连接检测只靠这一根线） |
| 手机收不到状态行 | 波特率不是 9600；APP 没打开接收显示 |
| 发命令无回显 | APP 没勾"发送新行"（模块按行解析）；或 APP 发送编码选错 |
| 回显乱码 | 波特率：全链路必须 9600（HC-05 出厂默认，改过 AT 的要改回来） |

> 测试③跑通 = 蓝牙"收发 + 改参数 + 实时看数据"链路全部打通。之后 [蓝牙调参说明书.md](蓝牙调参说明书.md) 的正式调参（循线模式）就是在这条链路上工作。

## 6. 安全注意事项

1. **HC-05 裸模块只能接 3.3V**，接 5V 必烧；带底板成品可用 5V（板载 LDO）。
2. **断电再接线**，杜邦线松脱短路可能烧稳压。
3. 测试②③、以及正式调参中发过 `m` 命令后，**车必须架起或按住**；`m0` 停轮。
4. 烧录时若舵机/电机乱动属正常（上电瞬间），先架车再上电最稳。
5. 测完记得把 `HW_TEST_SELECT` 改回 **0** 并重新编译烧录——测试宏留在 1/2/3 车是不会循线的。
