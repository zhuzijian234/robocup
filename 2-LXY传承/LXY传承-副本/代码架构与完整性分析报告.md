### 3.1 USER/ — 用户应用层

#### [USER/main.c](USER/main.c) — ⭐ 主程序

**功能**：整个系统的入口和主控制循环。

**初始化顺序**：
1. `NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2)` — 中断优先级分组：2位抢占+2位子优先级
2. `delay_init(84)` — 延时函数初始化（SysTick, 84MHz/8=10.5MHz）
3. `PWM_Init_leida()` — 雷达电机 PWM 初始化（TIM9 CH2, PE6）
4. `Bluetooth_Init()` — 蓝牙初始化（USART3, 9600bps）
5. `PWM_SetCompare_leida(97)` — 设置雷达电机初始占空比
6. `uart6_init(230400)` — 雷达串口初始化（USART6, 230400bps）
7. `DMA_Initializes()` — DMA2 Stream1 初始化（雷达数据接收）
8. `Servo_Init(84, 20000, SERVO_PWM_MID/10.0f)` — 舵机初始化（50Hz, 中位见centre_line.h, LXY~1565）
9. `Midline_PD_Init()` — 舵机 PID 参数初始化（第一次，后续覆盖）
10. `Speed_PID_Init()` — 速度 PID 参数初始化
11. `Moto_Init(42, 100, 90)` — 电机初始化（约20kHz, 初始90%占空比）
12. `Encoder_Init()` — 编码器初始化（TIM4 正交编码）
13. `TIM5_Int_Init(99, 8399)` — 速度控制定时器（10ms周期）

**主循环流程**（每帧雷达数据）：
```
DMA_RX_DONE == 1
  ├── [测试模式] 舵机往复扫描 + 电机占空比往复
  └── [正常模式]
       ├── HANDLE1: 解析雷达原始字节 -> 极坐标
       ├── HANDLE3_2: 筛选有效点 (distance >= 100mm)
       ├── LEIDA_Distance: 计算跑道宽度
       ├── HANDLE6/7: 提取左右边界点
       ├── HANDLE5: 前方路径扫描 (70°-110°)
       ├── Midline_fit: 前方路径直线拟合
       ├── HANDLE8/9: 检测左右边界突变点 (弯道入口)
       └── 决策分支:
            ├── 右断点存在 -> 右转 (flag=3/8/1)
            ├── 左断点存在 -> 左转 (flag=4/9/2)
            └── 无断点     -> 直道 (flag=0/5/7)
```

**关键全局变量**：
- `paodao_distance` — 跑道宽度，600-900mm间更新，带异常过滤
- `RIGHT_duandian` / `LEFT_duandian` — 左右边界断点y坐标
- `state_left_cnt` / `state_right_cnt` — 强制转弯计数（连续大转后补帧）
- `duandian_DIStance` — 断点有效距离阈值（默认550mm）

**控制模式决策逻辑**：

| 条件 | pid_select | 模式 | 偏差来源 |
|------|-----------|------|---------|
| 右断点 + 前斜率<0.35 | 3 | 大右转 | 前方拟合Δy/k |
| 右断点 + 0.35≤前斜率<0.7 + S弯 | 8 | 中右转 | 前方拟合Δy/k |
| 右断点 + 前斜率≥0.7 | 1 | 小右转 | 左边界投影偏差 |
| 左断点 + 前斜率<0.35 | 4 | 大左转 | 前方拟合Δy/k |
| 左断点 + 0.35≤前斜率<0.7 + S弯 | 9 | 中左转 | 前方拟合Δy/k |
| 左断点 + 前斜率≥0.7 | 2 | 小左转 | 右边界投影偏差 |
| 无断点 + 中线垂直 | 5 | 垂线直道 | 中线x偏移-50 |
| 无断点 + 斜率≤0.1 | — | 保持舵机 | 不更新 |
| 无断点 + 中线点<8 | 7 | 均值控制B | 中线x均值 |
| 无断点 + 其他 | 0 | 普通中线 | 中线末点x偏移-50 |

#### [USER/system_stm32f4xx.c](USER/system_stm32f4xx.c) — 系统时钟配置

**功能**：上电复位后的系统时钟初始化。

**关键函数**：
- `SystemInit()` — 在 `startup_stm32f40_41xxx.s` 进入 main 前调用
  1. 使能 FPU（浮点运算单元）
  2. 复位 RCC 时钟配置到默认状态
  3. 调用 `SetSysClock()` 配置系统时钟
  4. 设置中断向量表偏移地址（FLASH 基址）

- `SetSysClock()` — 配置系统时钟为 168MHz
  - 时钟源：HSE (25MHz 外部晶振) -> PLL
  - PLL_M = 8, PLL_N = 336, PLL_P = 2
  - PLL_VCO = 25MHz / 8 × 336 = 1050MHz
  - SYSCLK = 1050MHz / 2 = 525MHz... ❌ 不对，实际上代码配置了 PLL_M = 8
  
  > **注意**：`system_stm32f4xx.c` 中 `PLL_M = 8`（对于25MHz HSE → VCO输入=3.125MHz），`PLL_N = 336`，`PLL_P = 2`：
  > - PLL_VCO = (25/8) × 336 = 1050MHz
  > - SYSCLK = 1050/2 = 525MHz ❗ 这超过了 STM32F407 的最大 168MHz！
  > 
  > ⚠️ **潜在问题**：如果使用 25MHz HSE，PLL_M 应为 25（使 VCO 输入=1MHz）。但实际板子可能使用 8MHz HSE（PLL_M=8 使 VCO 输入=1MHz，PLL_VCO=336MHz，SYSCLK=168MHz ✅）或者代码实际运行时主频并非注释所述的 168MHz。请核实实际晶振频率。

- `SystemCoreClockUpdate()` — 更新 `SystemCoreClock` 全局变量（时钟改变时调用）
- `SystemInit_ExtMemCtl()` — 外部 SRAM/SDRAM 初始化（条件编译，本项目未启用）

**时钟树配置（STM32F40_41xxx）**：
| 时钟 | 频率 | 来源 |
|------|------|------|
| HSE | 25MHz (默认) / 8MHz (需核实) | 外部晶振 |
| PLL_VCO | 336MHz (8MHz HSE) | HSE/PLL_M×PLL_N |
| SYSCLK (HCLK) | 168MHz | PLL_VCO/PLL_P |
| APB1 (PCLK1) | 42MHz | HCLK/4 |
| APB2 (PCLK2) | 84MHz | HCLK/2 |

### 3.4 SYSTEM/ — 系统组件

#### [SYSTEM/delay/delay.c](SYSTEM/delay/delay.c) — 延时函数（原子哥@ALIENTEK）

**功能**：基于 SysTick 定时器的微秒和毫秒延时函数。

- `delay_init(u8 SYSCLK)` — 初始化延时模块
  - SysTick 时钟 = HCLK/8 = 168MHz/8 = 21MHz
  - `fac_us = SYSCLK/8 = 21`（每微秒计数21次）
  - `fac_ms = fac_us × 1000 = 21000`（每毫秒计数21000次）

- `delay_us(u32 nus)` — 微秒延时（阻塞式）
  - 将 `nus × fac_us` 加载到 SysTick LOAD 寄存器
  - 等待 COUNTFLAG 置位（定时到达）
  - 最大延时：798915μs ≈ 799ms

- `delay_ms(u16 nms)` — 毫秒延时（阻塞式）
  - 大于 540ms 时分段延时：循环 540ms + 余数
  - 为什么要 540ms？因为 SysTick LOAD 是 24 位，最大 0xFFFFFF = 16777215
  - 最大单次 = 16777215/21000 ≈ 799ms，取安全值 540ms

- `delay_xms(u16 nms)` — 单次毫秒延时（内部函数）

**OS 支持**：通过 `SYSTEM_SUPPORT_OS` 宏可扩展支持 UCOS-II/III，但本项目未启用。

#### [SYSTEM/usart/usart.c](SYSTEM/usart/usart.c) — 串口驱动（原子哥）

**功能**：
1. **USART1 初始化** — `uart_init(u32 bound)`（原调试串口，现保留备用）
   - 引脚：PA9=TX, PA10=RX
   - 默认波特率 115200
   - 接收中断使能（`EN_USART1_RX` 宏控制，当前 = 0，关闭）
   - 2026-08-31 新增 `uart3_init(u32 bound)`：USART3 调试串口（PC10=TX, PC11=RX, APB1），printf 已重定向到此口
   
2. **USART6 初始化** — `uart6_init(u32 bound)`（雷达串口）
   - 引脚：PC6=TX, PC7=RX
   - 波特率 230400
   - 使能 DMA 接收：`USART_DMACmd(USART6, USART_DMAReq_Rx, ENABLE)`
   - **不使用 USART6 的接收中断**，完全由 DMA 接管

3. **printf 重定向** — `fputc()` 重定向到 USART3（原为 USART1，2026-08-31 起）
   - 使得 `printf("...")` 输出到 USART3 (PC10)
   - 需要 Keil 勾选 "Use MicroLIB" 选项

4. **USART1 中断服务** — `USART1_IRQHandler()`
   - 基于 `\r\n`（0x0D 0x0A）的回车换行帧解析
   - 接收状态 `USART_RX_STA` bit15=完成, bit14=收到0x0D, bit13:0=长度

##### [CENTRE_LINE.c](HARDWARE/CENTRE_LINE/CENTRE_LINE.c) — ⭐ 实现

**包含的函数**：

**（1）`Midline_fit()` — 最小二乘法直线拟合**

将一组笛卡尔坐标点 `(x_i, y_i)` 拟合为直线 `y = k*x + b`。

```
k = Σ[(xi-x̄)(yi-ȳ)] / Σ[(xi-x̄)²]
b = ȳ - k*x̄
```

两遍扫描：第一遍求均值，第二遍求分子分母。除零保护：分母为0时 k=0。

**（2）`curvity_cal()` — 三点法平均曲率**

使用 Menger 曲率公式 `K = 4S/(AB·BC·AC)`，对中线点集中每间隔 `forward=10` 个点的三元组求曲率后取平均。步长 10 是为了让三点间距足够大以抗噪声。

**（3）`Midline_PD_Init()` — 舵机 PD 参数初始化**

用三组 kp/kd（直道/大转弯/小转弯）初始化 PID 参数块，清零误差历史。

**（4）`Speed_PID_Init()` — 速度 PID 参数初始化**

**（5）`Midline_PD()` — ⭐ 9模式 PD 舵机控制器**

这是整个项目最核心的控制函数。

**PD 公式**：`pwm = mid + kp×err + kd×(err - err_last)`

**9种模式对比**：

| flag | 模式 | 偏差 err | 用哪组参数 | 适用场景 |
|------|------|---------|-----------|---------|
| 0 | 普通中线 | `-((y_last-b)/k - 50)` | kp, kd | 直道/微弯 |
| 1 | 小右转 | `-((Y_R-b)/k + width*DIS_R)` | kp_3, kd_3 | 右弯道内侧 |
| 2 | 小左转 | `-((Y_L-b)/k - width*DIS_L)` | kp_3, kd_3 | 左弯道内侧 |
| 3 | 大右转 | `-|Δy|/k` | kp_2, kd_2 | 右弯道外侧 |
| 4 | 大左转 | `-|Δy|/k` | kp_2, kd_2 | 左弯道外侧 |
| 5 | 垂线直道 | `-(chuizhi - 50)` | kp, kd | 绝对直道 |
| 6 | 均值控制A | `-(junzhi)` | kp, kd | 备用 |
| 7 | 均值控制B | `-(junzhi)` | kp, kd | 中线点稀少 |
| 8 | 中右转 | `-|Δy|/k` | kp_2, kd_2 | S弯右转 |
| 9 | 中左转 | `-|Δy|/k` | kp_2, kd_2 | S弯左转 |

**处理流程**：
1. 检测模式切换（小转弯→直道时清零 err_l，防止 D 项跳变）
2. 根据 flag 计算偏差 err
3. 偏差限幅 [-500, 500]
4. PD 计算输出
5. 放大 ×10 得到实际 PWM 值
6. 限幅 [SERVO_PWM_MIN, SERVO_PWM_MAX]
7. 调用 `Servo_ChangePwm()` 输出到舵机
8. 保存 err 和 flag 供下一帧使用

**调试输出**：每帧打印 ERROR、flag、speed_now、speed_mubiao、PWM_Before、PWM_After。

**（6）`Speed_PID()` — 增量式 PD 速度控制（备用）**

增量式 PD：`pwm += kp×err + ki×err_sum + kd×(err - err_last)`，带积分抗饱和。

**（7）`PID_realize()` — 位置式 PI 速度控制（主用，TIM5 中断中调用）**

位置式 PI：`pwm = kp×err + ki×err_sum + kd×(err - err_last)`，每 10ms 在 TIM5 ISR 中调用一次。

##### [LEIDA_DATA.c](HARDWARE/LEIDA_DATA/LEIDA_DATA.c) — ⭐ 实现（981行）

**（1）`LEIDA_DATA_HANDLE1()` — 原始字节解析**

M10 雷达数据包格式（每包 47 字节）：

| 偏移 | 长度 | 内容 |
|------|------|------|
| 0 | 1 | 帧头 0x54 |
| 1-3 | 3 | 保留 |
| 4-5 | 2 | 起始角度（LSB first）/100 = 度 |
| 6-8 | 3 | 数据点0：距离（LSB first）mm + 保留 |
| 9-11 | 3 | 数据点1：距离 + 保留 |
| ... | ... | 每包12个数据点 |
| 42-43 | 2 | 结束角度（LSB first）/100 = 度 |
| 44-45 | 2 | CRC（未校验） |

**同步策略**：寻找间隔 47 字节的三个连续 0x54 帧头。

**角度处理**：
1. 12 个数据点的角度在起始和结束角度之间线性插值
2. 坐标系旋转：`angle = -angle + 360 + LEIDA_ANGLE_CENTER`
3. 归一化到 [0°, 360°)，使得 0°=右侧(x+), 90°=前方(y+)

**（2）`LEIDA_DATA_HANDLE2()` — 极坐标转笛卡尔**
```
x = distance × cos(angle × π/180)
y = distance × sin(angle × π/180)
```
使用 CMSIS-DSP 库的 `arm_cos_f32()` / `arm_sin_f32()` 加速。

**（3）`LEIDA_DATA_HANDLE3()` — 筛选有效点（按角度范围）**
筛选 [LEIDA_ANGLE_RIGHT, LEIDA_ANGLE_LEFT] 内距离非零的点。

**（4）`LEIDA_DATA_HANDLE3_2()` — 筛选有效点（按距离）**
筛选 distance >= 100mm 的所有点。

**（5）`LEIDA_DATA_HANDLE4()` — 中线点计算** ⭐

**算法**：
1. 从右边界(0°)到左边界(180°)以 0.6°步进扫描
2. 在每个角度对(angle_right, angle_left)处，找距离[50, 2000]mm 内满足容差的最优点
3. 计算中点：`(x_left+x_right)/2, (y_left+y_right)/2`
4. 排除 x 的 2 个最大值和 2 个最小值（去极端离群）
5. 按相邻点 x 间距在 5 倍平均间距范围内滤除
6. 只保留 y ≤ 800mm 的近区点

**（6）`LEIDA_DATA_HANDLE6()` — 左边界提取**
从 180°向下扫描 `BLUE_ANGLE_LEFT_RIGHT`度，每度找最近有效点（距离≤4000mm）。

**（7）`LEIDA_DATA_HANDLE7()` — 右边界提取**
从 0°向上扫描 `BLUE_ANGLE_LEFT_RIGHT`度，处理 0°/360°回绕。

**（8）`LEIDA_DATA_HANDLE8()` — 左边界突变检测** ⭐

**算法**（6点滑动窗口）：
```
if |dist[i]   - dist[i+1]| ≥ 400mm AND
   |dist[i-1] - dist[i+2]| ≥ 400mm AND
   |dist[i-2] - dist[i+3]| ≥ 400mm
→ 检测到突变！
```
三重条件防止单点噪声误触发。仅在角度 ≥ 100°（左侧）范围内检测。
返回距离突变点更近一侧的 y 投影距离（1m 以内才报告）。

**（9）`LEIDA_DATA_HANDLE9()` — 右边界突变检测**
同 HANDLE8，但仅在角度 ≤ 80°（右侧）范围内检测。

**（10）`LEIDA_Distance()` — 跑道宽度计算**

**算法**：
1. 对每个左边界点（150°~210°），找到对侧对应点（角度+180°）
2. 将两者的距离求和
3. 使用 6 元素最小值级联，取第 6 小的距离和
4. 目的：排除少数噪点的影响，用第 6 小值作为稳健估计

**（11）`LEIDA_DATA_HANDLE5()` — 前方路径扫描** ⭐

**障碍物检测**：86°-94°范围内若有 ≥5 个点距离 > 1500mm → 认为前方有缺口，返回 0。
**无障碍时**：扫描 70°-110°（每 1°），每度找最近符合条件的点（y≤2000mm, distance≥200mm），经拟合、反转、离群点滤除后返回。

**（12）`LEIDA_DATA_HANDLE5_2()` — 侧前方扫描**
与 HANDLE5 类似但角度范围可配置（用于 S 弯检测的 70°-90° 和 90°-110° 分别扫描）。

**（13）`LEIDA_DATA_HANDLE10()` — 离群点滤除**
按 x 坐标间距一致性进行离群点滤除（算法同 HANDLE4 中的滤除步骤）。

**（14）`LEIDA_DATA_HANDLE11()` — 中线垂直度判断**
若第 3 级 x 极值跨度 `< 10mm` → 中线垂直，返回中点 x 坐标。否则返回 0（用于判断是否处于绝对直道）。

**（15）`LEIDA_DATA_HANDLE13()` — 边界直线度判断**
5 级极值排除法：若第 5 级 x 极值跨度 `< 100mm` → 边界为直线（可能用于判断是否即将进入弯道）。

**（16）`LEIDA_ANGLE_jiuzheng()` — 雷达角度校准**
利用左右边界的对称性自动计算角度偏差并修正。**已实现但未在主循环中调用**。

**（17）`reverse()` — 数组反转**
按 x 和 y 分量分别反转 `_LEIDA_DATA_plane` 数组。

**（18）调试打印函数**
`LEIDA_PrintAll()`、`LEIDA_PrintSample()`、`LEIDA_PrintHead()` — 用于串口输出雷达数据调试。

1. 暂停 DMA（安全拷贝）
2. 双缓冲：`memcpy(DMA_USART6_RX_BUF_r, DMA_USART6_RX_BUF, 2000)`

## 八、存在的代码问题与建议

### ⚠️ 潜在问题

1. **系统时钟 PLL_M 值存疑**：`system_stm32f4xx.c` 中 `PLL_M = 8`。如使用 25MHz HSE，VCO 输入 3.125MHz 会导致 PLL 输出超频。需确认实际晶振为 8MHz。

2. **HW_TEST_MOTOR_SERVO = 1**：当前编译的是硬件测试模式（舵机往复+电机往复），正常循线需改为 0。

3. **HARDWARE/TIM/PWM1/PWM.h 头文件保护宏冲突**：与 `HARDWARE/TIM/PWM/PWM.h` 使用相同的 `__PWM_H` 宏，同时包含编译会失败。

4. **互补 PWM 引脚复用冲突**：`TIM9 CH1 (PE5)` 和电机方向引脚 `PE5` 共用同一引脚，如果同时使用会冲突。

5. **USART6 DMA 模式为 Normal**：每帧 2000 字节后需要中断重新使能。若雷达帧长变化可能导致数据错位。建议考虑使用循环模式或添加帧同步超时保护。

6. **printf 调试输出开销大**：主循环中有大量 `printf()`，在高速运行时（每帧 10-30ms）可能成为性能瓶颈。建议在生产版本中关闭或使用条件编译。

7. **`LEIDA_ANGLE_jiuzheng()` 未调用**：雷达角度校准函数已实现但未在初始化或主循环中使用，物理安装误差可能影响循线精度。

8. **`curvity_cal()` 未使用**：曲率计算函数已实现但未在决策逻辑中引用，可能提供更多弯道信息。

### 💡 优化建议

1. 将 printf 调试语句包裹在 `#if DEBUG_PRINT` 条件编译中
2. 考虑使用 DMA 循环模式以简化接收缓冲区管理
3. 将 PID 参数存储在 EEPROM/Flash 中，实现掉电保存
4. 增加看门狗（IWDG）提高系统可靠性
5. 添加电池电压 ADC 采样和低电量保护

## 十、总结

本工程是一个**完整的 STM32F407 雷达循线小车项目**，代码组织清晰，模块划分合理。

**架构优势**：
- 分层清晰：硬件驱动 → 数据处理 → 控制算法 → 主决策
- 多模式 PD 控制策略设计精良，能应对直道、大弯、小弯、S弯等不同路况
- 雷达数据处理流水线完善，包含同步、解析、坐标转换、边界提取、突变检测等完整流程
- 双缓冲 DMA + IDLE 中断提高了通信可靠性
- 蓝牙远程调参降低了现场调试难度

**可改进空间**：部分预留功能（SPWM、互补PWM、曲率）可集成进主控制逻辑以获得更好的循线性能，输出调试信息可精简以提升主循环频率。
