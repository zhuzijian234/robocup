## 2. 首次台架验收（轮子架空）

| 项目 | 操作 | 通过条件 |
|---|---|---|
| UART一致 | 模块与MCU设115200，查询info | 正确布局/源码标识；无乱码 |
| 模式互斥 | tele0/1/2/3逐条切换 | 在途帧结束后只出现目标格式；tele0无主动心跳/控制，查询仍可回复 |
| 会话边界 | session12345，再session12346 | 旧在途帧完整收尾；新帧session正确，tx_seq按新会话计数 |
| 精确配置 | getcfg；核对kp3等 | 全30片齐全，float32原值一致；不是只核对get整数显示 |
| 参数事件 | 发一条合法参数命令，再发非法值 | 合法ACK、revision、新配置/事件一致；非法值不修改参数，ERR可见 |
| 配置并发 | getcfg过程中写参数 | ERR busy；旧配置片不混入新值 |
| 控制状态 | 输入回放触发模式5/7、保持、强制及≤20点 | 实际模式、action、valid/updated及最终CCR与分支一致 |
| 停流 | 正常输入后断开雷达数据 | 无重复旧CONTROL；HEALTH报告输入年龄增长；约500ms保护锁定，恢复输入不自动起步 |
| 丢失/乱流 | 回放缺包头、错字节、短块 | 不把旧点标为新有效数据；计数与标志可解释；CRC未校验的局限仍记录 |
| 降频 | rate1→2→3 | control_seq继续逐次增长，发送抽样变化；HEALTH周期不变 |
| 断连 | 关闭蓝牙连接，再重连 | 无旧队列无限堆积；需重新建立session/配置 |
| 队列压力 | 高频查询、降低无线吞吐 | 仅整帧丢弃、tx_drop增长可见；不出现文本插入V2载荷；控制不中断等待UART |
| 两次采集 | 连续记录两个run | 独立UUID/session/raw/时间，无上一run数据混入 |
| 时间准确 | 示波器或已知时序回放对照 | TIM6毫秒/微秒间隔、TIM5保护周期符合实际时钟；不将UART延迟当控制周期 |
| RAM/CPU | 最重配置与控制分支 | map在预算内，栈水位有余量，ISR无超过计时/接收窗口的阻塞 |

KEY/EN、模块电源接法、机械停车距离不由软件测试证明。保留正常跑圈、低电压、强光、管道间隙、断连日志后再决定控制参数。

## 3. 是否适配M10？

**遥测V2格式和上位机可以承载M10结果；当前固件的雷达接收解析仍是LD14P，不能直接插M10就运行。**

| 部分 | M10适配情况 |
|---|---|
| 蓝牙调参命令、V2 CRC/帧头、CONFIG/EVENT、上位机 | 与雷达原始串口协议解耦，可复用 |
| 原始雷达解析/DMA容量/组圈/滤波 | 未在本轮移植；仍需按雷达升级方案实现 |
| 时间记录 | 调用Diag_InputDone记录真实输入完成；组圈后应在整圈完成时发布，不能继续把DMA小块标成整圈 |
| raw_count | 填本次成功解析的原始距离槽数，不能填过滤后的有效点数；检查u16及缓存上限 |
| radar_dps | M10速度先按其协议单位换算成度/秒，不可直接复用LD14P字节偏移 |
| lidar_id/input_kind/配置 | 当前1=LD14P、0=DMA块；M10改2，整圈输入改1，并更新CONFIG第14键、点率、波特率/容量及构建摘要 |
| 算法摘要 | 转成现有统一点云/算法输出后填26字段及valid/updated；缺失字段清有效位，不用旧值冒充 |
| 控制参数 | 协议兼容不代表PD、保持次数、断点阈值和500ms门限无需验证 |

绑定入口为Diag_Begin/Diag_Field/Diag_Submit和输入完成接口。M10移植必须同时检查原始数据与时钟/型号元数据，不能仅把DIAG_LIDAR_ID从1改成2。

## 4. 带宽预算

按115200、8N1的理论11,520 B/s计算；下表不含CONFIG/ACK/EVENT突发及无线重传影响，不是实测吞吐：

| 配置 | CONTROL+正常HEALTH | 理论占比 |
|---|---:|---:|
| LD14P标称估算8.713次控制/s | 约1021 B/s | 约8.9% |
| M10按10次控制/s | 1160 B/s | 约10.1% |
| M10P按12次控制/s | 1376 B/s | 约11.9% |
| 附加20次控制/s压力条件 | 2240 B/s | 约19.4% |

因此M10通常不需要另换遥测协议。是否能rate1全发，仍由实际控制频率、模块无线吞吐、队列丢弃及延迟决定。9600只有960B/s，连LD14P上述正常全量预算也超过理论上限，必须降频并验收；不建议把9600当V2正式性能基线。

本轮新增RAM主要为整帧发送池、快照和配置状态，以及独立增加的3KiB栈；与M10升级预算必须重新合并，不能把同一遥测/栈预留加两次，也不能省略当前实际增量。
