## 3. 快照与状态语义

每次控制尝试递增 control_seq，不依赖是否发遥测。一次结果可为 PD、保持、强制转向或感知无效。没有新输入不重复生成旧结果；主循环独立调用 Diag_Poll 处理 HEALTH、命令和发送。

必须记录最终下发 CCR（计数单位），这不是测得的舵机物理角度。若同一轮强制输出后又被 PD 覆盖，CONTROL 记录最终值，动作原因取最终动作；过程覆盖另计 EVENT 或计数。保持计数已递减到零不能推断本轮未执行强制动作。

模式字段记录实际执行 PD 模式；本轮未执行 PD 时置 0 并清其 updated 位，结合 action_reason 判断。动作枚举：0=未知，1=PD，2=保持，3=强制左，4=强制右，5=感知无效，6=初始化。不得将所有 mode 0 都解释为直道。

修复前 main.c 的模式 5/7 有真实调用：`Midline_PD(..., 7)`（约453行）和 `Midline_PD(..., 5)`（约468行），但局部 pid_select 仍为0，导致 ch4 错报为0。模式6未见当前主循环调用。实施时从实际 PD 实参记录诊断模式，或在对应调用点明确更新快照；优先使用独立的 executed_mode，避免将诊断修正与用于分支/历史判断的 pid_select 混为一体。若选择直接赋 pid_select=5/7，需回放验证其所有消费者和历史状态，不仅检查串口显示。

`|k|<=0.1` 分支没有新 PD 误差：输出保持动作，清 err/mode 的 updated 位，并记录最终CCR。有效点不足的 continue 分支必须提交感知无效结果。不能把强制打满后递减为0的保持计数当成该周期未执行强制动作的证据。

valid_mask 表示数值可用于当前诊断，updated_mask 表示本次重新计算，clipped_mask 表示编码发生物理或整数限幅。旧 err 可保留，但不得标成本次 PD 结果。断点距离 0 是否代表“未发现”必须与“计算无效”分开，后者清 valid 位。

同一 CONTROL 从稳定快照编码；速度环值在提交快照时一致性读取。配置在控制边界应用，param_revision 与实际使用配置对应。遥测数据不得直接逐项指向变化中的全局量。

## 4. 命令与采集协商

保留原有参数名、单位及 get 文本格式。新增命令使用有界解析、完整数值消费和范围检查，不能让 atoi 把非法字符串静默当 0。

| 命令 | 语义 |
|---|---|
| info | 回复协议能力、字段布局、固件/算法/雷达标识 |
| session N | N 为非零 uint32；在当前帧结束后切换会话，清除旧会话尚未发送遥测，回复 OK |
| tele 0/1/2/3 | off / 原 VOFA+ / V1 / V2 |
| rate 1..10 | 每 n 次控制结果一次 CONTROL，切换时重置抽样计数；不影响 HEALTH |
| getcfg | 精确配置快照；V2 时分片返回 CONFIG |
| get | 保留现有兼容回显，不作为精确配置备份 |

tele 0 停止主动 CONTROL/HEALTH，仍可响应查询。模式互斥。初期 ASCII 回复一条完整行入队；主机一次只发一个等待应答的命令，超时不得当成功。参数组更新未实现原子事务前，只允许逐条应用并逐条验证，不宣称支持整组原子写入。

连接流程：打开 → info 能力查询 → 建立 session → tele 3 → rate → getcfg → 确认配置完整 → 开始正式记录。协商原始数据也保存并标记为 pre-roll。旧固件不支持命令时明确提示，可选择 V1/VOFA 降级，不能假装 V2 就绪。不用 sleep 后 reset_input_buffer 清掉应答。

session 切换时清除未发送旧会话帧；已发送的旧帧允许完整收尾。主机以 ACK 和帧头 session 区分边界。设备复位 session=0，必须重新协商并开启新数据段。

## 5. V1 兼容与 V2 公共格式

V1 保持 57 B：AA55、version=1、seq8、26×int16、载荷 sum8。字段顺序和缩放保持与当前 Python FIELD_TABLE 一致。校验不保护序号、无设备时间与有效位是其固有限制；旧报告应明确降级。

V2 全部多字节整数小端，总长度 16～256 B，不发送 C 结构体原始内存，避免填充和对齐差异。

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0～1 | 2 B | AA55 |
| 2 | u8 | version=2 |
| 3 | u8 | type：1 CONTROL、2 HEALTH、3 CONFIG、4 EVENT |
| 4～5 | u16 | 总帧长，含头和 CRC |
| 6～9 | u32 | tx_seq |
| 10～13 | u32 | session_id |
| 14～len-3 | bytes | 类型载荷 |
| len-2～len-1 | u16 | CRC16，小端 |

CRC16/CCITT-FALSE：poly 0x1021、init 0xFFFF、非反射、xorout 0；覆盖 offset 2 到 len-3，包含 version/type/len/seq/session。标准串 123456789 的 CRC 为 0x29B1。实现前生成 C/Python 共用黄金报文。

tx_seq 在发送器选中完整帧、即将开始发送时分配，再填 CRC；优先级重排不能造成序号倒退。按会话计数，切换会话归零。入队前丢弃由单独计数记录。未知类型在长度/CRC 正确时保存并跳过；错误长度或校验按字节重同步。解析缓冲必须有上限。

扩展字段无效时编码占位0、valid=0；无新转速可以保留旧值但updated=0，是否仍valid取决于配置的最大年龄，超龄清valid。只有协议确实报告有效零转速才表示“测到0”；停流本身只能表示无新测量。70个槽全部FFFF时原始点数=70、bit26有效，有效回波数=0；没有成功解析输入与已知空输入不能混用。raw槽数不能用过滤后的 valid_couter 代替。

首个 control_dt_us=0且bit30 valid/updated均为0。三个时间字段允许完整uint32取值，包括0和0xFFFFFFFF，不再保留数值哨兵；读取时先看valid位。毫秒时钟约49.7天回绕，微秒32位间隔约71.6分钟达到范围上限；用扩展计数或持续采样确保差值不含未知多次回绕，无法证明连续性则清valid并分段。会话重置/设备重启不是时钟回绕。时间是接收/处理时间，不冒充激光发射时间。

int16范围为−32768～32767，不表示允许计数/距离等字段出现负物理值；先做字段语义验证。err 的三个门限分别是：**算法限幅±500；报告近饱和阈值ERR_SAT=490；编码保护限幅±600**。±600有意比算法限幅宽，以免把算法饱和与编码异常混为一谈：err=500编码5000且clipped=0，err=650编码6000且clipped=1。不要“统一”改为500。k=±30是缩放前上限，存值±30000，为int16留出余量。

距离为 mm，PWM 为 CCR 计数；速度沿用现有编码器速度单位，不当 m/s。目标速度保留现有整数分辨率；以后支持小数需换布局。四个保持字段本版仍是“剩余控制次数”，不暗改成 ms。未来控制器改为毫秒保持时升级字段布局/协议，并同步主机，不能复用旧字段偷偷改单位。

当前输入单位是 DMA 块；完成雷达扫描组帧后变为扫描。CONFIG 必须记录 input_kind，变化开启新 run。单独的扫描序号可在后续扩展消息中增加，不能把 control_seq 宣称为扫描圈号。

编码顺序：判有限值 → 物理限幅 → 缩放 → 在宽整数/浮点域舍入 → 最终 int16 饱和 → 写字节。NaN/±Inf编码占位0、valid=0、clipped=0；updated仅表明本轮是否重新计算，不能代替valid。发生物理或整数限幅置clipped=1；普通量化舍入不置clipped。不得在int16边界加0.5后直接转窄整数，也不得直接将巨大浮点值转int32。先比较可表示范围再进行有界转换。

舍入冻结为 **round-half-away-from-zero（恰好半整数时远离0）**，例如+34.5→35、−34.5→−35，禁止直接用Python默认round()代替。浮点字段以车端float32为基准：C/Python黄金用例使用相同IEEE754输入位模式，物理限幅和乘缩放均按binary32取值，然后把该缩放结果精确提升到足够宽的浮点域进行舍入。这样可同时检查输入精度、运算精度和舍入规则，而不是把Python的decimal/double示例当车端float32结果。整数源字段使用足够宽的整数计算并检查溢出。

模拟器和车端须共享等价的字段规格（缩放、物理限幅、有效性和舍入）；V1不能表达mask，非有限值测试应使用V2并确认主机不把占位0当有效值。黄金用例至少包含：err±500/±600/±650、k±0.5/±30/±40、缩放后±34.5及两侧相邻可表示值、NaN/±Inf、整数范围边界、有效0与未知0、input_end_ms/control_end_ms的0xFFFFFFFF→0回绕、首帧无dt，以及dt超出u32范围时清valid而不是回绕成小间隔。

## 7. HEALTH、配置和事件

### 7.1 HEALTH：80 B

正常 1 Hz；检测无输入/失效时最多 5 Hz，在主循环独立调度。若主循环卡死仍无法发心跳，主机接收超时需显示“链路或设备无响应”，不能断言仅雷达故障。

载荷为 16 个 u32，依次位于 14+4×i：
0 uptime_ms；1 last_input_age_ms；2 last_valid_control_age_ms；3 input_seq；
4 control_seq；5 uart_error_total；6 dma_error_total；7 rx_overflow_total；
8 scan_overflow_total；9 input_drop_total；10 tx_drop_total；11 process_max_us；
12 rx_queue_peak_bytes；13 param_revision；14 status_flags；15 unsupported_mask。
CRC位于78～79。unsupported_mask的bit0～13仅表示对应字段未实现/不支持，其他位必须为0；status_flags和unsupported_mask本身必须支持。支持但暂时没有测量，与未实现分开记录。

status_flags：bit0输入超时、bit1本轮感知无效、bit2 TX拥塞、bit3参数快照未就绪、bit4输入为完整扫描、bit5 last_input_age_ms有效、bit6 last_valid_control_age_ms有效、bit7 uptime_ms有效；其他位保留为0。无对应历史事件、时钟失效或年龄超出u32范围时，相应年龄有效位清0并写占位0。时间相关字段不再用全1哨兵；0xFFFFFFFF在有效位为1时是合法值。unsupported_mask置位时优先判为不可用，相应时间有效位必须清0。超时门限记录于CONFIG，不在遥测里另起一套控制门限。

### 7.2 CONFIG：有界分片

载荷前 12 B：config_id u32、param_revision u32、chunk_index u16、chunk_count u16；余下≤228 B 为配置记录字节。一次快照内容不可混用不同 revision，变化时中止并重发。主机仅在全部片段齐全、编号合法且版本一致时提交配置。

配置采用有类型的 TLV 记录：key u16、value_type u8、length u16、value。记录可跨分片，主机重组后解析；键注册表随协议源码维护，至少包含：
- 固件构建/源码摘要（含未提交修改）、主机与协议布局版本；
- 雷达/算法型号、input_kind、点率/转速配置；
- 单位、几何阈值、PD 输出尺度、T_ref（若适用）、保持字段单位；
- 全部可调参数、当前 rate、诊断周期/超时设置。
float32 使用 IEEE754 原始 4 字节，不能以 get 的舍入显示值备份。value_type 定义 1=u32、2=i32、3=float32、4=UTF-8、5=bytes。键注册表与黄金报文是编码前必须冻结的交付物，未完成前不进入实车采集验收。

### 7.3 EVENT

载荷前缀：event_ms u32、param_revision u32、event_code u16、body_len u16，后接≤228 B body。
event_code：1参数应用、2参数拒绝、3状态变化、4数据丢弃。
参数应用 body：key u16、value_type u8、value_len u8、旧值[value_len]、新值[value_len]；当前数值参数 value_len=4。
拒绝/状态/丢弃 body 为 UTF-8 有界说明，报告不将自由文本自动解释为已生效参数。
命令 ACK 在实际应用后返回；若无空间保留应答/事件，拒绝本次写入并计数，不静默改参数。无法支持按组原子更新时在 INFO 明示。事件可丢失时，主机通过 revision 缺口触发 getcfg 并标记未知区间。

## 8. 发送、连接与硬件配置

所有 VOFA、V1、V2、get、ACK 均由统一完整消息队列发送；只有 TXE ISR 写 USART6 DR。旧直接发送调用必须同时迁移，不能混用队列和直接 DR 写入。

ACK/关键事件保留空间，优先于尚未发送的 CONTROL；只丢弃完整未发送遥测，不能截断在途帧。发送队列有上限，断连时停止堆积控制帧；重连重新握手。无硬件流控时，队列发完不代表无线端收到，仍需主机链路统计。

只读台架 V1 可暂用阻塞发送校验协议；最终非阻塞方案还需移出实时路径的 USART3 大量 printf，避免把周期扰动误归给蓝牙。

HC-05 配置必须先识别具体模块/底板及引脚说明：模块供电电压、UART 逻辑电压、KEY/EN 电平不能混为一谈，不沿用旧稿“KEY 接 VCC、VCC 接 5V”的通用接线。按实际模块手册通过 USB-TTL 进入 AT 模式，查询并保存旧配置，设置115200/8N1，再查询确认；MCU 同步改为115200。以蓝牙命令应答和合法数据帧验收，不能依赖 USART3 的 Bluetooth_Init printf。

若只能用9600，必须按实际 CONTROL+HEALTH+ACK 总量降频、重新测延迟；不是只改 rate 就维持相同诊断能力。上位机明确标注降级，MCU与模块波特率必须一致。

## 9. 上位机实现与报告规则

1. V1/V2/VOFA 明确分派，长度、版本、类型、CRC、枚举、mask 与配置一致性全部验证。ASCII 仅识别允许的 ACK/ERR/get 格式，缓冲设上限，损坏二进制不能随意 decode 后当参数事件。
2. 每次 start_capture 新建录制原始缓冲、解析器和 run UUID；实时预览独立。连续两次采集不得累积。最好流式落盘，避免长时采集占满内存。
3. bin 对应 rx.jsonl 记录每块 offset、length、host_monotonic_ns；meta.json 包含协商信息、配置、起止墙钟及结束原因；events、CSV、报告、图来自同一录制范围。开始/结束位于半帧时注明，不拼接不同 run。
4. 使用 monotonic 控制采集时长；Tk 只做展示，后台任务通过队列回传，串口单一所有者。生成报告不堵塞采集；断连与磁盘写入失败需显示并结束/标记不完整录制。
5. 按设备时间建立时间轴，uint32 时间回绕分段展开，复位/session 变化另起段。control_dt 用于控制周期，不能用遥测包间隔代替。未做时钟对齐不得估计绝对单程延迟。
6. 按 session/param_revision/input_kind 分段，跨缺失、无效、未更新数据停止连续差分。rate>1 时明确有未记录控制结果，不能重建其中 PWM 峰值。
7. 速度误差逐行使用 Speed_mubiao；动态目标前后分段。方向异常、保持残留、饱和、模式占比结合实际动作和有效标记；连续异常用毫秒窗口，阈值记录到报告。
8. tx_seq 推断的缺口仅为链路缺失估计；队列丢弃、主动抽样、复位分别统计。丢帧率分母为收到数+推断缺失数，不能简单缺失/收到；重传/重复单独计数。首尾未知丢失不作精确统计。
9. V1 不输出“实测8.7Hz”；有主机块时间可给接收统计，否则仅给假设下的估计，不能据此调 D。无配置旧日志不得假装已知增益。
10. 报告必须列覆盖范围与不足，不以“10项全部有输出”判通过。没有有效样本时输出“无法判断”，而非正常/零误差。

## 11. 交付与回退

交付固件版本、协议键表/黄金样例、编译map、测试记录、主机版本，以及至少一组台架和一组实车run。AI复核以bin+时间+精确配置为依据，不仅看截图或自动摘要。

每阶段保留可还原版本；在线改参保存修改前精确值。仅关闭遥测使用tele0；协议兼容问题可退tele1/2并标注能力降低。波特率回退必须同时恢复模块和MCU。新增输出记录点不改变控制算法，不因关遥测移除必要的控制初始化修复。

本方案不承诺自动刷写、自动调参或通过蓝牙全量回传高点频点云。编译失败可修复后重试；失败未解决前不得通过构建验收、不得烧录。本文不修改双方关于授权范围和意外情况处理的既有约定。
