# 三次视频与遥测对照分析（仅建议，不修改代码）

## 结论

本次确实已有明显改善。第三次的有效运动记录显示：控制器能够输出较大的左转、切换右转，并在后续几何失效时保持最后的右转指令；不能再把这次撞到围挡直接归因于“弯中反复回正”。视频中的局部急弯、围挡折角和车辆实际转弯能力值得优先核实。

但现有证据还不能确定“完全是赛道问题”或“舵机已达到机械极限”：轮子看起来角度很大，实际 PWM 却没有达到软件限位。应先量清楚实际轮角和最小转弯半径，再决定是否需要增加控制强度。

本次只读取工程、视频和日志，生成分析资料；没有修改固件代码、参数或重新编译烧录。后续建议继续遵守：封闭赛道竞速、每次测试保持固定目标速度、保留编码器闭环，本报告不建议重新加入自动变速或停车逻辑。

## 2. 第三次真正运动阶段发生了什么

原始记录包含 84 条 CONTROL、84 条控制详情、696 条电机记录。52 帧应用了新的转向结果，31 帧没有可用几何路径，1 帧保留转向等待退出确认。

| 遥测相对时间 | 关键变化 | 能说明什么 |
| --- | --- | --- |
| 约 0～1.67 秒 | 实际预瞄位置由约 700 mm 逐渐缩短到 405 mm，输出接近中位。 | 弯前的路径可用范围已经收缩，可作为以后研究更早入弯的线索。 |
| 1.757 秒 | 使用右边界生成路径，远段有效；输出跳到 1573。 | 控制器开始明确左转。 |
| 1.925 秒 | 左转输出达到 1637。 | 已有较强左转指令。 |
| 约 2.68～3.18 秒 | 左转逐渐减小；部分帧几何无效，保持 1484。3.089 秒候选输出接近中位，但退出确认逻辑仍保持 1484。 | 左转减小并非全是无条件回正；保持逻辑确实生效。是否减小得过早仍需要精确同步视频和点云。 |
| 3.256 秒 | 确认反向弯，输出 1278。 | 正常切换右转，没有持续左右翻转。 |
| 3.503～4.756 秒 | 多帧路径误差达到 -500 限幅；右转最低 1233，随后多次保持 1247。 | 后段已经持续请求较大右转。 |
| 4.845～6.926 秒 | 连续没有可用几何路径，实际输出仍为 1247。 | 此阶段没有回到中位 1445；但也没有继续根据新路径修正转向。 |

因此，更准确的描述是：**后半段保持较大的右转，但路径几何随后失效，控制器只能保持已有转角。** 不应把“保持转角”误认为“始终有有效循迹结果”，也不能把“几何无效”误认为“雷达断流”。

几何失效涉及边界支撑范围、独立分桶数、拟合残差或双边一致性等条件。例如某些末段帧边界支撑已很短，另有一帧左侧拟合 RMS 约 63 mm，超过 60 mm 阈值。但当前汇总遥测没有逐分支拒绝原因，无法断言所有无效帧都是同一个阈值造成的。

## 3. “看起来打满”与实际指令

当前中位为 1445，右侧软件限位 1170，左侧限位 1720，每侧范围 275。

| 状态 | PWM | 相对中位偏移 / 软件单侧范围 |
| --- | --- | --- |
| 最大左转 | 1637 | 192 / 275，约 70% |
| 最大右转 | 1233 | 212 / 275，约 77% |
| 持续右转 | 1247 | 198 / 275，约 72% |

这些百分比只表示 PWM 偏移比例，不表示轮角比例。转向连杆、舵机安装和机械止挡都可能使轮子提前接近实际极限。

持续 1247 有明确的软件解释：单边路径比例增益为 0.0395，误差限幅为 500；当误差稳定、微分项归零时，比例输出约为 `10 × 0.0395 × 500 = 197.5`，右转输出约为 `1445 - 197.5 = 1247.5`。这是误差限幅与当前增益形成的平台，并非已经触碰 1170 的输出限位。

所以最关键的实测是：**1247 与 1170 是否还能产生明显不同的实际轮角？** 若几乎无区别，优先解决转弯半径或赛道几何；若还有明显角度余量，以后才值得研究大曲率时的控制强度。现在不宜直接全面增加 Kp 或扩大软件限位。

## 4. 速度闭环、接收与计算效率

第三次原始运动记录中，目标速度始终为 10，编码器速度平均约 10.06，范围约 8.87～12.51；电机 PWM 为 43～100，只有 2/696 条达到 100。后段平均 PWM 比前段升高，说明闭环在增加驱动力。

这里的速度采用工程现有单位，不能直接称为 m/s。编码器测的是车轮转速；即使车身被围挡挡住，轮子滑转也可能让编码器读数正常。没有精确时钟对齐，不能将某个电机样本直接对应某个接触画面。

单次路径处理约 4.4～5.1 ms，CONTROL 间隔约 78～90 ms；雷达持续收包，拒包、溢出、串口与 DMA 错误未见新增异常。累计 discontinuities=1 等历史计数没有在这段持续增长。现有数据没有支持“计算阻塞或雷达接收卡死导致这次撞弯”的证据。更高层更新频率与预瞄时机仍可优化，但不是已经证实的当前主因。

第一、二次以及第三次后段记录中虽然轮速为 0，电机输出指令却为 100，因此也不能把这些记录解释成程序主动停车；是否顶住、驱动电源状态变化等，需要结合现场情况判断。

## 5. 建议优先级

### 第一优先：保持当前代码，量清赛道与车辆极限

- 将 S 弯围挡的局部鼓包、折角整理为平滑过渡，实测最窄通道宽度和急弯半径。视频存在透视，不能据此给出可靠尺寸或认定赛道不合规。
- 测量车辆左右最小转弯半径，比较整车外侧前角、内侧后轮的运动包络与通道，而不只比较车辆中心的轨迹。
- 对照中位、1247、1170 以及左侧对应位置的实际轮角，检查左右转向能力是否对称。先确定转向余量，再决定算法是否需要更大输出。

### 第二优先：做一次条件一致的固定速度对照

- 同一赛道摆放、同一发车位置、同一控制参数，分别使用固定目标速度 8 和 10。
- 观察是否总在同一个反向弯位置受阻、是否存在前轮推头、是否提前或延后入弯。
- 每次目标速度保持恒定。这是用于区分动力学和几何因素的对照，不是增加自动变速。
- 现有第一次与后两次的日志窗口不同，不能直接推出速度 8 必然更好或更差。

### 第三优先：以后若改算法，优先改入弯时机和路径连续性

- 检查双边路径实际预瞄缩短时，是否有质量合格的单边远段可以更早采用。当前只有后续切换结果，没有足够证据证明先前远段已经可用，不能直接提前强制切换。
- 对反向弯的前一弯退出与后一弯确认进行时间对齐分析。本次退出保持和反向确认已生效，不建议整体推翻。
- 若实测确认轮角还有余量，再评估大误差区域的输出强度，保留直线和小误差区的平顺性。
- 末段几何失效应先增加可辨别的原因记录、结合点云定位，再决定是否调整支撑范围、分桶和一致性阈值；不要盲目放宽全部有效性检查。

### 下一轮采集方法

先确认上位机已经正式采集，再释放小车；视频拍到发车和受阻全过程，最好固定机位覆盖整个 S 弯，并保留一次清楚的共同动作作为时间对齐参考。保持当前遥测频率即可，不必大量追加蓝牙文本输出。

最有价值的补充数据是：**1247/1170 的实际轮角对照、左右最小转弯半径、出问题 S 弯的最窄宽度和弯曲尺寸，以及从发车前开始的完整视频与遥测。**
