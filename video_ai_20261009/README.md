## 2. 对齐方法（重要：请先读这一节）

### 2.1 为什么不能用 mp4 的文件时间

三次视频的 mp4 `mtime` 与采集窗口**不重叠**（run2 晚 81 秒、run3 晚 4 秒），
说明 `mtime` 更像**拷贝/保存时刻**，不是录制结束时刻。**不能用它对齐。**

### 2.2 实际采用的锚点：**结尾对齐**

三次的文件名都写明"撞…后**停止采集**"，而视频也是车停下就停录，因此：

```
offset = 采集时长 − 视频时长          tele_t = video_t + offset
```

| 次 | 视频帧/时长 | 遥测源 | 采集时长 | **offset** | 帧覆盖 |
|---|---|---|---|---|---|
| 1 第一次 | 135 / 4.467s | `v2_1009_173009`（32.0s） | 31.984s | **+27.52s** | 127/135 |
| 2 第二次 | 190 / 6.300s | `run_1009_173143`（解码自 .bin） | 7.125s | **+0.83s** | 190/190 |
| 3 第三次 | 215 / 7.133s | `run_1009_173614`（解码自 .bin） | 7.782s | **+0.65s** | 215/215 |

即：**run2 的遥测从视频第 0.83 秒处开始，run3 从第 0.65 秒处开始**；run1 的视频只覆盖采集的最后 4.5 秒。

### 2.3 交叉验证：**不成立，请勿依赖**

尝试用"视频逐帧差分信号 × 遥测编码器速度"的归一化互相关来验证，结果：

| 次 | 端对齐 offset | 互相关最佳 offset | 相关系数 | 一致性 |
|---|---|---|---|---|
| 2 | +0.83 | −1.05 | **0.39** | 差 1.88s ❌ |
| 3 | +0.65 | −0.35 | **0.52** | 差 1.00s ❌ |
| 1 | +27.52 | 不可用（轮速恒 0） | — | — |

**互相关不可信**：摄像机是**手持移动**的，帧间差分主要反映**人的抖动**而不是车的运动，
所以相关系数只有 0.39/0.52，峰值位置没有意义。

**因此对齐精度完全依赖"结尾对齐"这一条假设。** ⚠️ 本文件早期版本写的"±0.3~0.5 s"是**主观估计，不是经过验证的误差界限**——三次都没有共同时间标记，无法给出可验证的界限（见 GPT 复核文档 §2.4）。联络表适合看画面，但**逐帧叠加的 PWM 数字不能当作精确同步证据**。
若需要更准，只有两条路：
1. 下一次录制时保留一个共同动作（拍手/开灯/把车放手）作为同步标记；
2. 从视频里量出"车开始移动"的帧，与遥测轮速由 0 变正的时刻对齐（本轮 run1 无轮速数据、run2/3 未做）。

## 3. 数据质量（本轮"遥测有损"具体损在哪）

| 项 | run1 | run2 | run3 |
|---|---|---|---|
| 采用哪份遥测 | `v2_1009_173009` | **`run_1009_173143`**（解码） | **`run_1009_173614`**（解码） |
| 对照组 `v2_*` 是否可用 | 就是它本身 | ❌ 轮速全 0、`end_reason=error` | ❌ 轮速全 0、`end_reason=error` |
| 编码器速度（本次采用源） | **3160 条样本、序号无缺口，但轮速全 0 而 PWM 恒 100** → 更可能是**采集窗口没覆盖运动阶段**（车已撞停/被拿起），不能断言编码器或电机遥测损坏 | 均值 9.06，范围 0~11.93 ✓ | 均值 9.56，范围 0~12.29 ✓ |
| CONTROL 帧数 | 380 | 85 | 93 |
| firmware | `sha256-85a1cdd24e799127` | 同（无 INFO 行，但 session/配置一致） | 同 |

**结论**：
- **run1 的采集窗口没有覆盖运动阶段**：3160 条电机样本序号无缺口，但轮速全 0、PWM 恒 100，CONTROL 输出也只在小范围（≈1427~1431）≈固定场景。
  所以**不能**说"电机遥测损坏"，也不能把这段静态数据贴到运动画面上。它的 CONTROL 通道可用，但只能代表近似静止的状态。
- 本轮固件标识：**run1 明确记录 `fw=sha256-85a1cdd24e799127`（`algorithm=4`）**；run2 的原始记录沿用相同 session/修订号（推断一致）；
  **run3 是新 session，其原始记录与后段正式记录都没有完整配置握手 → 缺少独立的固件标识证据**（行为/增益/误差关系符合当前版本，但不能当作已证实）。
- **run2/run3 必须用 `run_*.bin` 那份**。`v2_*` 那两份只覆盖车已经顶住墙之后的静止阶段。
- 参数（run1 配置块明确记录）：`spd=10, cx=-27, eclamp=200, dy=200, preview=700, width=500`，`algorithm=4`（`path_track` 新架构、含锥桶避让与逐帧 `reason`）。
- `firmware` 行中 run2/run3 的"同"是**按 session/修订号推断**，不是独立证据（见上一段）。

> ⚠️ **校正记录**：本文件早期版本在 `bend_code` 的编码、run1 的"电机帧丢失"、
> "±0.3~0.5 s 误差界限"、以及 run2/run3 的固件标识这四处有错误或过度断言，
> 已按 `md文档/M10P最新三次S弯复核与修改计划_20261009.md` §2 校正。

## 4. 从这批数据已经能看到的东西

### 4.1 run2 末段：**点云很足，但几何被拒，舵机被保持**

sheet_11（帧 176~189，视频 5.87~6.30s，遥测 6.69~7.12s）每帧都是：

```
pwm=1505.0  act=5  vc=704~710        ← valid_couter 700 上下, 点完全够
reason=1 (PATH_NO_GEOMETRY)  src=3 (PATH_NONE)  far=0  bend_code=2 (=左弯状态)
cand=1505   ref_y=0.0   near_a=0.0   ← 路径根本没建起来
```

**即：不是"没点"，是"路径建不起来"。** 而且此时 `pwm` 被保持在 **1505**（偏左 60 计数），
`cand=1505` 说明候选=实际=保持值，`action_reason=5` 表示本帧没有采用新转向。

画面同步显示：车已经贴/顶在左侧软管上，人的拖鞋入镜（人走过来）→ 与文件名"撞向边界后停止"一致。

**这正是当前最需要定位的失效模式**：`PATH_NO_GEOMETRY` 有 7 个可能分支
（两侧近段都无效 / 两面矛盾且 RMS 相近 / 参考高度 400mm 无支持 / `configured_width`/`preview`/`center_x` 越界 …）。
`aligned.csv` 与 `detail.csv` 里的 `left/right_near_count`、`left/right_rms`、`left/right_span`、`left/right_gap`、`width_source`
就是用来分辨这些分支的。

## 5. `aligned.csv` 字段

| 列 | 含义 |
|---|---|
| `frame` | 视频帧号（0 起） |
| `video_t` | 视频内时刻(s) = frame/30 |
| `tele_t` | **对齐后的遥测时刻(s)** = `video_t + offset` |
| `status` | `ok` / `out_of_range`（该时刻没有遥测行，此时其余列为空） |
| `servo_pwm` | 该帧遥测里舵机 CCR 指令（1170右 / 1445中 / 1720左） |
| `action_reason` | 1=执行了PD 2=保持 5=本帧无有效转向（`BLE_MODE_INVALID`） |
| `valid_couter` | 本帧有效点数（**不是**桶数门槛失败的意思） |
| `path_reason` | **0=APPLY 1=NO_GEOMETRY 2=WAIT_EXIT 3=WAIT_REVERSE 4=EXIT 5=REVERSE 6=BAD_SCAN** |
| `command_applied` | 1=本帧真的写了舵机 |
| `far_valid` / `source` | 远段是否可信 / **0=双侧 1=仅左 2=仅右 3=NONE** |
| `final_pwm` / `candidate_pwm` | 最终输出 / 仲裁前候选 |
| `width_source` | 0=配置值 1=历史实测 2=本帧双侧实测 |
| `bend_code` | **弯向状态**：**0=右弯、1=中性、2=左弯**（= `bend+1`，`bend∈{−1,0,+1}`）。⚠️ 本文件早期版本写成"1=右弯/2=无/3=左弯"，**错一位**，已按 `M10P最新三次S弯复核与修改计划_20261009.md` §2.1 校正 |
| `near_x` / `ref_y` / `near_a` / `far_a` | 近段横向位置 / 预瞄前向位置 / 近段与远段方向 `x=a*y+b` 的 a |

## 7. 已知限制（不要越界解读）

1. **对齐精度 ±0.3~0.5s**：依赖"结尾对齐"假设，互相关验证不成立（手持抖动）。
2. **摄像机手持移动**：不能从视频提取车的绝对轨迹或速度；画面里的透视不能用来量尺寸。
3. **run1 无运动遥测**：视频里的运动没有对应的轮速/电机数据。
4. **视频是单机位**：看不到被软管遮挡的一侧；车小、部分帧有运动模糊。
5. **视频时间与遥测时间不是同一时钟**，`tele_t` 是推算值。
