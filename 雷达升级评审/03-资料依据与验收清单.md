源码公式复核示例（是计算，不是硬件实验）：
- start=17300、70个有效点，文档角范围173°～187.7857°；例程仅输出163°与168°，不能当正确全点解析。

## 4. 待实现接口约定

建议接口，命名可随工程规范调整，语义应保持：
```c
void LidarRx_Init(const LidarConfig *cfg);
size_t LidarRx_Read(uint8_t *dst, size_t cap); /* 主循环消费者 */
void LidarParser_Feed(const uint8_t *p, size_t n, uint32_t rx_end_ms);
bool LidarScan_Acquire(const LidarScan **scan); /* 取得只读所有权 */
void LidarScan_Release(const LidarScan *scan);
bool LidarAdapter_Build(const LidarScan *scan, AlgorithmInput *out);
void Control_Submit(const AlgorithmInput *in, uint32_t now_ms);
void Diag_Poll(uint32_t now_ms); /* 独立于有效扫描 */
```

- ISR生产字节，不向算法发布半包/半圈；解析器持有跨块状态。
- 每个写数组接口带容量；空/坏包返回状态和点数，不靠旧数组内容。
- 单次Control对应明确输入序号、配置版本及有效状态。
- 调度每圈优先排空接收队列的合理批量，再处理最新READY扫描；设置工作量上限避免蓝牙命令饥饿。
- 解析输入丢失后重置包状态和当前扫描；恢复到可证明边界后才发布。
- 所有数据结构sizeof、DMA地址区间、最大点数在构建/启动诊断检查。

## 5. 验收矩阵（尚未执行项）

### 5.1 上电前

- [ ] 芯片丝印与板卡原理图确认ZG；晶振频率核实。
- [ ] 雷达型号、接口、固件、供电和连接器观察方向记录。
- [ ] PA2不再输出LD14P PWM；PA3线路正确；蓝牙和编码器未占冲突资源。
- [ ] MCU和雷达共地，电平/电源正确，PPS/REC未误接。
- [ ] 对应型号冷启动策略明确，不依赖电脑先启动雷达再移接到车。

### 5.2 解析离线

- [ ] 全有效标准包、FFFF、全部FFFF、高反0x9388→5000 mm且保留标志、FFFF不误成32767。
- [ ] M10普通距离不错误屏蔽bit15；M10/M10P错配置必须失败。
- [ ] 角36000归零，speed0拒绝；任何分块位置/1字节/多包喂入结果一致。
- [ ] 插字节、丢字节、A5 A5 5A、载荷含A55A/FAFB、假长度20/255/65535、错尾均能恢复且不越界。
- [ ] GPS未支持变体明确拒绝；m取协议有效点数而非距离过滤后点数。
- [ ] C和PC解码同一实机原始流输出一致。

### 5.3 扫描/坐标

- [ ] 任意角起机首次半圈不发布，回绕不重复点，转向/安装偏置用实物标定。
- [ ] 车体坐标保持0°右、90°前、180°左：选定三个已知方向目标验证，按x=r cosθ、y=r sinθ检查；方向系数s=±1及零位偏置写配置。
- [ ] 丢扇区、乱序、重复、转速变化、2048点溢出均有状态，不能混入旧圈。
- [ ] 缓冲READING时不被写入，处理超时明确丢弃并计数。
- [ ] 0.5°工作集的空格/取点规则可复现，不把无回波填成管道。

### 5.4 电气/实时性

- [ ] 冷启动、热启动、连续至少10次掉电重启均记录到稳定点云的时间；次数为本次建议门槛。
- [ ] 舵机打满、电机加速时测雷达端4.75～5.25 V及规定纹波，记录最大电流/压降。
- [ ] 最高线路速率回放10分钟，同时蓝牙遥测/get/改参与速度环运行，台架不驱动车轮。
- [ ] UART/DMA/软件FIFO溢出目标0；任何异常有具体原因，未解释前不放行。
- [ ] 测DMA中断最长延迟、FIFO峰值、解析/感知/控制P50/P99/最大、扫描年龄和控制dt。
- [ ] 比较遥测开/关的时序；USART3打印不造成明显周期长尾。
- [ ] 新map≤112 KiB普通SRAM、至少16 KiB余量；动态栈水位和中断嵌套有余量。若不满足先改预算，不硬上车。

### 5.5 控制与故障

- [ ] 上电电机不驱动，传感器未稳定时不可运行；拔掉雷达/注入坏包后撤销许可。
- [ ] PI积分能清理，恢复不突然冲车；0占空比的实际制动性质单独确认。
- [ ] 舵机初始化1445、限位1170～1720及转向方向与实物一致，日志为最终CCR。
- [ ] dt适配、模式切换和故障恢复无D冲击；单位变更同时更新遥测布局。
- [ ] 无点云仍有健康心跳；主循环完全卡死时主机显示无响应，不假装健康。

### 5.6 管道赛道与收益

- [ ] 铝管距离0.1/0.2/0.5/1/2 m，不同入射角、阴影/直射光，记录有效率、偏差、抖动和高反比例；0.1 m是测试点，不是承诺量程。
- [ ] 管缝后放近物/远物/空场；测假断点，真实急弯测漏判。
- [ ] 雷达安装扫描面始终能打到管体，过坎/俯仰/遮挡场景覆盖。
- [ ] 同赛道、同速度、同配置，旧雷达与新雷达各多次重复，记录碰撞/脱轨、完成时间、漏弯、假断点和摆动。
- [ ] 单独比较旧断点与混合比例判据，不把换雷达与算法改进混成一项收益。
- [ ] 若延迟或近场失败增多，停止提速，保留失败日志并回退可用配置。

## 6. 每次测试保留什么

建议run目录：
```text
run_日期_编号/
  meta.json                 # 主控/雷达/固件/源码摘要/编译配置/参数/接线版本
  radar_raw.bin             # 台架完整原始输入，来自独立有线记录或可验证回放
  radar_rx.jsonl            # 原始字节接收块偏移与时间
  telemetry.bin
  telemetry_rx.jsonl
  events.jsonl
  config.json
  samples.csv
  report.md
  waveform.png
  timing.json               # 时序分布、峰值、错误计数
  power_notes.md            # 电压/纹波/电流测量条件和结果
```

高点频原始数据不经115200蓝牙全量发送；若用USB-TTL旁路监听，只接接收端与地，不能把两个TX输出并联。旁路接入的电平、地线与输入负载也需核验。日志必须区分原始输入记录与降采样可视化点云。
