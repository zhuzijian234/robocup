日期：2026-09-19  
目标工程：`2-LXY传承/LXY传承-副本`；用户实车主控声明为 STM32F407ZGT6。  
状态：**资料、源码和资源评审完成；雷达驱动未移植、固件未烧录、无新雷达实车验证。**

本版取代根目录《雷达升级修改方案.md》中涉及新例程移植、内存预算和实施顺序的旧安排。配套：[兼容性、内存与风险评估](02-兼容性内存与风险评估.md)、[资料依据与验收清单](03-资料依据与验收清单.md)。遥测线协议以[诊断遥测实施方案第二版](../2-LXY传承/LXY传承-副本/诊断遥测实施方案.md)为准，不再另定义一套遥测。

## 1. 结论与路线

1. **F407ZGT6 有能力接入两款串口雷达。** 新例程证明存在 F407 平台读取路径，但不证明本车可以整包复制后运行。芯片外设可迁移、封装和开发板接线不同，工程还需适配。
2. **保持当前标准外设库工程，沿用 USART2 PA3 RX 与 DMA1 Stream5/Channel4。** 不搬入 HAL_Init、示例 main、SysTick、启动文件和整套 HAL，不为模仿示例改接 UART5。
3. **主接入目标按 M10P-20K 串口版设计，共用接收层支持 M10-10K。** 优先 M10P 的理由是新资料对该串口格式和 F407 读取有直接证据，并且扫描数据更密；这不是比赛性能已胜出的结论。M10 仍有较低处理负担的价值，具体速度模式需确认。
4. **不能沿用例程 data_process。** 它把每包70个点压成两个半包平均值，并非提供完整70点供算法使用；会损失管缝、边界及弯角信息。
5. **RAM 按128 KiB普通SRAM预算。** 当前构建58,216 B；完整预留方案108,892 B，余22,180 B。详见配套资源表。首版不依赖CCM、不需要外扩RAM。
6. 不要求先把LD14P全面重写调到最优。先留可信基线、修必要的输出/失效记录，随后直接实现共用链路和新雷达驱动；断点比例优化作为独立后续实验。

本赛道约1 m宽、边界为直径20～30 cm铝管且可能有缝隙，前方有效空域通常不超过10 m。升级重点是近距离有效回波、动态延迟、缺测/管缝处理，不以最远量程决定收益。手册未充分证实本车近场/阳光/铝管斜入射性能，必须实测。

## 2. 新资料实际提供了什么

| 材料 | 已确认内容 | 限制 |
|---|---|---|
| 两目录内《STM32读取M10P雷达数据说明.pdf》 | SHA256相同；都是M10P、512000、160 B、70点的说明 | 放在M10目录不代表适用于M10-10K |
| M10P F407VET6例程 | HAL；UART5 PD2 RX/PC12 TX；USART1 PA9/PA10调试；单字节中断接收 | 没有雷达DMA、完整圈管理或小车控制 |
| M10-10K通讯协议 | 无GPS固定92 B，42距离槽，460800；无长度字段 | GPS表字节编号与文字长度冲突，不能直接定成103 B |
| M10P-20K输出格式 | 160 B带长度字段；高反bit15；10 B GPS保留 | 无CRC；启动串口原始命令未提供 |
| M10P用户手册 | 12 Hz、20k点/s、串口TTL及5V裸机供电 | 文档同时有网口/转换盒参数，不能混用供电 |

### 2.1 新例程必须避免的行为

证据位置均见配套资料清单：
- `usart.c:275～297`：70个距离分成两组平均，赋角为包角度减10°、减5°；与协议规定的“起始角＋15/m×N”不是同一处理。
- `usart.c:276`：整数除以100后赋给float，丢失小数角度。
- `usart.c:325`：0xFFFF改为0，随后参与平均，会把无效点变成过近障碍。
- `PointDataProcess[70]`每包只写2项，35包才写满；按24扇区/圈估算跨约1.46圈，不是完整一圈70点。
- 每包都置flag，主循环却打印70项；ISR同时更新数组，flag非volatile且没有所有权机制，可能混合旧点/新点。仅加volatile不能修复所有权问题。
- 长度读入后截到u8、无严格160验证；部分畸形长度可能使均值计算的分母为0。不能把它作为容错解析器。
- UART回调每字节触发，完成包时还在中断中计算；未见完整错误恢复。主循环逐点阻塞printf明显降低消费能力。
- 示例.ioc包含CCM区，不能直接照搬其通配分配；未来DMA数组若落在CCM会失效。

因此移植的是协议知识和已核实的外设配置思路，不是整个示例工程。

## 3. 工程目标、时钟与接线

### 3.1 先对齐实际主控和构建入口

当前主工程 `USER/Template.uvprojx` 的 Device仍为STM32F407VETx，Flash范围0x80000；两份EIDE也仅配置512 KiB Flash及128 KiB普通SRAM。它可能在ZG上运行，但目标配置与实物不一致，不能据此认定实车芯片型号。

实施前记录芯片丝印、开发板型号/原理图、晶振频率、板上接线照片。若实物确认ZGT6：
- 三份构建入口统一目标为F407ZG对应配置、匹配的烧录算法；Flash可按实际1 MiB配置。
- 保留F407适用启动向量、`STM32F40_41xxx`标准库宏及单精度FPU设置，不混入HAL的编译宏和ISR。
- 普通SRAM仍为0x20000000～0x2001FFFF；不把长度直接改为192 KiB。
- 保留现有8 MHz HSE、PLLM=8、PLLN=336、PLLP=2、PLLQ=7配置，但以实物/运行时RCC读回确认。uvproj中的CLOCK(12000000)只是元数据，不能代替实际时钟核查。
- 示例HSE=8 MHz、PLLM=4、PLLN=168、PLLP=2也得到168 MHz，但PLLQ=4得到84 MHz的Q输出；不要复制后影响需要48 MHz时钟的其他外设。

### 3.2 推荐接线及外设占用

| 功能 | 当前/推荐映射 | 实施要求 |
|---|---|---|
| 雷达TX → MCU RX | PA3、AF7、USART2_RX | 保留；460800或512000按型号配置 |
| MCU TX → 雷达RX | PA2、AF7、USART2_TX | M10/M10P禁用LD14P的TIM9 PWM初始化；有启动命令需求时使用 |
| 雷达接收DMA | DMA1 Stream5 Channel4 | byte/byte、MINC、循环、HT/TC/错误中断 |
| 蓝牙 | USART6 PC6/PC7，STATE现有引脚 | 保留，升级遥测按115200及TXE队列 |
| 调试输出 | USART3 PC10/PC11 | 保留，限频；不逐点printf |
| 舵机 | TIM3_CH1 PA6 | 保留最终CCR单位及限位；修初始化尺度问题 |
| 电机PWM/方向 | TIM2_CH1 PA5 / PB15 | 不照旧版说明接回PA2或PB11 |
| 编码器 | TIM4 PD12/PD13 | 保留 |
| 速度环 | TIM5，10 ms | 保留并增加失效许可检查 |
| 时间基准 | 核实未用后TIM6及DWT等 | 不占用电机/舵机定时器，不改现有delay的SysTick用法 |

备用方案可以使用示例UART5 PD2/PC12，其RX DMA为DMA1 Stream0 Channel4，但需要重新核对开发板走线、SDIO/其他占用、中断和工程初始化；只有PA3不可用时再采用。

LD14P模式才允许PA2映射TIM9。M10/M10P不是通过这个PWM脚控制转速，不能继续向其RX脚输出1 kHz PWM。复用选择必须由型号配置决定，不能依赖初始化顺序碰巧覆盖。

### 3.3 电源和接口

裸机串口雷达按资料为5 V（4.75～5.25 V）、3.3 V TTL信号、共地；电源能力至少5 W，典型400 mA、最大工作450 mA，纹波要求80 mV以内。**至少5 W是供电能力要求，不是已测启动峰值，也不是整车电源总预算。**

雷达TX接MCU RX，雷达RX接MCU TX；PPS/REC不需要GPS时按厂家要求处理，不接到普通UART冒用。6P端子的观察方向必须对照实物和说明图，不能只按线色。不得将网口盒的宽电压供电值接到5 V裸机上。

启动/急转舵机/电机加速时同时测雷达端电压和纹波；必要时独立稳压支路、合理地线和去耦。短线共地连接验证通过后再评估整车线束抗干扰。串口电平不是RS232，不能经普通RS232电平接口直连。

## 4. 两种雷达使用独立协议配置

所有字节偏移从0开始，多字节为大端，距离单位mm。

| 字段 | M10-10K无GPS | M10P-20K |
|---|---|---|
| UART | 460800、8N1 | 512000、8N1 |
| 总长 | 92 B固定 | 160 B，长度必须等于160 |
| 帧头 | 0～1 A5 5A | 0～1 A5 5A |
| 长度字段 | **无** | 2～3，00 A0 |
| 起始角度 | 2～3，百分之一度 | 4～5，百分之一度 |
| 转速计数 | 4～5 | 6～7 |
| 距离槽 | 6～89，42×2 B | 8～147，70×2 B |
| GPS/保留 | 无 | 148～157，10 B |
| 帧尾 | 90～91 FA FB | 158～159 FA FB |
| 无效值 | 原始0xFFFF | 原始0xFFFF |
| 高反位 | 文档未定义，禁止照搬bit15屏蔽 | 排除FFFF后记录bit15，距离raw&0x7FFF |
| 完整性校验 | 无CRC/校验和 | 无CRC/校验和 |

转速：rpm=2,500,000/speed，Hz=rpm/60，dps=rpm×6；先检查speed非0，不把原始计数直接放进LEIDA_speed_dps。

### 4.1 流式解析规则

- 编译配置/明确设备配置选择型号，不以A55A相似帧头自动猜型号。
- 找头→等足长度→验证尾和字段→解包。错误向后滑动一个字节继续同步，A5 A5 5A应能恢复；跨DMA分块的半包保留。
- M10P读取完整u16长度，非160拒绝；不让不可信长度驱动数组写入或等待任意大包。
- 角度允许协议中的36000并归一化为0，其他非法范围拒绝；speed0不除法。
- 不把“角度必须为15°整数倍”当检查规则，说明截图已有173°起始角。检查相邻包角增量、方向和回绕，而非固定绝对齿位。
- UART ORE/FE/NE及DMA错误、重同步、丢字节都计数；错误打断扫描连续性，不能静默接上。
- 头尾不能证明载荷未损坏：距离中的单字节翻转可能仍是合法值。补几何一致性/时序检查，但不能宣称恢复成CRC级数据保证。
- 诊断V2的CRC只能保护蓝牙封装，不能检测封装之前雷达链路中已发生的合法值误码。

### 4.2 无效槽与角度插值

先依据原始FFFF统计协议有效点数m；m=0直接标记空扇区，不做除法。M10P高反位先保留再清除。按现有文档，非FFFF点依次以N=0..m-1计算：
`angle = packet_start + 15.0f * N / m`，再归一化。

这里的m不是“经过100 mm过滤后的点数”。物理距离过滤在角度赋值之后进行，不能因删除近点或高反点重新压缩角度。

资料对FFFF是补齐槽还是实际测量缺失描述不够明确。上线前必须采“全有效、部分FFFF、连续FFFF、整扇区FFFF”的原始包，并与固定墙/角标及厂家显示对照。若实际固件采用固定槽位角，新增明确的角度策略配置并记录版本；不能悄悄修改所有设备解释。

### 4.3 明确不默认支持的变体

M10 GPS表列Byte90～100、尾101/102，文字又说GPS10 B，存在102/103 B矛盾。本版只启用92 B无GPS，拿到实际报文前不实现猜测长度。

M10手册列10/20 Hz，但42槽×24包×20 Hz=20,160槽/s，与标称10k点/s不一致；20 Hz可能采用填充或其他包行为，必须抓包确认。本版先验收10 Hz，不承诺只改转速即可20 Hz运行。

新F407例程没有发送雷达启动命令。资料ROS部分提及默认未启动，不能从只收数据的示例推断所有设备上电自动输出。若实物冷启动不转，必须取得该固件原始串口启停命令及应答；不能把ROS话题文本当串口报文发送。冷启动是实车接入前置门槛。

## 5. 连续接收与扫描缓存

### 5.1 接收资源

首版统一：1024 B循环DMA（两半各512 B）→8192 B软件字节队列→主循环流式解析→两份2048点原始扫描。DMA ISR只复制已完成半块、发布写索引和错误计数，不拟合、不转三角函数、不打印。

采用单生产者/单消费者索引，uint32单调计数与环形索引分离，按内存发布顺序维护；必要的屏障/短临界区和volatile不能替代缓冲所有权。写满时记录失流并重新同步，整圈标为不连续。控制不继续执行积压旧扫描。

首版HT/TC足以连续接收；单次半块收集本身最多带来约10 ms（M10P线路满速）延迟。若需要处理停流尾部或降低等待，可增加IDLE/定时提取，但必须共用消费水位，防止HT/TC和IDLE重复拷贝、漏字节。先验证简单版本，再引入该优化。

### 5.2 不混淆两种延迟预算

512000下一个字节约19.53 μs，512字节约10 ms：
- **DMA半块读取必须在另一半填满前完成。** 长时间关中断或更高优先级ISR超过该窗口会覆盖未复制数据，8192 B软件队列无法补救。
- 软件队列在线路最大51,200 B/s下容纳约160 ms，只吸收主循环短时抖动，不能作为允许控制落后160 ms的目标。
- 若HT/TC中断迟到超过整圈，标志可能合并，无法从标志数精确恢复全部丢失。必须记录服务间隔/NDTR异常并使扫描失效，不声称只要计数为0就绝无丢字节。
- 雷达DMA与USART错误中断优先，执行足够短；速度环次之，蓝牙TXE更低。具体分组与优先级结合最长ISR时间测试，不盲目复制示例全部优先级0。

### 5.3 点结构与完整圈

建议原始点8 B：
`uint16_t angle_cdeg, range_mm, offset_100us; uint8_t quality, flags;`
无强度字段的M10类quality标为不可用，不伪造LD14P同等质量。flags保留有效/高反等属性。构建时断言sizeof为8。offset是接收估计相对时刻，非精确发射时刻；溢出或跨过配置最大圈时长则拒绝该圈。

扫描元数据包含seq、起止时间、数量、包覆盖、回波覆盖、丢包/溢出状态。协议包收到但全无回波，与包丢失分开。按角度展开经过一整圈决定边界，不按“固定1798 B”或“凑够1680点”组帧。

第一段不完整圈丢弃。以车后为切点减少前方被拆开；每个点归属边界一侧，不能重复计入前后两圈。检测反向跳变/重复包/大缺角，只有连续且满足感知覆盖条件的扫描进入控制。空扇区允许作为“已收到但不可见”，不补假墙。

两份扫描的FREE/WRITING/READY/READING状态由主循环调度，算法读取期间禁止覆盖；无可用槽时丢弃未读旧快照或新一圈并计数，不能复用READING。若处理过慢先优化或降控制速率，不默认加第三份大缓存掩盖延迟。

2048点覆盖常规M10P每圈24×70=1680槽，但启动低转速、固件变体仍需检查；超出容量整圈拒绝，不截短冒充完整。M10专用1024点仅在实测最大圈点数有余量时采用，默认共用2048较易维护。

## 6. 算法适配及管道断点策略

### 6.1 首版保留算法尺度

原始扫描密度不直接扩张所有LEIDA_DATA_COUNTER。先做角度索引与代表点选择，把输入归一化至最多720个0.5°角度格，沿用800容量的算法工作数组。空格保留无效标记，不插假数据。代表点规则固定、可复现，并用管缝/边界样本决定最近点或稳健统计，不能随机取到第一个就认为等价。

旧HANDLE6/7按1°、±0.5°取边界，HANDLE8/9才做6点窗口。新雷达原始角分辨率变化不等于断点窗口物理范围同比改变；维持角度尺度并禁止跨大缺角连接。

逐项修复：
- 解析返回实际点数并贯穿后续，失败0点，不使用固定800处理旧残留。
- 所有输出数组显式容量和数量检查；滤波/掐头尾10点策略重新核对扫描顺序，不能无条件删固定点数。
- 拟合输入不足、分母近0、NaN/Inf有状态；中线配对清理旧索引、修正索引0被当无效等问题。
- 赛道宽度600～900 mm才接受且回退700 mm，与用户约1 m赛道不一致；实测有效宽度后配置范围及可信更新策略。
- 当前4 m筛选上限是否足够按前视距离测，不能因为雷达标称远而直接扩大所有计算范围。

### 6.2 断点优化作为独立阶段

首版用旧400 mm差值和550 mm入弯距离作为对照起点，先证明接入几何正确，再对同一批真实点云比较改进判据。

候选可用 `abs(r2-r1) > max(Dmin, alpha*min(r1,r2))`，但Dmin/alpha没有本车实测最优值，不能硬填“通用参数”。近距离用绝对下限抑制小噪声，远距离引入相对比例；还需角间隔、两侧支持点、断点后边界是否恢复、前方与另一侧边界一致性。

管缝后看到远处物体也会产生大比例，故纯比例不能区分管缝和真实弯道。窗口按角度、持续确认按时间设置；多圈确认会增加检测延迟，必须计入可用转向距离。最少记录候选分数、判定原因、相关角区、缺测比例和实际动作。标量遥测不足以回放时，另采原始串口日志。

## 7. 控制周期、失效及遥测融合

- M10P名义12 Hz整圈83.3 ms；M10 10 Hz整圈100 ms。这不是端到端延迟，仍有扫描相位、DMA半块、排队、计算和舵机响应。
- LD14P当前约114.8 ms分块决策不是6 Hz整圈；若先切成整圈控制，可能降低旧雷达更新次数。无需先在旧雷达上强制完成这个迁移才允许新雷达接入。
- D项迁移用 `kd_old*T_ref/dt*(err-err_prev)`，T_ref取旧有效控制间隔实测；模式切换、失效恢复、异常dt抑制或重置D。不能拿原kd直接除秒数。是否必须调整kp由同速试跑决定。
- 保持时间由帧数改毫秒是控制变更，参数单位、遥测布局和配置版本同步升级；遥测V2当前保持字段仍为剩余次数，不能直接塞毫秒。
- 修servo_pwm未初始化，Servo_Init使用实际CCR中位1445而非PWM/10值；PD中位参数避免整数截断。保留内部输出尺度时，不随意改kp/kd量纲。
- 启动电机输出0，传感器和感知稳定后才许可运行。无数据/拟合失效/溢出持续故障撤销许可，速度ISR同时检查，并清PI积分；恢复需要明确条件。电机0输出是断驱动还是制动必须以驱动器/实测确认。
- 距离裕量需用经轮径/里程标定的速度，不能把当前Speed_now直接视为m/s；设置失效时间依据最大行进距离和制动/转向时间。
- 遥测复用115200、V2 CONTROL108 B、HEALTH80 B及统一TXE，数据有效/更新/限幅位、配置版本、实际输出和失效记录按已有方案。
- 新增scan_seq、包丢失/角覆盖、RX峰值、处理最大耗时等通过明确扩展布局/配置注册；CONTROL中的control_seq不改名冒充scan_seq。所有扩展计入资源预算。

## 9. 完成判据与尚需实物确认

交付不仅是编译成功，还包括：准确原始日志→正确点云→稳定控制输出→正常遥测→同速赛道对照。检查项和证据格式见配套验收清单。

目前无法仅靠文件确认：
1. 实车是ZGT6的哪块板、晶振和电源支路、接头观察方向。

3. FFFF的真实角度语义、近场盲区、铝管斜入射与直射阳光的失效率。
