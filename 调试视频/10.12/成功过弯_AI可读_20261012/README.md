## 3. 「到弯距离」怎么求的（定义 + 门限 + **独立验证**）

### 3.1 定义
`path.csv` 给了**每条边界的近段/远段拟合直线**（`a`,`b`）及其 y 范围（`min_y`,`max_y`）。
同一侧两条直线的**交点 y** 就是边界改方向的地方：

```
近段: x = a1·y + b1 ,  y ∈ [min_y1, max_y1]
远段: x = a2·y + b2 ,  y ∈ [min_y2, max_y2]
交点: y_corner = (b2 - b1) / (a1 - a2)          ← 车体坐标，y = 前进方向，单位 mm
```

### 3.2 有效门限（全满足才算，否则记 none 并给出原因）
| 门限 | 内容 |
|---|---|
| **G1** | 该侧近段与远段都"未被拒"：`fit_rejected` 对应字节 == 0（字节序来自 `ble_diag.c:440`：`near[0] \| near[1]<<8 \| far[0]<<16 \| far[1]<<24`，下标 0=左 1=右） |
| **G2** | `\|a1 − a2\| ≥ 0.05`（两线近乎平行时交点无意义 → 直道上被自动排除） |
| **G3** | `min_y1 < max_y2`（近段在远段之前，顺序正常） |
| **G4** | 交点落在 `[min_y1 − 50, max_y2 + 50]`（不许大幅外插） |

### 3.3 独立验证（**关键：排除"近段/远段窗口交界造成的假象"**）
用**原始点云**（`cloud.csv`，每采集 8 个快照、每快照约 280 点，列为 `x_mm`/`y_mm`）
换一套完全不同的算法：

> 取该侧 y∈[100,600] 的点自算最小二乘直线 `x=a·y+b`，
> 再从 y=600 往上找**第一个偏离该直线 >150 mm** 的点的 y，记 `y_depart`。

结果（连续 4 帧，单位 mm）：

| 段 | 转弯 | 外侧壁 | **点云独立法 `y_depart`** | 拟合交点法 | 差 |
|---|---|---|---|---|---|
| SUC01 | 左 | **右** | **690 → 662 → 642 → 625** | 659 / 673 | ≤ 50 mm |
| SUC02 | 左 | **右** | **734 → 736 → 679 → 648** | 644 / 666 | ≤ 50 mm |
| SUC03 | 左 | **右** | **738 → 726 → 709 → 721** | 669 | ≤ 50 mm |
| SUC04 | 右 | **左** | **831 → 799 → 750 → 706** | （该帧两门限拒） | — |
| SUC05 | 右 | **左** | **801 → 772 → 731 → 690** | 650 | ≤ 50 mm |
| SUC06 | 右 | **左** | **770 → 722 → 664 → 610** | 677 | ≤ 50 mm |

**两条结论**
1. **两个独立方法互相印证（差 ≤50 mm）** → `y_corner` 反映的是**真实的壁面转折**，不是窗口交界假象。✓
2. 数值随车前进**单调递减**（如 690→662→642→625）→ 符合"弯道越来越近"的物理。✓

> **顺带一条规律（事实）**：**左弯只有右壁（外侧）的拐点可解，右弯只有左壁** ——
> 因为内侧壁急转，其远段拟合被拒（G1）。六次全部如此。

## 4. 你要的两个量（6 次带遥测的）

**车的位置口径**（有代码依据）：
`target_x` = 路径中线的横向位置（车体坐标，**+x = 车右**，车在 x=0）；
`error = cx − target_x`（`CENTER_X_TARGET_MM = −27`）；无避让时 `road_error == error`。
→ **`road_error` 就是"车相对目标路径的横向偏差(mm)"，>0 表示车偏在路径右侧。**

### 4.3 可直接用的结论（数字）

1. **成功过弯时，摆舵机发生在"外侧壁拐点还有 645~680 mm"的时候**（拟合交点法；点云独立法同区间给 610~690 mm）。
2. **入弯前车确实贴在外侧**：相对路径横向偏 **+230~+522 mm（左弯，偏右）** / **−230~−612 mm（右弯，偏左）**。
3. **到弯距离在整个入弯过程中从约 830 mm 单调递减到约 610 mm**（点云法，见 §3.3 表）。
4. 六次可解帧占比 **60%~69%**（其余帧因 G2 平行 / G1 被拒而不可解，主要出现在直道上——这是门限在起作用，不是丢数据）。

### 4.4 两处数据缺口（如实标注）
- **SUC03 / SUC05 的摆舵机那一帧没有 detail 行**（`bend/src/far` 都是 None）→ 该帧无 `road_error` 与弯道位置。
  它们的"入弯前"帧有数据，已列入 §4.2。
- **SUC04 摆舵机时刻两侧都被 G1 拒**（当时 `far_valid=0`）→ 该帧解不出到弯距离。

- 已按 **30fps 全片**抽帧到各自 `keyframes\`

**我没有从这两个视频给出绝对距离**，原因如实说明：
1. 手持、有运动模糊（如左弯 f0130 整帧糊）
2. 画面里**"弯道拐点"没有可辨认的几何标记**，无法定出测量端点
3. 没有标尺落在与目标同一深度平面上
→ 硬算出来的数会是编的。需要量的话，请用你自己的已知尺寸（通道内边到内边 **500 mm**、管径 **200 mm**、车长 **350 mm**）在 `keyframes\` 上人工量。

**摆舵机时到弯 645~680 mm、入弯前贴外侧 230~612 mm**。这比从视频硬算可信。
