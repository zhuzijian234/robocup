## 2. 时间对齐（关键，请读完再引用任何"同一时刻"）

### 2.1 先说限制
视频与遥测**没有任何共同时间标记**。视频的 mp4 `mtime` 是 **2026-10-12 上午的拷贝时间**，不是录制时间，**不可用**。

### 2.2 实际采用的锚点：**运动起点**
遥测的 `motor.csv` 里有 `speed_float`。把 `|speed|>1` 的**连续段（>0.3s）**找出来：

| 采集 | 连续运动段 | 段长 | **视频时长** |
|---|---|---|---|
| 215921 | **0.83 ~ 8.34 s** | 7.51 s | 7.27 s |
| 220025 | **0.41 ~ 9.09 s** | 8.69 s | 7.50 s |
| 220116 | **0.41 ~ 9.89 s** | 9.49 s | 7.10 s |
| 220417 | **0.42 ~ 9.12 s** | 8.70 s | 7.00 s |

**运动段长度与视频时长基本一致**（差 0.2~2.4 s），所以把 `video_t = 0` 对齐到运动段起点。

### 2.3 验证（这条是真的验证，不是假设）
在对齐后的窗口里，视频每一帧对应的遥测 **`Speed_now` 都 > 1**：

| 采集 | offset_A（运动起点） | **落在"车在动"的帧** |
|---|---|---|
| 215921 | **+0.83 s** | **219 / 219** |
| 220025 | **+0.41 s** | **226 / 226** |
| 220116 | **+0.41 s** | **214 / 214** |
| 220417 | **+0.42 s** | **211 / 211** |

### 2.4 不确定度：**0.66 ~ 2.77 s**
另一个候选锚点是"把视频结尾对齐到运动段结束"（offset_B）：

| 采集 | offset_A | offset_B | 两者之差 |
|---|---|---|---|
| 215921 | +0.83 | +1.48 | **0.66 s** |
| 220025 | +0.41 | +1.98 | **1.58 s** |
| 220116 | +0.41 | +3.18 | **2.77 s** |
| 220417 | +0.42 | +2.47 | **2.05 s** |

**A 与 B 之差就是对齐不确定度**。`aligned.csv` 用的是 A；如果你要按 B 复核，把 `tele_t` 整体加（B−A）即可。
`sheets\overview_tele.jpg` 顶部同时写了 A 和 B 两个值。

> ⚠️ 因此：**不要把"视频第 x 秒"和"遥测第 x 秒"当成同一时刻使用**，精度只有秒级。

### 3.3 `fit_rejected` 解码（编码已从代码核对）

`ble_diag.c:440` 把它拼成 4 个字节：
**byte0=左近段 / byte1=右近段 / byte2=左远段 / byte3=右远段**；
每字节是 `FIT_*` 位图：**1=点数不足 2=跨度不足 4=间隙过大 8=退化 16=RMS超限 32=斜率超限**（`path_track.h:21-26`）。

观测到的值（次数最多的几个）：

| 值 | 十六进制 | 含义 |
|---|---|---|
| 50331648 | `0x03000000` | 右远段：**点数不足 + 跨度不足** |
| 196608 | `0x00030000` | 左远段：**点数不足 + 跨度不足** |
| 50332416 | `0x03000300` | 右远段 + 右近段：点数不足 + 跨度不足 |
| 50529024 | `0x03030000` | 右远段 + 左远段 |
| 196611 | `0x00030003` | 左远段 + 左近段 |
| 0 | `0x00000000` | 四条拟合都没有被拒 |
| 50331652 | `0x03000304` | 右远段(点数+跨度) + 右近段(**间隙过大**) + 左近段(**间隙过大**) |
| 268632067 | `0x10030003` | 右远段(**RMS超限**) + 左远段 + 左近段 |

**共同点（事实）**：出现最多的拒绝原因是 **`FIT_POINTS`（有效分区<4）+ `FIT_SPAN`（y跨度<250mm）**，即"可见段太短"。
`FIT_SLOPE`（\|a\|>1.8）**没有出现在高频值里**。

## 5. 看不出 / 无法确认

1. **前轮实际转角**：看不清 → 所有关于"舵机打多少"的说法只能来自 `servo_pwm`（指令），不是实测轮角。
2. **是否真的"刮蹭/接触"**：全景分辨率下区分不出"紧贴"与"接触"。本批我**没有**在图上标 `CAR-AT-TUBE`。
3. **弯道半径、通道宽度、管径**：无标尺 + 手持透视，**测不了**。
4. **绝对轨迹/速度**：摄像机在动，无法还原。
5. **对齐精度**：见 §2.4，**0.66~2.77 s**。
6. `Speed_mubiao` 在 CONTROL 里出现 15/16/17 三个值 → 说明这一列报的是**速度调度后的有效目标**，不是 `spd` 参数本身（`spd=17` 在 `meta.configs` 里）。

## 6. 复现命令

```powershell
$py='D:\anaconda3\anaconda3\python.exe'
$R='D:\OneDrive\Desktop\robocup\调试视频\S弯拆解_遥测对照_20261011'
```

**踩过的坑（都在这批里真实发生过）**
- `cv2.imread` / `imwrite` 对中文路径失败 → 用 `imdecode(np.fromfile)` / `imencode(...).tofile`
- `cv2.putText` 的 Hershey 字体不支持中文 → 图内一律 ASCII
- **中文路径不要通过 `python -c` 传参**（会被 PowerShell 弄坏）→ 写进脚本文件
- **列来源要看清**：`path_reason / far_valid / source` 在 `detail.csv`，`geometry_reason / fit_rejected` 在 `path.csv`，`speed_limit` 在 `race.csv`
- **对齐别默认"结尾对齐"**：先诊断运动段在哪（本批运动段在采集**开头**，用结尾对齐会把视频贴到车已停下的时段）
