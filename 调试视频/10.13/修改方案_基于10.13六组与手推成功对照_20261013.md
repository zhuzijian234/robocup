## 1. 事实清单（全部可复核）

### 1.1 急弯新逻辑在 10/13 六组里"基本没启动"

`acute_checks` 是**拒绝位图**（`path_track.c` 15 个赋值点全为失败条件 `|=`）。
位定义见 `path_track.h:64-67`；`512(PREFILTER)` 的条件是 `path_track.c:1233`：

```c
if (out->model || (!state->acute_phase &&
    !((out->far_fit[0].valid && fabsf(out->far_fit[0].a) > .30f) ||
      (out->far_fit[1].valid && fabsf(out->far_fit[1].a) > .30f))))
{ acute_clear(state); out->acute_checks = ACUTE_CHECK_PREFILTER; return; }
```

| 段 | acute 事件 | PREFILTER(512) | **512 的成因（逐条关联 race/path 得到）** |
|---|---|---|---|
| 194302 左大弯 | 40 | 15 | **左远弱+右远弱×12**、左远弱×2、右远弱×1 |
| 194450 左弯 | 52 | 17 | **左远弱+右远弱×13**、右远弱×3、`model=2`×1 |
| 194631 左弯 | 56 | 17 | **左远弱+右远弱×13**、左远弱×4 |
| 194802 右弯 | 35 | 14 | **左远弱+右远弱×10**、左远弱×4 |
| 195030 右弯 | 32 | 11 | **左远弱+右远弱×8**、左远弱×3 |
| 195147 s弯 | 34 | 14 | **左远弱+右远弱×11**、`model=2`×1 |

（"远弱" = 该侧远段拟合无效，或有效但 `|a| ≤ 0.30`）

**阶段统计**：六组合计 249 个 acute 事件中，
`ACUTE_CONFIRM(1)` 出现 **2 次**、`ACUTE_PREPARE(2)` **1 次**、`ACUTE_TURN(3)` **1 次** ✗
其余 `reason` 以 `0 无入口证据` 与 `6 证据丢失` 为主。

**→ 结论（数据验证）**：急弯分支连"扫描"都没开始，因为它的**预滤波要求远段拟合有效**，
而急弯入口处两侧远段恰好都失效。

### 1.2 远段拟合大面积失效——这是同一个根因的另一面

`fit_rejected` 是 4 条拟合各 8 位拼的（`ble_diag.c:440`），每字节 = `FIT_*` 位图
（1=点数不足 2=跨度不足 4=间隙过大 8=退化 16=RMS 32=斜率）。10/13 六组高频值：

| 段 | 高频 `fit_rejected` |
|---|---|
| 194302 | **`0x03030003`×47**、`0x00030000`×40、`0x00000000`×35、**`0x03030303`×26** |
| 194450 | `0x00000000`×58、**`0x03030003`×51**、**`0x03030303`×49**、`0x00030000`×39 |
| 194631 | `0x00000000`×70、`0x00030000`×51、**`0x03030003`×41**、`0x03000000`×33 |
| 194802 | **`0x03030303`×110**、`0x00000000`×59、`0x03000000`×30 |
| 195030 | `0x03000000`×83、**`0x03030303`×57**、`0x00000000`×50 |
| 195147 | **`0x03030303`×110**、`0x00000000`×31 |

**`0x03` = `FIT_POINTS|FIT_SPAN` = "分区数不足 4" + "y 跨度不足 250mm"**，
即"可见段太短"。`0x03030303` = 四条拟合全废。
（逻辑上必然：四条全废时来源仲裁只能给 `source = PATH_NONE(3)`）

### 1.3 感知无效与舵量饱和：10/13 明显差于手推成功

按 `(session, control_seq, param_revision)` 精确关联；接近舵量边界 = `PWM ≤ 1180 或 ≥ 1710`。

| 组 | CONTROL | **接近舵量边界** | **`action_reason=5`（无有效转向）** | `geometry_reason=3`（冲突） |
|---|---|---|---|---|
| 10/13 六组 | 1699 | **635（37%）** | **528（31%）** | 76 |
| 手推六次 | 1218 | **145（12%）** | **61（5%）** | 3 |

`source` 分布里 `NONE(3)` 在 194450 占 **142/311**、195147 占 **137/269**、194802 占 **122/284** ✗

### 1.4 手推成功给出的"可行条件"（同一赛道、舵机自动）

| 事实 | 数值 |
|---|---|
| 手推速度 | 9.5 ~ 14.0（评审文档正式窗口速度中位 7.6 ~ 11.9） |
| 手推也在打舵量边界 | 10~35 帧/次（占 12%） |

而 10/13 在 17.7~18.8 下，37% 的帧贴在舵量边界、31% 的帧没有有效转向 ✗

## 2. 根因（一个因，三个果）

```
远段拟合在急弯入口大面积失效（FIT_POINTS|FIT_SPAN，"可见段太短"）
   ├─→ acute 预滤波(path_track.c:1233)要求远段有效 → 急弯分支从不扫描   ✗
   ├─→ 来源仲裁只能给 PATH_NONE → action_reason=5 感知无效 31%        ✗
   └─→ 只能靠近段/单侧 → 舵量在饱和区间反复打满（37%）                  ✗
```

**同时**：急弯入口的**速度**（17.7~18.8）比手推成功时（9.5~14.0）高出 30~90%，
在舵机已经饱和的区间，速度再高也换不来转角 ✗

## 3. 修改方案（按"先诊断、后改行为、可独立回滚"排序）

### P0-A（最高优先，最小改动，直对根因）：急弯分支的预滤波不再要求远段

**改哪里**：`HARDWARE/CENTRE_LINE/path_track.c:1232-1240`

**现状问题**：预滤波把"远段拟合有效且 |a|>0.30"当成急弯扫描的**必要条件**。
但 `acute_wall()` 自己是从**近段**（y∈[100,400]、`side*x>60` 的种子点 ≥8、≥5 个 50mm 分区、
跨度 ≥200mm、RMS ≤12mm）建立墙面身份，再向外延伸 —— **它并不依赖远段拟合**。
所以这个前提与它自己的逻辑不自洽。

**改法（候选，二选一）**：
```c
/* 方案1：远段作为"任一证据"，近段也可单独触发 */
if (out->model || (!state->acute_phase &&
    !((out->far_fit[0].valid && fabsf(out->far_fit[0].a) > .30f) ||
      (out->far_fit[1].valid && fabsf(out->far_fit[1].a) > .30f) ||
      (out->near_fit[0].valid && fabsf(out->near_fit[0].a) > .30f) ||
      (out->near_fit[1].valid && fabsf(out->near_fit[1].a) > .30f))))
```
```c
/* 方案2：只在"完全没有可延伸的近墙"时才预滤波（更保守） */
if (out->model || (!state->acute_phase && !out->valid))
```

**推荐方案 1**：它把触发条件从"远段必须好"改成"任一段明显在弯"，
而真正的严格门限仍在 `acute_wall()` 内部（种子点数、分区跨度、RMS≤12、偏离≥40mm×3、转角≥0.60rad）——
**放宽的是入口，不是判据** ✓

**必须同时保留的**：`out->model` 的否决要不要留，需要单独确认。
10/13 六组里 `model=2` 只出现 2 次，所以它不是主要瓶颈；建议**第一轮先保留**，避免同时改两处。

**离线验证（不需要实车）**：
- 用 10/13 六组 + 10/12 十二组（`上位机\log` 全部 BIN）回放，
  统计改动前后 `acute_checks==512` 的占比、以及 phase 能否走到 1→2→3；
- 用 `test/check_acute_stages.py`（122 项阶段测试）确认镜像方向、40mm 不累计、
  确认中断、不退回准备、出口清状态等原设计约束**没有被破坏**；
- 重点看**误激活**：直墙斜放、横墙、局部锥桶、单帧假弯、近远反向时 `acute_phase` 必须仍为 0。

### P0-B（与 P0-A 独立，但影响面更大）：远段"可见段太短"的门限

**改哪里**：`path_track.c` 的 `fit()` 与 `build_lines()`（远段窗口 y∈[550,1300]）

**现状**：`FIT_POINTS` 要求有效分区 ≥4、`FIT_SPAN` 要求 y 跨度 ≥250mm。
急弯入口处远段常见 `0x03`，导致 `source=NONE`、感知无效 31%。

**候选改法（按风险从低到高）**：
1. **只给远段降门槛**：远段允许 3 个分区 / 跨度 ≥180mm，但 RMS 收紧（如 ≤35mm）；
   近段判据完全不动 —— **风险最小，因为近段才是纠偏主力**。
2. **把远段窗口的近边从 550mm 提前到 450mm**，让它多收到几个分区；
   代价：远段更靠近车，方向前瞻性下降 → 需要用回放确认不改变原好 S 弯/缓弯的输出。
3. 近远段拼接（**不要做**：评审 §191 明确"不能恢复上一轮已撤回的全局近远段放宽规则"）。

**建议先做 1**，并用回放逐帧比对原两组表现良好的 S 弯、缓弯、长直道、锥桶序列，
**要求逐帧 PWM/P/D 完全一致**（评审 §207 的验收方式）。

### P1（与几何无关、性价比最高）：急弯入口的速度分层

**依据**：手推在 9.5~14.0 能过；10/13 在 17.7~18.8 失败，且 37% 的帧已贴在舵量边界。
**评审已明确**："继续提高全局 Kp 不能解决已经饱和的区间"、"低速提供的额外转向时间不能用增大 Kp 替代"。

**改哪里**：`Path_SpeedLimit()` / `Path_SpeedStep()`（`path_track.c:1539/1578`）已有的速度调度里**加一档**，
不改结构、不改 PI、不改 PWM 上下限。

**建议参数（待回放+实车验证）**：
- 现有：直道 **17** / 弯道 **15**（`md文档` 记为 17/15，`cx=10`）
- 新增：**急弯入口档 11~12**（`acute_phase ∈ {CONFIRM, PREPARE}` 或"近段已明显在弯"时生效），
  主弯接管后回落到 15，出弯后按原斜率回 17
- 斜率仍用现有 `accel=2 / decel=12`，不引入新的控制项

**⚠️ 必须分开验证**：评审 §213 要求"不将外移算法和继续提速混为同一次试验"。
本轮**不要**同时改速度与几何门限做同一次实车；建议先 P0-A+P1，跑一轮，再上 P0-B。

### P2（纯诊断增强，不改任何控制行为）：让"卡在哪一条"以后一眼可见

三处都是**只写不读**的增量，不改判定：

1. **`acute_extension()` 加一个拒绝位图**（`path_track.c:970-1024`）。
   现在延伸失败只留一个 `GAP` 位，但失败点有 6 处
   （tip 越界 / `end-begin<12` / 跨度<300 / `entry.y` 偏离 tip 超出 −120~+150 / 点距>180 /
   法向偏移越界 / `n<5` / 转角不在 [0.08,1.0] / 残差>20mm）。
   **要改阈值，先得知道是哪一条**。
2. **`gap` 位的语义修正**：`L980 wall->gap = 1;` 是在通过 tip 测试后**无条件**置位的，
   之后无论找没找到延伸都保持。名字叫 gap（间隙），实际语义是"延伸未成立"。
   建议改名或在文档里写清，否则会误导（我第一遍就被误导）。
3. **`acute_position` 每帧发布**：`L1267` 已经算出 `acute_position = direction*(a*100+b)/normal`
   （前轴 y=100 处的局部法向位置），但后面的早退把它吞掉了，导致只有 phase 1/2 才有值 ——
   而 phase 1/2 几乎进不去，等于**没有"车是否已到外侧"的反馈** ✗（评审 §5 也点了这条）
   建议把它作为**诊断字段**在每帧都填（不参与控制）。

### P3（并行支线）：左右不对称的感知排查

事实：`source=NONE` 在 194450（左弯）占 46%、195147 占 51%；而 194631（左弯）只占 0.3% ✗
评审 §1(b) 也指出"后两次自主左弯的感知无效明显多于成功手推左弯"。

**做法**：把 10/13 六组按**左/右分开**统计 `geometry_reason` / `fit_rejected` / `source` /
`action_reason` 的分布，定位是"近段缺失"还是"几何冲突"，再决定是否动 `cx=10`
（评审 §152：**不先改全局 cx、Kp/Kd 或左右极限 PWM**）。

## 4. 明确"不要做"的清单（都有依据）

| 不做 | 依据 |

| 提高全局 Kp/Kd | 37% 的帧已在舵量边界，饱和区间加 Kp 无效（评审 §13/§150） |
| 加大 40mm 外移量 | 评审 §131："若误差预算或有效宽度不支持，**减小甚至取消该次布位**，不能为凑足 40mm 继续朝外走" |

## 7. 这份方案里**未经证实**的部分（如实标出）

1. **两组数据的固件不同**（`59f2128e` vs `fa544667`），所以"感知无效 31% vs 5%"里
   有多少来自固件差异、多少来自速度差异，**本方案没有分离**。
2. **P0-A 的候选改法未做离线回放**（我没有跑回放，只读代码+统计既有数据）。
   括号里的"方案1/方案2"是设计建议，不是已验证的补丁。
3. **远段门限的具体数值**（3 个分区 / 180mm / RMS 35mm）是我按现有量级给的**起始值**，
   未经回放标定。
4. **急弯入口速度 11~12** 取自手推成功区间（9.5~14.0）的下半段，是**候选值**，
   不是算出来的最优值 —— 评审 §227 明确："有这些校准后，准备距离应由所需横移、速度、
   可实现曲率与执行延迟求出可行区间，而不是固定取 650 mm。"
5. 我**没有**逐行读完 `acute_prepare()`（183 行）与 `build_lines()`；
   `acute_checks` 的位语义来自 15 个赋值点的上下文，`PREFILTER/NEAR/DIRECTION/ROOM` 的条件已核实原文，
   其余位（`LINKED/CONE/RANGE`）只核实了赋值位置，未核实完整条件。
